\BioseqWalkRow{sql}{appendices/02_sql_walkthrough/sql/09_options.sql}{%
\textbf{Change algorithms for one call}
I wanted to have an example with explicit algorithm settings to show how we can change either the algorithm for specific stage like chaining or the k/w parameters.
You need to pass \texttt{aligner\_options} to the \texttt{mmsearch} function.
The codes choose bounded ntHash SIMD minimizers (4), SIMD minimap2

\texttt{Result} is just a projection of the \texttt{BioseqScan}

The scan reads the identifier, age and sequence. A chunk-group filter
compares the age condition with stored minima and maxima, but couldn't skip any chunk (because we have so few rows, there's only one chunk).
The vectorized filter tests individual ages in the

\texttt{allow} means that we can either read the index or recompute minimizers from scratch~\ref{tab:configuration-index-requirement}.
The planned share is 100\% recomputed - this is the estimate of how many minimziers in index do not have a corresponding minimizers stored. In this case 
BioseqDB have buggy const-query implementation which causes index to always be rebuilt which significantly degrades performance. For better performance you should use join between query and target tables, so both 
of query/target arguments are red from tables.}

\BioseqWalkRow[firstline=19,lastline=27,gobble=12]{plan}{appendices/02_sql_walkthrough/plans/10_explain_search.plan}{%
Internally BioseqDB is implemented as type-driven heavily-templated code, so CEP means "constant expression parameter".
The zero \texttt{cep.window\_len}, \texttt{cep.kmer\_len} and
\texttt{query\_len} values represent the fact that generic implementaion is used (internally I have parameter that can allow instantiation of template specifically for k/w parameters or 
for specific sequence length, for specific minimizer lengths. Specialized false with all zeros means that these parameters are runtime, not compile-time optimised constexpr parameters - this is default as enabling instantiation 
produces very large binaries the linker msut work with).

\texttt{max\_occ} limits max counts of minimizers per hash, while \texttt{reserved} is a planned anchor-buffer capacity in elements (how many anchors I predict to have - in reality this allocation by default is const, but can grow)}
