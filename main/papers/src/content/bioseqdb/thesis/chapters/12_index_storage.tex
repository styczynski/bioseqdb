\section{Persistent indexes as derived database state}
\label{sec:index-storage-role}

A minimizer index avoids sketching and organizing the same target for every
alignment query. In a standalone mapper, the index can be a file that the user
rebuilds when the reference changes. A current versioned database index has a
stricter identity. It belongs to a physical relation, a sequence column, and a
particular version of the source data. Its descriptor records the alphabet,
minimizer parameters, hash scheme, occurrence policy, position width, storage
format, and any execution interface that consumes the stored shape directly.
Older asynchronous payloads have a narrower compatibility identity, as
described in Section~\ref{sec:index-compatibility}.

BioSeqDB therefore treats a persistent sequence index as reproducible database
state, rather than as an opaque cache. The source sequence remains authoritative.
Replacing or deleting an index does not change it. Conversely, an index built
for an earlier source epoch is not eligible after the sequence changes, even if
the relation and row identifiers still exist. This rule prevents an old payload
from being attached to new sequence bytes by name alone.

The index has a control plane and a data plane. The control plane identifies a
visible version and its compatibility contract. The data plane contains hash
controls, positions, and navigation metadata. PostgreSQL stores the authoritative
descriptor and, in the general path, the payload chunks. A grouped fragment
index may additionally have an immutable sealed image for direct reading. That
image remains subordinate to the PostgreSQL descriptor. It cannot become current
without successful construction and publication of the corresponding generation.

Figure~\ref{fig:index-generation-lifecycle} summarizes the resulting lifecycle.
Readers resolve the current descriptor under their snapshot. A writer builds a
new generation without modifying the version already visible to those readers.
Only a complete and compatible generation can replace the current descriptor.

\section{Logical organization of minimizer indexes}
\label{sec:index-logical-layouts}

BioSeqDB retains two logical minimizer organizations because they optimize
different stages of the workload. Minimizers per fragment, abbreviated MPF,
matches the fragmented representation of long sequences. Minimizers per
sequence, abbreviated MPS, reorganizes the same information by hash range for
selective loading. The registered index policy also includes compact symbol
counts, which support planning and filtering but do not provide seed positions.
The implemented persistent MPF and MPS policies admit the profile
\(k=15,w=10\). Other minimizer parameters can be used by transient execution,
but these persistent layouts do not store them.

\subsection{Minimizers per fragment}
\label{sec:index-mpf}

An MPF object is built for one source fragment. Its main components are a hash
table and a contiguous positions array. Each occupied hash entry stores an
offset and a count into that array. An occurrence encodes its local target
position together with strand information. Readers rebase positions when
assembling a queryable view.

Each fragment can be sketched independently. This bounds one construction unit
and lets an insertion policy update affected index objects without sorting
every minimizer in the logical sequence. A query over a long target must inspect
or assemble several fragment images. The default path accepts this cost because
it follows the existing storage and ingestion unit.

The grouped MPF representation, called Format~5, stores controls and positions
in a specified array layout rather than serializing a language-specific hash
container. The layout can be checked before use and can be adapted to a CPU or
accelerator view. A sealed MPF5 image offers a direct read path for this grouped
layout. It is an immutable reader representation, not an independently managed
index provider.

\subsection{Minimizers per sequence}
\label{sec:index-mps}

MPS performs more work during construction so that a query can avoid loading
unrelated target hashes. It combines fragment sketches into sequence-wide,
hash-ordered buckets. A compact directory maps each stored hash interval to the
bucket or stream region that contains its controls and positions. The reader
searches this directory with the distinct query hashes, then admits only the
intersecting regions.

The selective Format~6 organization separates three logical streams. The
directory describes hash ranges and authorized spans. Control blocks store
hashes and occurrence counts. Postings extents store positions for hashes that
pass the occurrence policy. This order matters. The reader can reject a highly
repetitive hash from its count without allocating or reading its full position
list. The current Format~6 path requires DNA4 symbols, four-byte hashes, and
the registered \(k=15,w=10\) profile. Other combinations are not interpreted
as this selective format.

Neither BioSeqDB organization is always preferable. MPF avoids a global merge
and follows incremental ingestion. MPS can reduce cold input when the query
touches a small part of the target hash space. The relevant factors are source
fragmentation, update frequency, query selectivity, construction cost, and the
memory available for transient assembly.

\section{Bounded construction and publication}
\label{sec:index-construction}

A sequence-wide index cannot safely be built by appending every
\((hash,position)\) pair to one vector and sorting it in memory. The input may
contain billions of bases, and one frequent minimizer may have a position list
much larger than an ordinary work buffer. BioSeqDB instead uses bounded sorted
runs. Pairs enter an admitted memory region. A full run is sorted and either
retained under a residency permit or written to temporary database storage.
The merge limits its fan-in, so the number of open readers and merge buffers is
independent of the total number of runs.

The source is scanned in ranges with the halo required by minimizer extraction.
Local positions are converted to global sequence coordinates before entering a
run. The final merge groups equal hashes and writes storage units near a target
size. A frequent-hash accumulator can also spill, which prevents one posting
list from bypassing the general memory bound.

Algorithm~\ref{alg:mps-build} gives the high-level construction procedure. It
omits physical row sizes and backend-specific calls because they do not change
the algorithmic contract.

\clearpage
\begin{algorithm}[H]
  \caption{Memory-bounded construction of a sequence-wide minimizer index}
  \label{alg:mps-build}
  \small
  \textbf{Input.} Source identity \(I\), the registered minimizer profile
  \(k=15,w=10\), and memory budget \(M\).
  \begin{enumerate}
    \item Reserve a build identity and capture the source epoch.
    \item Scan bounded source ranges with the required overlap.
    \item Extract minimizers and append globally positioned
          \((hash,position,strand)\) records to the active run.
    \item When a run reaches its permit, sort it and retain it only if memory
          remains available. Otherwise spill it.
    \item Merge runs with bounded fan-in until one hash-ordered stream remains.
    \item Group equal hashes, spilling a large posting list when necessary.
    \item Write buckets or streams with lengths, checksums, and compatibility
          metadata.
    \item Write the navigation directory after all referenced data is complete.
    \item Check the unpublished object against \(I\) and its manifest.
    \item Publish its descriptor atomically, or discard it on failure.
  \end{enumerate}
\end{algorithm}

Writing the directory last is a basic completeness rule. A reader cannot infer
a usable sequence-wide index from a prefix of buckets because there is no final
directory that authorizes them. Immutable generation mode strengthens this
rule. All rows and optional sealed artifacts belong to a fresh generation.
The writer checks the complete object before replacing the small descriptor
that names the current version. Readers that already resolved the previous
descriptor may continue until their snapshot is no longer visible.

The older storage mode writes chunked objects in ordinary sidecar relations and
replaces their contents within a transaction. It remains the default
configuration and provides broad support for the registered index layouts.
Grouped immutable generations are an explicit mode. They give stronger
copy-on-publication behavior but impose additional manifest, retirement, and
artifact management. The thesis distinguishes these modes because directory-last
completion in one mutable namespace is not equivalent to snapshot-safe
generation replacement.

Grouped derived index relations may be unlogged because their bytes can be
rebuilt from durable sequences. This reduces duplicated write traffic, but it
also defines a recovery obligation. After an unlogged reset, the prior index
must not be advertised as ready. It must be rebuilt and published again.

The sealed direct-reader image follows the same authority rule. Construction
first produces an authenticated grouped generation. The image is then written
under a private name, made immutable, synchronized, and published without
overwriting an existing generation. The database descriptor becomes current
only after the final artifact has the expected identity. Retired descriptors
are excluded from new reads. This sequence keeps
filesystem publication consistent with transaction visibility without treating
the image as durable source data.

Index updates are governed separately from reads. An index can be maintained on
insertion or rebuilt only on request. MPF is the default minimizer index and is
suited to insertion-time work. MPS is normally manual because construction
requires a sequence-wide merge. Deferred persistence transfers stable relation
identity and parameters to a database worker. It does not transfer live
snapshots, relation handles, or memory owners. The worker opens the source under
its own database context and rechecks the epoch and policy before writing.

\section{Compatibility and integrity}
\label{sec:index-compatibility}

A valid byte sequence is not necessarily a usable index. Query and target
minimizers must be produced by the same hash scheme and parameter set. The
reader also needs a position width capable of representing the source, a known
control layout, and occurrence counts with the expected meaning. A direct
accelerator view adds an execution interface requirement because its kernels
interpret the stored shape without a general conversion step.

For current versioned MPF and MPS formats, the compatibility identity includes
at least the following fields:

\begin{itemize}
  \item source relation, sequence column, source epoch, and generation
  \item alphabet and encoded symbol width
  \item minimizer \(k\), window \(w\), hash scheme, and scheme version
  \item position width, occurrence policy, and persistent layout
  \item producer identity, and accelerator identity for directly consumed
        persisted outputs
\end{itemize}

Legacy asynchronous payloads do not carry the complete scheme identity. They
are admitted only through their narrower layout contract. In particular,
bounded ntHash reads are excluded from this legacy persisted path.

Manifests bind this identity to section lengths, ordering, checksums, and
address ranges. Readers check arithmetic before constructing spans, so a corrupt
count cannot wrap around and designate an apparently small allocation. Reserved
fields and format versions are checked rather than ignored. Relation chunks are
checked at the granularity in which they are admitted. A sealed image checks its
fixed header and identity when opened, while complete section checks are part of
publication and full inspection.

The SQL read requirement determines the response to absence or mismatch. A
request that requires a compatible persisted index fails if no matching index
is visible. It does not silently sketch the source. A permissive request may
recompute a transient index. A request that requires absence bypasses
persisted reads and forces transient recomputation even when stored data
exists. These policies separate
correct fallback behavior from measurements or operations that depend on a
particular representation.

Compatibility checking occurs before a CPU or accelerator view is reused.
A resident object is keyed by the persisted assembly identity and relevant
algorithm parameters. Matching SQL types are insufficient because two payloads
with the same row schema can use different hash schemes or control layouts.

\section{Selective cold loading and memory accounting}
\label{sec:index-cold-loading}

Serialized size does not describe the peak memory of an index read. A backend
may simultaneously own a directory, selected controls, postings, decoded
positions, a transient lookup, query occurrence counts, input buffers, and an
accelerator upload. BioSeqDB uses explicit permits for these significant owners.
A component obtains admission before allocating or retaining its destination,
and the permit remains held for the lifetime of cached or device-resident data.

Figure~\ref{fig:index-selective-load} shows the cold MPS path. The directory is
small enough to read and check as a complete navigation object. Distinct query
hashes identify the relevant control blocks. Counts are then compared with the
occurrence threshold. Only postings for surviving hashes are authorized, read,
and clipped to the requested target interval.

Physical access must preserve this logical selectivity. Adjacent authorized
ranges are coalesced into bounded read slabs, rather than fetched as many small
objects. Checksums are evaluated at the addressed unit. For MPF, the direct
sealed-image route avoids reconstructing a large immutable image through a
large number of relation tuples. The relation generation remains authoritative
for lifecycle and identity even when the read data plane is mapped.

Memory accounting distinguishes mapped address space from owned working data.
Opening a large immutable image does not allocate an equally large decoded
container, but operating-system page residency is not controlled by the
backend's memory permit. The permit covers decoded arrays, assembled lookups,
resident chunks, and device allocations. A memory-bound claim must state which
of these domains are included. A process-cold measurement must also
consider filesystem cache state separately.

Mapped-image lifetime is registered with database resource ownership so normal
completion and error handling close it. Backend-local caching is bounded by
entry and byte limits. The active relation reader can retain checked chunks,
while runtime-specific caches may retain compatible derived views. Transaction
abort and relation invalidation remove entries that may no longer be reused.
These caches reduce
repeated work within one backend, but they do not define visibility across
backends. PostgreSQL snapshots and the published descriptor remain the source
of coherence.

\section{Runtime index selection}
\label{sec:index-runtime-selection}

The alignment dispatcher resolves an index policy for each source sequence
column. Presence alone is not enough. The dispatcher combines the requested
index name with the read requirement, visible source epoch, compatibility
identity, available reader route, memory admission, and execution backend.
Algorithm~\ref{alg:index-runtime-selection} states the decision.

\begin{algorithm}[H]
  \caption{Runtime selection of a persistent minimizer index}
  \label{alg:index-runtime-selection}
  \small
  \textbf{Input.} Source identity \(I\), query minimizers \(Q\), and read
  requirement \(R\).
  \begin{enumerate}
    \item Resolve the active index policy for the source column.
    \item If stored reads are permitted, resolve the visible descriptor.
    \item If a descriptor exists, check its source epoch, algorithm identity,
          layout, lengths, and addressed checksums.
    \item For MPF, read compatible fragment images or the configured sealed
          image, then obtain an admitted runtime view.
    \item For MPS, search the directory with \(Q\), load selected controls and
          postings, and assemble a clipped lookup.
    \item Reuse a compatible resident view when its complete identity matches.
    \item If no usable index exists and \(R\) requires persistence, fail.
    \item Otherwise build a transient index and, when policy permits, schedule
          persistence using stable database identity.
    \item Retain the selected descriptor and runtime view until the batch ends.
  \end{enumerate}
\end{algorithm}

The default active minimizer path is MPF. When both deferred MPF and MPS
policies could write an index, selection is deterministic and prefers MPF.
This avoids presenting two incompatible background products as one implicit
choice. MPS is selected explicitly when its construction cost is justified by
selective reads. A strict persisted requirement turns an absent or incompatible
object into an error. A permissive query can continue with recomputation.

Runtime selection also separates persistence from the final execution shape.
The stored representation may be adapted into a CPU lookup or a compatible
accelerator view. Those derived views have their own memory lifetime and cache
identity. Device dispatch does not weaken host-side compatibility checks.

\section{Differences from minimap2 \texttt{.mmi}}
\label{sec:index-minimap2-comparison}

The minimap2 index is an appropriate algorithmic reference because BioSeqDB
uses the same general family of minimizer seed lookup
\autocite{minimap2_paper,minimap2_software}. A \texttt{.mmi} file records
minimizer parameters, reference metadata, bucket data, and optionally the
packed reference sequence. Each bucket has a hash lookup and a positions
array. A singleton position can be stored directly in the hash value, while a
repeated minimizer points to a range in the positions array. The loader reads
the file and reconstructs the complete in-memory bucket representation.

This design fits a command-line mapper. The caller chooses the file and replaces
it when the reference changes. Stored parameters are interpreted by the mapper's
own load contract. There is no need for a database snapshot to keep an older
file version visible while another transaction publishes a replacement.

BioSeqDB retains the useful offset-and-count lookup idea, but changes the
surrounding contract. Sequence-wide layouts use global coordinates, while MPF
stores fragment-local positions because long sequence values are stored in
fragments. MPS and the selective stream format can read
only query-relevant hash ranges. Neither organization is wire-compatible with
\texttt{.mmi}.

The larger difference concerns ownership. A versioned BioSeqDB index is bound to a
relation, column, source epoch, algorithm identity, and published generation.
Legacy updates can participate in insertion policy or an explicit rebuild. A new
immutable generation is checked before publication, and the predecessor remains
available to older snapshots. Cold loading is subject to backend memory
admission, and cached CPU or device views inherit the same compatibility
identity. These mechanisms are unnecessary for a standalone \texttt{.mmi}
file, but they are required when index reuse is part of transactional SQL.

The direct sealed-image route does not remove this distinction. Although both
systems can read an ordinary file efficiently, BioSeqDB's image is selected by
an authoritative database descriptor, and its retirement is recorded
transactionally. It is derived from the database generation and may be regenerated.
It is not a user-selected replacement for PostgreSQL index state.

\section{Operational limits and conclusions}
\label{sec:index-storage-conclusions}

Persistent minimizer storage reduces repeated construction, but it adds
recovery and administration requirements. Unlogged payload relations must be
rebuilt after reset. Sealed images must either be included in backup and
replication procedures with their descriptors or be regenerated from the
authoritative source. Operating-system page cache residency lies outside
backend memory permits, so warm and cold
measurements require separate interpretation.

The two retained organizations address different workload shapes. MPF follows
fragment-native ingestion and remains the default. MPS pays for a bounded
sequence-wide merge to gain query-selective loading. The versioned forms of both
organizations include the source epoch and minimizer semantics in their
compatibility identity. MPS construction uses admitted sorted runs and bounded
spill. Immutable mode checks an unpublished generation before atomic descriptor
replacement.

The resulting design differs from a database wrapper around a minimap2 file. It
defines a transaction-aware index lifecycle with explicit logical organization,
physical representation, publication, memory admission, and runtime selection.
These properties allow persistent seed lookup to coexist with lazy sequence
storage, concurrent SQL readers, and multiple execution backends.
