\section{From every base to a sparse, comparable sketch}
\label{sec:minimizers-role}

The first computational stage of the BioSeqDB mapper converts a sequence into a
much smaller stream of representative $k$-mers.  This stream is called a
\emph{minimizer sketch}. The target sketch becomes an index. The query sketch
is looked up in that index, and equal keys become the anchors consumed by
Chapter~\ref{r:06-chaining}. Sketching is therefore more than a sampling
optimization. Its hash
function, strand convention, tie rule, invalid-symbol rule, and output encoding
jointly define the language spoken by the query and its stored target index.
Changing any component can yield an implementation whose output is
incompatible with the stored index.

This observation explains an otherwise surprising property of the final
implementation: BioSeqDB retains several minimizer backends instead of
declaring one universally best algorithm.  The current public backend enum in
\path{main/bioseq/backend/sequences/kmers/index.cppm} contains
\texttt{Scalar}, \texttt{ExactSimd}, \texttt{PaperNtHashSimd}, and
\texttt{VulkanSegment}.  Scalar and ExactSimd share the legacy minimap-style
scheme. PaperNtHashSimd implements the versioned paper-derived 32-bit ntHash
scheme stored under identifier \texttt{PNT1}. VulkanSegment reproduces the
legacy minimap-style
scheme on a device through the Phase C tiled kernel.  Persisted index metadata
records the selected scheme; dispatch is not allowed to substitute one scheme
for another merely because both outputs are called ``minimizers''.

The implementation history is useful because it exposes three recurring
lessons:

\begin{enumerate}
  \item a scalar algorithm with irregular control flow is not made efficient
        merely by replacing scalar integers with vectors;
  \item a mathematically attractive hash or tie policy is not a transparent
        replacement for a deployed index scheme; and
  \item accelerator throughput matters only after fragment boundaries,
        ambiguous symbols, output order, memory admission, and host/device
        transfers have been included in the contract.
\end{enumerate}

The discussion below first defines that contract, reconstructs minimap2 and
SIMD-Minimizers, then follows the rejected and retained BioSeqDB designs.  Code
locations refer to the current checkout.  Historical timing claims are tied to
the archived report that measured them; they are not presented as current
performance.

\subsection{Formal definition}
\label{sec:minimizer-definition}

Let $S=s_0s_1\ldots s_{n-1}$ be a sequence over an alphabet $\Sigma$.  For
nucleotide sketching, valid bases are normalised to minimap2's nt4 codes
\[
  \eta(A)=0,\qquad \eta(C)=1,\qquad \eta(G)=2,\qquad \eta(T)=3,
\]
and an ambiguous base such as dna5's $N$ maps to a sentinel.  The $k$-mer
beginning at $i$ is $K_i=S[i,i+k)$.  Its reverse complement is
$\overline{K_i}$, and its canonical orientation is determined from the two
encoded integers
\[
  F_i=\operatorname{enc}(K_i),\qquad
  R_i=\operatorname{enc}(\overline{K_i}).
\]
For the minimap-style scheme, define
\[
  C_i=\min(F_i,R_i),\qquad
  z_i=\begin{cases}0&F_i<R_i,\\1&R_i<F_i,\end{cases}
  \qquad h_i=H_{\mathrm{mm}}(C_i).
\]
When $F_i=R_i$, the strand is undefined and the candidate is a sentinel rather
than an emitted minimizer.  A candidate record is
\[
  x_i=(h_i,\;i+k-1,\;z_i),
\]
where the position denotes the final base of the $k$-mer, matching minimap2.
For every window of $w$ consecutive candidates,
\[
  W_j=(x_j,x_{j+1},\ldots,x_{j+w-1}),
\]
the basic minimizer is an argument attaining
\[
  m_j=\min_{x\in W_j} h(x).
\]
Random hashes make the same candidate the minimum of several neighbouring
windows; adjacent windows therefore usually repeat a position.  A collector
emits changes in the selected identity rather than one record per window.  For
ideal independent hashes the expected minimizer density is approximately
$2/(w+1)$, so $w=10$ retains roughly one candidate in every 5.5 positions.

The word ``identity'' is load-bearing.  In BioSeqDB's compact
\texttt{MinimizerRepr}, comparisons mask off position and strand and compare
only the hash field, while \texttt{does\_sketch\_match} means ``same hash but a
different identity''.  Two equal hashes at different positions are therefore
ties to be reported, not duplicate machine words to be discarded.  This is why
the final ExactSimd implementation carries both a hash vector and raw
position/strand metadata through its rare tie path.

\subsection{The minimap2 scalar reference}
\label{sec:minimap2-sketch}

The bundled baseline,
\path{main/bench/tool_minimap2/minimap2/sketch.c}, makes the compatibility
contract concrete.  It maintains two rolling two-bit integers:
\[
\begin{aligned}
 F_i &= ((F_{i-1}\ll2)\mathbin{\vert}c_i)\mathbin{\&}(2^{2k}-1),\\
 R_i &= (R_{i-1}\gg2)\mathbin{\vert}((3\oplus c_i)\ll2(k-1)).
\end{aligned}
\]
The smaller orientation is mixed by Thomas Wang's reversible integer
scramble, with every arithmetic step masked to the $2k$-bit domain.  In the C
source this is \texttt{hash64}; the packed record is
\texttt{x = hash << 8 | span} and
\texttt{y = rid << 32 | lastPos << 1 | strand}.  BioSeqDB drops fields not
needed by its pipeline and instead chooses a 16-, 32-, 64-, or 128-bit
\texttt{MinimizerRepr} from the position and hash requirements.  The common
$k=15$, maximum-position-$2^{28}$ layout uses a single 64-bit word with one
strand bit, 28 position bits, and 35 available hash bits.

The scalar window minimum is a circular buffer plus a saved minimum.  A new
candidate replaces the saved minimum on \emph{less than or equal}; consequently
the entering candidate is the rightmost equal minimum.  When the saved
candidate expires, the ring is scanned from oldest to newest with a
\emph{greater than or equal} comparison, again ending on the closest
(rightmost) equal candidate.  The first full window and expiry path also emit
other equal-hash, different-identity candidates.  This chronology is more
specific than the often-quoted rule ``deduplicate minimizer positions''.

\begin{algorithm}[H]
\caption{Minimap-style scalar event collector, including the semantic branches}
\label{alg:minimap-scalar-events}
\small
\begin{algorithmic}[1]
\Require packed or decoded sequence $S$, $k$, $w$
\State initialise forward and reverse rolling encodings
\State $\textit{ring}[0..w-1]\gets\infty$;
       $\textit{current}\gets\infty$
\For{each base $s_i$}
  \If{$s_i$ is ambiguous}
    \State reset valid-run length and both rolling encodings
    \State $\textit{candidate}\gets\infty$
  \Else
    \State roll $(F,R)$; increment valid-run length
    \If{at least $k$ clean bases and $F\ne R$}
      \State $\textit{candidate}\gets
        (H_{\mathrm{mm}}(\min(F,R)),i,\operatorname{strand}(F,R))$
    \Else
      \State $\textit{candidate}\gets\infty$
    \EndIf
  \EndIf
  \State overwrite the next circular-buffer slot with \textit{candidate}
  \If{this is the first full window}
    \State emit other identities tied with \textit{current}
  \EndIf
  \If{$\textit{candidate.hash}\le\textit{current.hash}$}
    \State emit old \textit{current} when the stream is armed
    \State $\textit{current}\gets\textit{candidate}$
  \ElsIf{the overwritten slot held \textit{current}}
    \State emit old \textit{current}; rescan the ring with $\ge$
    \State emit other identities tied with the rescanned minimum
  \EndIf
\EndFor
\State unconditionally emit the final live \textit{current}
\end{algorithmic}
\end{algorithm}

An ambiguous input character resets the clean-base counter and rolling
$k$-mer, ensuring that no emitted $k$-mer spans an $N$.  The original
minimap2 C loop skips a palindromic $k$-mer with \texttt{continue}; the
BioSeqDB scalar reference instead advances the ring with a max-valued sentinel.
The palindrome still cannot become a minimizer, but it consumes a window slot.
This was chosen so scalar and vector lanes share one chronological window
shape.  It is a disclosed structural deviation from minimap2, not an accidental
implementation detail.

\section{Eliminating data-dependent rescans}
\label{sec:two-stack-minimum}

The minimap2 ring is an excellent scalar design.  Its rescan branch is taken
only when the saved minimum expires, approximately once every $w$ candidates.
Lane-parallel execution changes that probability.  With $L$ independent
streams and a scalar rescan probability near $1/w$, the probability that at
least one lane requests the slow path in a vector step is
\[
  1-\left(1-\frac{1}{w}\right)^L.
\]
For $w=10$ and four NEON lanes this is approximately $34.4\%$, rather than
$10\%$.  Each divergent step must mask unaffected lanes or spill state to a
temporary matrix.  This is why BioSeqDB's first literal SIMD port performed
more work even though it computed four hashes at once.

\subsection{Deque, rescan, and two-stack formulations}

There are three standard ways to maintain a sliding minimum:

\begin{description}
  \item[Rescan.] Keep a circular buffer and a current minimum; scan $w$
    candidates only when that minimum expires.  Expected linear time and very
    small scalar state, but data-dependent work.
  \item[Monotone deque.] Remove expired indices from the front and candidates
    no smaller than the entering value from the back.  Amortised $O(n)$, but
    each candidate executes a data-dependent number of pops.  It vectorises
    poorly for the same reason.
  \item[Prefix/suffix or two-stack minimum.] Partition candidates into blocks
    of $w$.  Store prefix minima from the start of the current block and suffix
    minima from the end of the previous block.  A crossing window is the
    minimum of exactly two precomputed values.  The suffix pass runs once every
    $w$ candidates and always has the same length.
\end{description}

For a hash sequence $a_0,\ldots,a_{n-1}$, let block
$B_q=(a_{qw},\ldots,a_{qw+w-1})$.  Define
\[
  P_i=\min(a_{qw},\ldots,a_i),\qquad
  Q_i=\min(a_i,\ldots,a_{qw+w-1})
\]
for $i\in B_q$.  If a window begins at $j$ and ends at $e=j+w-1$,
\[
  \min(a_j,\ldots,a_e)=\min(Q_j,P_e).
\]
Both input and control flow are therefore regular.  A tie-aware combine can
carry $(h,p_\ell,p_r)$ instead of a single hash, retaining the leftmost and
rightmost positions that attain $h$.

\subsection{Rolling ntHash}
\label{sec:rolling-nthash}

SIMD-Minimizers combines the data-independent minimum with ntHash.  Associate
each nucleotide with a pseudo-random 32-bit constant $f(b)$ and choose a
rotation $r$ (BioSeqDB freezes $r=7$).  For a $k$-mer beginning at $i$,
\[
\begin{aligned}
 H^F_i &= \bigoplus_{j=0}^{k-1}
       \operatorname{rotl}\!\left(f(s_{i+j}),r(k-1-j)\right),\\
 H^R_i &= \bigoplus_{j=0}^{k-1}
       \operatorname{rotl}\!\left(f(\overline{s_{i+j}}),rj\right).
\end{aligned}
\]
After the $O(k)$ initialisation, the forward state advances in constant time:
\[
 H^F_{i+1}=
 \operatorname{rotl}(H^F_i,r)
 \oplus \operatorname{rotl}(f(s_i),rk)
 \oplus f(s_{i+k}).
\]
The reverse-complement recurrence rotates in the opposite direction and
replaces the outgoing and incoming complement contributions.  In the
BioSeqDB PNT1 scheme the canonical key is the wrapping 32-bit sum
\[
  h_i=H^F_i+H^R_i \pmod {2^{32}},
\]
while the stored strand records whether $H^R_i<H^F_i$.  This differs
fundamentally from applying minimap2's integer scramble to
$\min(F_i,R_i)$; the two schemes cannot share a persisted index.

The upstream SIMD-Minimizers implementation makes canonical window selection
reverse-complement invariant by retaining both extreme equal minima and then
choosing the left or right endpoint according to a canonical orientation of
the full $(k+w-1)$-base window.  Its orientation counter compares the number of
$G/T$ symbols with the number of $A/C$ symbols and requires an odd window span
to avoid a tie.  BioSeqDB's packed PNT1 fork makes a different, explicit
choice: it emits the left endpoint and, when the minimum hash is tied, also the
right endpoint, then suppresses identical adjacent identities.  Thus it keeps
a reverse-complement-symmetric endpoint superset without importing the
upstream window-orientation counter.

\begin{algorithm}[H]
\caption{Data-independent paper-style ntHash minimizers}
\label{alg:paper-nthash}
\small
\begin{algorithmic}[1]
\Require dna4 sequence $S$, compile-time $k$, $w$
\State split $S$ into eight logical streams with $k+w-2$ bases of context
\State initialise vector forward/reverse ntHash states and a $w$-slot ring
\For{each lock-step packed-symbol vector}
  \State decode ranks directly from packed sequence words
  \State update forward and reverse ntHash with rotations/XOR/table lookup
  \State $h\gets H^F+H^R\pmod{2^{32}}$; record per-$k$-mer strand
  \State update the block prefix minimum with
         $(h,p_\ell,p_r,z_\ell,z_r)$
  \If{the $w$-slot block wrapped}
    \State rebuild all suffix minima in a fixed reverse loop
  \EndIf
  \State combine one prefix and one suffix minimum
  \State emit the left endpoint if its identity differs from the last output
  \State emit the right endpoint too when the minimum is tied
\EndFor
\State reconcile the first/last identities of adjacent logical streams
\end{algorithmic}
\end{algorithm}

\subsection{Eight logical streams on variable-width SIMD}

The original Rust implementation fixes eight 32-bit lanes.  It splits the
sequence into eight contiguous chunks and overlaps neighbouring chunks by
$k+w-2$ bases so that each owned window has enough left and right context.
Window minima are produced lane-wise, transposed back to sequence order, and
deduplicated at chunk joins.

BioSeqDB preserves the eight-\emph{logical}-stream algorithm but implements it
with Highway.  On AArch64 NEON, four physical 32-bit lanes require two
independent vector registers per step; on an eight-lane target one register is
enough.  The execution proof requires
\[
  \textit{registers-per-step}\times\textit{physical-lanes}=8.
\]
Input is not converted to the Rust library's packed type.  The kernel consumes
the existing \texttt{compact\_sequence\_range} through the project's packed
iterator, fixes the final-stream tail mask explicitly, computes segment-local
positions, and lets the segmented caller add a checked global base offset.
The first event of logical lanes 1--7 is withheld until the preceding lane's
last identity is known, so cross-stream deduplication uses only bounded
metadata.

\section{BioSeqDB's CPU implementation history}
\label{sec:minimizer-cpu-history}

\subsection{Why the literal SIMD port failed}

The earliest vector collector kept minimap2's rescan state independently in
each lane.  Two bugs arrived before performance could even be judged.  First,
the strand bit was not carried through every buffer update, so approximately
half of reverse-oriented matches disappeared. DOC0107 records values of 0.958
and 0.972 on its short and medium fixtures after strand masks, strand buffers,
and duplicate-emission propagation were corrected. The archived record does
not define the metric and denominator precisely enough to promote these values
to an accuracy claim. Second, each lane's data-dependent rescan forced
horizontal tests and masked buffer updates.  The SIMD unit was busy, but the
instruction stream did more bookkeeping than the scalar loop.

Micro-optimisations could not repair that algorithmic shape.  DOC0108 replaced
general complement work with dna4 XOR, hoisted palindrome masks, and fused
lane predicates.  Its measured collector moved only from approximately
40.8 to 39.6 ms while the scalar reference remained near
12.7--12.9 ms.  Later direct packed access removed an eager conversion, but
also exposed an LSB-first ordering error in the first helper.  Correcting that
error restored identity, not speed.

The long-sequence report DOC0113 gives the honest intermediate result.  For
the 903 kbp case, whole-pipeline minimap2, scalar BioSeqDB, and SIMD BioSeqDB
were 185.6, 158.4, and 170.7 ms; for 5 Mbp they were 1062.1, 994.5, and
1047.2 ms.  The vector route was still 5--8\% slower than BioSeqDB scalar.
The report attributes the gap to horizontal \texttt{AllFalse} checks, spills,
output-buffer traffic, and runtime shifts.  These archived figures should not
be compared numerically with the current XXL benchmark: they use different
inputs, binaries, and whole-pipeline configurations.

\subsection{The V4--V15 branch: useful ideas and misleading names}

DOC0114 and DOC0118 then moved the collector to a prefix/suffix minimum
inspired by SIMD-Minimizers.  This branch produced several techniques that
remain useful:

\begin{itemize}
  \item direct traversal of packed sequence storage;
  \item static $w=10,k=15$ specialisation;
  \item two independent vector streams on NEON to expose instruction-level
        parallelism;
  \item explicit transposition and stable compression of lane outputs;
  \item forced inlining of the packed-iterator callback; and
  \item preallocation and bounded boundary deduplication.
\end{itemize}

It also produced an important naming trap.  The public benchmark name
\texttt{two\_stack\_nthash} was used while some versions ordered canonical
two-bit words lexicographically, mixed them with a golden-ratio multiplier, or
deferred the minimap scramble until emission.  A non-order-preserving scramble
cannot be deferred while retaining the same minimizer set.  Later DOC0370
forensics found that the exceptionally fast report-76 row was the older
resident eight-stream prefix/suffix collector: it disabled palindrome
detection on its long dual-stream route and had stream-topology-dependent
boundaries.  It is therefore historical approximate evidence, not a
byte-for-byte baseline for today's ExactSimd continuation.

The optimisation sequence was nevertheless informative.  The V8 ordering
change roughly halved the expensive inner work, V11 interleaved two independent
streams, and V12 removed a surviving out-of-line lambda; the recorded inner
phase fell to approximately 9.23 ms on that report's case.  V13's largest win
was actually downstream: replacing a sort in \texttt{mm\_est\_err} with prefix
counts reduced that region from 7.88 to 0.85 ms.  A destructive

\section{Current BioSeqDB minimizer backends}

\subsection{ExactSimd: segmented minimap-compatible continuation}
\label{sec:exact-simd}
\label{sec:exact-simd}

The exact segmented kernel was written to answer a different question from
the paper backend: can vector instructions reproduce BioSeqDB's legacy
minimap-style event stream over a lazy, fragmented packed sequence without
falling back to scalar sketching?  Its public checked driver is in
\path{main/bioseq/backend/sequences/kmers/two_stacks_minimizers.cppm}.
Despite historical function names containing \texttt{nthash}, this path
canonicalises the two-bit forward/reverse $k$-mer and applies the minimap
integer scramble.  It is not ntHash.

\subsubsection{Bounded state across arbitrary fragments}

For a static $W,K$, \texttt{TwoStackContinuationState} retains at most
$K-1$ normalised nt4 codes, $W-1$ candidate hashes/raw records/ordinals, less
than one pending SIMD block, the current minimum, counters, and execution
proof.  A fragment boundary neither resets nor replays the biological
algorithm.  The next call completes the pending chronological block and
continues from the saved carries.  The memory bound depends on $K$, $W$, and
the vector width, not on sequence length or fragment count.

For dna5, packed symbols do not form a continuous bit stream across storage
words because three bits per symbol leave unused high bits.  The generic
decoder therefore prepares source-word addresses and shifts per active lane,
then performs rank extraction, rank-to-nt4 normalisation, and ambiguity
classification as Highway vector operations.  Scalar orchestration is
reported separately and never hashes, canonicalises, selects a minimum, or
emits a record.  Unsupported alphabets, storage shapes, position ranges, or
scalar Highway targets return a checked status and are converted into
\texttt{ExactSimdRuntimeError}; the selected Exact backend does not silently
call the scalar collector.

An ambiguous base is also not an implicit fragment finalisation.  The kernel
flushes any pending valid candidate block, clears the $K$-mer context and
clean-run length, then advances one max-valued candidate through the ring.
It does not clear the $W$-candidate tail, reset its chronological ordinal, or
emit the current minimum.  End-of-input alone performs minimap2's
unconditional final-current flush.

\subsubsection{The common $k=15,w=10$ B8 specialization}

The generic chronological kernel reconstructs overlapping canonical $k$-mers
and scans $W$ candidates for each vector group.  DOC0370 showed why this exact
approach regressed: on a 500 Mbp target an older two-lane version executed
about 250 million vector batches but 9.75 billion scalar-orchestration steps,
behaving like $O(N(K+W)/2)$ rather than a rolling hash plus amortised minimum.

The retained specialisation processes eight candidates at a time.  It takes
the $K+B-1=22$ needed dna4 codes, SWAR-packs them into 44 bits, extracts eight
overlapping 30-bit K15 words through fixed shifts, forms forward and reverse
orientations in two independent u32 streams, applies the exact minimap
scramble, and carries 64-bit position/strand metadata separately.  The
$W=10$ reduction still scans ten chronological slots, deliberately using
\texttt{<=} so each lane ends on the rightmost equal minimum.  This is more
work than the paper's prefix/suffix combine, but it preserves the deployed
event chronology.

Most windows have no equal-hash, different-identity event.  The common path
therefore performs a stable \texttt{CompressStore} directly.  A hash-only
prefilter guards the expensive raw-aware tie matrix.  In report 100 the target
prefilter rejected 46,654,429 possible-tie lanes; only 1,051 batches reached
the raw verifier and tie matrix.  When that rare route is needed, the kernel
constructs event 0 (the old minimum) plus up to $W$ tied identities per lane,
transposes the event matrix in registers, and stable-compresses rows in
chronological order.

\begin{algorithm}[H]
\caption{ExactSimd B8 block, simplified}
\label{alg:exact-b8}
\small
\begin{algorithmic}[1]
\Require $K=15,W=10$, eight pending dna4 positions, continuation state
\State load $22=K+8-1$ context symbols and SWAR-pack them
\State extract eight overlapping forward K15 integers by fixed shifts
\State construct eight reverse-complement integers
\State $c\gets\min(f,r)$; mark palindromes as max sentinels
\State $h\gets H_{\mathrm{mm}}(c)$; pack $(h,p,z)$ in raw metadata
\State concatenate the saved $W-1$ candidate tail and eight new candidates
\For{each of the $W$ chronological slots}
  \State update eight lane minima using $\le$ (rightmost equal wins)
\EndFor
\State derive entering-minimum, expiry, first-window, and final event masks
\If{no actual equal-hash/different-identity event}
  \State stable-compress ordinary events directly
\Else
  \State build and transpose the exact tie-event matrix
  \State stable-compress all chronological events
\EndIf
\State save the final $W-1$ candidates and current minima as continuation
\end{algorithmic}
\end{algorithm}

The source still contains a separately attested full-resident
\texttt{vector\_stream} route for borrowed contiguous dna4/u32 data and the
historical XXL shape.  It is intentionally distinguished in
\texttt{TwoStackExecutionProof} from the B8 continuation.  Because later
forensics found that historical route did not satisfy all exact palindrome and
boundary semantics, it must be treated as an approximate resident control, not
as proof that the segmented Exact scheme has reached report-76 speed.  This
remaining split is one reason the final performance-qualified SIMD story uses
the separately named PNT1 backend rather than relabelling the resident control
as ExactSimd.

\subsection{PNT1: turning the paper algorithm into a persistent BioSeq scheme}
\label{sec:pnt1}

The SIMD-Minimizers result was ultimately useful, but not as a drop-in faster
implementation of the minimap2 sketch.  Its canonical hash selects an extreme
minimum using the orientation of the complete $(K+W-1)$-base window; minimap2
instead hashes every canonical $K$-mer and applies the rightmost-minimum event
rules described above.  Those definitions can choose different seeds even
when both implementations are internally correct.  BioSeqDB therefore gives
the paper-derived implementation a distinct, versioned identity:
\texttt{PackedPaperNthash}, persisted as scheme identifier
\texttt{PNT1} (\texttt{0x504e5431}).  This decision converts a tempting hidden
substitution into an explicit index contract.

The current PNT1 collector accepts packed dna4 input.  It keeps eight logical
streams because that is the decomposition used in the original algorithm,
while mapping them onto either four or eight physical Highway lanes according
to the target instruction set.  Forward and reverse-complement rolling hashes
are updated with wrapping addition and seven-bit rotations.  Each stream
retains both extreme equal minima.  The upstream canonical algorithm chooses
one of those extremes from the complete-window orientation; BioSeq instead
emits the left extreme and, when its identity differs, the right extreme as
well.  This BioSeq tie contract is deliberate: it is deterministic, does not
silently erase equal-hash identities, and is encoded in the PNT1 scheme rather
than advertised as minimap2 compatibility.

Logical fragments do not reset the rolling state.  The continuation contains
the previous $K-1$ bases, the minimum candidates required by the eight
streams, the absolute origin, and at most one pending block.  A fragment is
therefore an input-delivery boundary, whereas an ambiguous symbol is a
biological reset boundary.  The packed dna4 precondition means that ambiguity
has already been excluded by the representation.  If the proof of packed
storage, position width, or supported parameters is missing, the backend
fails closed; it does not reinterpret dna5 bytes as two-bit symbols and does
not fall through to a differently named scheme.

\begin{algorithm}[H]
\caption{PNT1 collection over a fragmented packed sequence}
\label{alg:pnt1}
\small
\begin{algorithmic}[1]
\Require scheme \texttt{PNT1}, packed dna4 fragments $F_0,\ldots,F_m$
\State verify storage proof, supported $(K,W)$, and position width
\State initialise eight logical rolling streams and an empty continuation
\For{each fragment $F_i$ in logical order}
  \State prepend only the saved $K-1$ context and the pending partial block
  \For{each complete eight-position block}
    \State decode the block directly from the packed words
    \State roll forward and reverse-complement ntHash values in all streams
    \State update each stream's left and right extreme minima
    \State emit deterministic PNT1 events owned by the block
  \EndFor
  \State save the bounded continuation; do not flush merely at $F_i$'s end
\EndFor
\State flush the one logical sequence end and return the scheme-tagged sketch
\end{algorithmic}
\end{algorithm}

\subsection{Vulkan Phase C: exact extraction on the device}
\label{sec:vulkan-minimizers}

The GPU implementation follows a different optimisation path.  Its purpose is
not to reproduce the eight-stream PNT1 decomposition, but to execute the
minimap-compatible scalar state machine over device-resident packed sequences.
It belongs to Phase C of the GPU pipeline: metadata, packed bases, sketch
events, seed hits, and downstream work can remain on the device.  This avoids
making a fast kernel irrelevant by repeatedly materialising sequences or
events on the host.

\subsubsection{Relationship to G3SA}

G3SA demonstrated that seed generation and alignment preparation can be
structured as a resident CUDA pipeline.  Its minimap2-derived sketch kernel
assigns one block to a read, uses a 32-thread warp and 128-base tiles, and has
thread zero compact the events.  The supplied reference kernel reconstructs a
$K$-mer from characters for each position, so its core work is
$O(K)$ per candidate rather than an $O(1)$ rolling update.  It also assumes a
small DNA-plus-\texttt{N} alphabet and treats an invalid character as a local
\texttt{continue}; that is not equivalent to resetting every window that
spans the symbol.

BioSeqDB adopts the useful system-level lesson---keep the data and successive
stages resident---but not those sketch semantics.  The implementation uses
Vulkan compute shaders, packed generic sequence descriptors, rolling
forward/reverse encodings, an exact minimap scramble, and an explicit
count/scan/emit protocol.  Table~\ref{tab:g3sa-comparison} makes the distinction
concrete.

\subsubsection{Tiles are storage units, not independent sequences}

An output event depends on the preceding $K-1$ bases and on a minimizer window
of $W$ candidate positions.  Starting every tile with empty state would
therefore invent resets and lose boundary events.  Phase C solves this with
replay and ownership.  For a tile whose owned trigger interval is
$[b,e)$, the shader begins earlier by a conservative overlap currently bounded
by $K+W+1$, reconstructs the exact state, and emits only events whose trigger
position lies in $[b,e)$.  Neighbouring tiles may recompute context, but they
cannot both own the same event.

The planner targets approximately 256 logical bases and rounds storage
according to the sequence representation; a dna5 packing shape therefore
commonly produces 252-base logical tiles.  The ABI bounds the supported span
and currently admits up to 384 bases including replay.  Those numbers are
planner parameters, not algorithmic constants: correctness follows from
replay coverage and half-open ownership, not from the nominal tile size.

The output cardinality is data dependent: ties and expiry events mean that a
window does not imply exactly one stored record.  A one-pass kernel would need
a large pessimistic buffer or a contended global append counter.  Phase C
instead executes the same state machine twice.  The first pass counts events
per descriptor; an exclusive prefix scan assigns exact offsets; the second
pass replays and writes only to the assigned interval.  This provides
deterministic event order and makes allocation failure visible before emission.

\begin{algorithm}[H]
\caption{Phase C exact tiled minimizer extraction}
\label{alg:phase-c-minimizers}
\small
\begin{algorithmic}[1]
\Require packed sequence descriptors, $(K,W)$, half-open tile ownership
\For{pass $\in\{\mathrm{count},\mathrm{emit}\}$}
  \ForAll{tiles in a grid-stride loop}
    \State start at the tile's replay origin with empty scalar-equivalent state
    \For{each logical symbol through the owned interval}
      \State decode rank from the representation-specific packed layout
      \If{the symbol is invalid}
        \State reset rolling encodings, ring, minimum, and valid-run length
      \Else
        \State roll forward and reverse encodings; canonicalise and scramble
        \State apply palindrome, rightmost-tie, expiry, and final-event rules
        \ForAll{events triggered at this position}
          \If{trigger is in the half-open owned interval}
            \State count it, or write it at the scanned tile offset
          \EndIf
        \EndFor
      \EndIf
    \EndFor
  \EndFor
  \If{pass is \textsc{count}}
    \State exclusive-scan tile counts and allocate the exact output
  \EndIf
\EndFor
\end{algorithmic}
\end{algorithm}

\subsubsection{Why the first GPU version was not the final one}

The development record is instructive because each intermediate version was
plausible in isolation:

\begin{enumerate}
  \item Phase B used a mixture of host metadata and specialised GPU work.  A
  4096-base dna5 case produced 859 events where the scalar oracle produced
  795.  Changing padding and inserting \texttt{N} symbols did not remove the
  excess, pointing to ownership/state rather than input corruption
  (DOC0348).
  \item The Phase C ABI made packed storage and descriptor metadata available
  everywhere, then DOC0351--DOC0352 retired the Phase-B route and forced one
  semantics-bearing path for all supported representations.
  \item The first Phase C shader still reconstructed too much state and left
  work concentrated in too few lanes.  DOC0353 replaced that structure with
  rolling hash updates and an all-lanes, grid-stride tile schedule.  The
  output remained bit-exact while sketch throughput increased from about
  73 to 494\,Mbp/s in the recorded benchmark.
\end{enumerate}

This sequence matters more than the name of a kernel.  The final design is the
combination of an ABI proof, explicit replay ownership, exact scalar-equivalent
event semantics, and a parallel schedule.  Removing any one of those
properties reproduces a previously observed failure mode.

\subsection{Why older ``wins'' are retained but not promoted}

The archive contains faster-looking numbers which are valuable as engineering
history but invalid as final claims.  Report 76 measured a 1.982\,s resident
vector route against a 9.416\,s scalar route, yet later forensic work found
approximate lexicographic/golden-ratio hashes, missing dual-stream palindrome
semantics, and topology-dependent boundaries.  Report 90 restored exactness
but regressed to 66.273\,s; later specialisation reduced that to 13.413\,s and
eventually the report-103 9.256\,s.  Those experiments show why performance
must be attached to an audited contract, not merely to the class name
\texttt{TwoStackMinimizerAlgorithm}.

The same caution applies to the SIMD tie path.  Report 100 recorded
40,464,168 candidate batches and 46,654,429 rejected ordinary lanes, with only
1,051 raw/tie-matrix batches reaching the expensive exact path.  That
demonstrates that the rare-path prefilter works; it does not by itself prove
that the remaining ordinary path beats scalar code.

\subsection{The resulting selection policy}
\label{sec:minimizer-selection}

No single collector is silently declared ``best''.  The pipeline chooses an
algorithm only after it has chosen a compatible sketch/index scheme:

\begin{description}
  \item[\texttt{Scalar}.] The portability backend and semantic oracle.  It is
  the reference for invalid-symbol resets, equal-hash identities, duplicate
  events, position widths, and final flushes.

  \item[\texttt{ExactSimd}.] The segmented minimap-compatible implementation.
  It is selected when exact compatibility is required and its representation,
  $K/W$ shape, and continuation proof are supported.  The B8 path removes
  rescans and sends only genuine hash-identity collisions to the expensive
  tie matrix, but current measurements do not justify claiming a general
  scalar speedup.

  \item[\texttt{PaperNtHashSimd}.] The performance-qualified CPU scheme for
  packed dna4 when both sides carry the PNT1 identity.  It realises the
  eight-stream rolling idea while making BioSeq's tie rule and hash width part
  of a persistent contract.  It cannot open or query a minimap-compatible
  index by pretending that a minimizer is just a 32-bit integer.

  \item[\texttt{VulkanSegment}.] The exact minimap-compatible device route
  when Phase C admission proves the representation, tile span, buffer
  capacity, and device features. It is favored when the next stages remain
  resident. Admission may select a compatible host backend before Vulkan
  execution begins. Once VulkanSegment is selected, a device decline is an
  error rather than a silent host fallback.
\end{description}

\subsection{Limitations and open measurements}
\label{sec:minimizer-limitations}

Several limitations remain visible rather than hidden behind automatic
fallbacks.  PNT1 currently requires proved packed dna4 and a supported
position width.  ExactSimd's best-specialised continuation is the common
$K=15,W=10$, eight-position shape. Other supported shapes use its generic
exact-vector route. If ExactSimd admission fails, dispatch must select Scalar
explicitly before ExactSimd execution begins. The Phase C tile owns one serial
scalar-equivalent state,
so positions within a tile are not independently parallel; parallelism comes
from many tiles and grid-stride work distribution.  Count and emit deliberately
run the state machine twice to obtain deterministic compact output.  Finally,
the historical full-resident route remains in the source for comparison and
must not be mistaken for an exact compatibility proof.

The most useful next measurements are therefore not another isolated hash
loop. They are:
\begin{enumerate}
  \item a preregistered 2 and 4\,Gbp comparison of complete PNT1 and Phase C
        configurations.
  \item cold and warm target-index builds reported separately.
  \item adversarial ambiguity at every fragment and tile boundary.
  \item tie-heavy synthetic inputs that force the exact identity path.
  \item cross-machine throughput with the emitted seed stream compared
        byte-for-byte against the appropriate oracle.
\end{enumerate}

\section{Conclusion}

Minimizer extraction began as a familiar rolling-hash loop and became a
lesson in systems correctness.  The observable object is not merely the
minimum hash of a window.  It is an ordered stream whose identity depends on
canonicalisation, hash width, tie direction, equal-hash $K$-mer identity,
palindromes, ambiguity resets, fragment boundaries, position width, and the
final flush.  The scalar implementation made those rules explicit.  The
two-stack work showed how to remove rescans without changing them, and its
failures showed that SIMD width alone does not provide a speedup.

The final CPU solution therefore exposes two honest choices: ExactSimd retains
the minimap-compatible contract, whereas PNT1 versions a faster paper-derived
contract and binds it to the stored index.  The final GPU solution adopts
G3SA's resident-pipeline insight but reconstructs the sketch around BioSeq's
packed representations, exact reset semantics, replay ownership, and
deterministic count/scan/emit allocation.  In both cases the governing design
principle is the same: an optimisation is accepted only when the seed scheme,
storage proof, continuation state, and measured downstream result agree.
