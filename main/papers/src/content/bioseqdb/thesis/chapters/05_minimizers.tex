\section{From every base to a sparse, comparable sketch}
\label{sec:minimizers-role}

The first computational stage of the BioSeqDB mapper converts a sequence into a
much smaller stream of representative $k$-mers.  This stream is called a
\emph{minimizer sketch}. The target sketch becomes an index. The query sketch
is looked up in that index, and equal keys become the anchors consumed by
Section~\ref{sec:chaining-purpose}. Sketching is therefore more than a sampling
optimization. Its hash
function, strand convention, tie rule, invalid-symbol rule, and output encoding
jointly define the language spoken by the query and its stored target index.
Changing any component can yield an implementation whose output is
incompatible with the stored index.

This observation explains an otherwise surprising property of the final
implementation: BioSeqDB retains several minimizer backends instead of
declaring one universally best algorithm.  The exported lower-level
sketch-backend enum in
\path{main/bioseq/backend/sequences/kmers/index.cppm} contains
\texttt{Scalar}, \texttt{ExactSimd}, \texttt{PaperNtHashSimd}, and
\texttt{VulkanSegment}.  It is distinct from the higher-level runtime
\texttt{MinimizerAlgorithmType}, which also retains the
\texttt{SIMD\_MINIMAP2\_SLOW} reference selector. In this chapter,
\texttt{u8} and \texttt{u32} denote unsigned fixed-width integer types of
8 and 32 bits, respectively. Scalar and ExactSimd share the legacy
minimap-style scheme. The
initializer-level runtime default is Scalar in both
\texttt{Minimap2Params} and the corresponding PostgreSQL Grand Unified
Configuration (GUC) parameter. ExactSimd is the
production-targeted all-SIMD alternative selected explicitly as
\texttt{two\_stack\_nthash}, including by named benchmark configurations.
PaperNtHashSimd implements a separate versioned, paper-derived 32-bit ntHash
scheme. Its persisted manifest identity is the pair $(1,1)$, while
\texttt{PNT1} and \texttt{0x504E5431} name the human-readable scheme family
and the checked-kernel proof magic. VulkanSegment targets the legacy
minimap-style scheme on a device through the Phase C tiled kernel. Its current
oracle contract is exact for DNA4. For DNA5 and the tested generic
DNA5/\texttt{u8}-packing route, the scalar events must be a subset of the
device output and the number of additional events is bounded. Persisted index
metadata records the selected scheme. Dispatch is not allowed to substitute
one scheme for another merely because both outputs are called ``minimizers''.

The implementation history is useful because it exposes three recurring
lessons:

\begin{enumerate}
  \item a scalar algorithm with irregular control flow is not made efficient
        merely by replacing scalar integers with vectors.
  \item a mathematically attractive hash or tie policy is not a transparent
        replacement for a deployed index scheme.
  \item accelerator throughput matters only after fragment boundaries,
        ambiguous symbols, output order, memory admission, and host/device
        transfers have been included in the contract.
\end{enumerate}

This chapter first defines that contract.  It then reconstructs
minimap2 and SIMD-Minimizers before following the rejected and retained
BioSeqDB designs.  Code locations refer to the current checkout.  Historical
timing claims are tied to the archived report that measured them. They are not
presented as current performance.

\subsection{Formal definition}
\label{sec:minimizer-definition}

Let $S=s_0s_1\ldots s_{n-1}$ be a sequence over an alphabet $\Sigma$.  For
nucleotide sketching, valid bases are normalized to minimap2's nt4 codes
\[
  \eta(A)=0,\qquad \eta(C)=1,\qquad \eta(G)=2,\qquad \eta(T)=3,
\]
and an ambiguous base such as DNA5's $N$ maps to a sentinel.  The $k$-mer
beginning at $i$ is $K_i=S[i,i+k)$.  Its reverse complement is
$\overline{K_i}$, and its canonical orientation is determined from the two
encoded integers
\[
  F_i=\operatorname{enc}(K_i),\qquad
  R_i=\operatorname{enc}(\overline{K_i}).
\]
For the minimap-style scheme, define
\[
  C_i=\min(F_i,R_i),\qquad
  z_i=\begin{cases}0&F_i<R_i,\\1&R_i<F_i,\end{cases}
  \qquad h_i=H_{\mathrm{mm}}(C_i).
\]
When $F_i=R_i$, the strand is undefined and the candidate is a sentinel rather
than an emitted minimizer.  A candidate record is
\[
  x_i=(h_i,\;i+k-1,\;z_i),
\]
where the position denotes the final base of the $k$-mer, matching minimap2.
For every window of $w$ consecutive candidates,
\[
  W_j=(x_j,x_{j+1},\ldots,x_{j+w-1}),
\]
the basic minimizer is an argument attaining
\[
  m_j=\min_{x\in W_j} h(x).
\]
Random hashes make the same candidate the minimum of several neighboring
windows. Adjacent windows therefore usually repeat a position. A collector
emits a deduplicated event stream driven by entering minima, expiry, ties,
first-window handling, and the final flush rather than one record per window. For
ideal independent hashes the expected minimizer density is approximately
$2/(w+1)$, so $w=10$ retains roughly one candidate in every 5.5 positions.

The word ``identity'' is load-bearing.  In BioSeqDB's compact
\texttt{MinimizerRepr}, comparisons mask off position and strand and compare
only the hash field, while \texttt{does\_sketch\_match} means ``same hash but a
different identity''.  Two equal hashes at different positions are therefore
ties to be reported, not duplicate machine words to be discarded.  This is why
the final ExactSimd implementation carries both a hash vector and raw
position/strand metadata through its rare tie path.

event-history contract rather than a single value per window.

\subsection{The minimap2 scalar reference}
\label{sec:minimap2-sketch}

The bundled baseline follows the minimap2 sketching algorithm
\cite{minimap2_paper}. Its source,
\path{main/bench/tool_minimap2/minimap2/sketch.c}, makes the compatibility
contract concrete.  It maintains two rolling two-bit integers:
\[
\begin{aligned}
 F_i &= ((F_{i-1}\ll2)\mathbin{\vert}c_i)\mathbin{\&}(2^{2k}-1),\\
 R_i &= (R_{i-1}\gg2)\mathbin{\vert}((3\oplus c_i)\ll2(k-1)).
\end{aligned}
\]
The smaller orientation is mixed by Thomas Wang's reversible integer
scramble, with every arithmetic step masked to the $2k$-bit domain.  In the C
source this is \texttt{hash64}. The packed record is
\texttt{x = hash << 8 | span} and
\texttt{y = rid << 32 | lastPos << 1 | strand}.  BioSeqDB drops fields not
needed by its pipeline and instead chooses a 16-, 32-, 64-, or 128-bit
\texttt{MinimizerRepr} from the position and hash requirements.  The common
$k=15$ layout supports sequence lengths up to $2^{28}$ bases. Its zero-based
positions range from $0$ through $2^{28}-1$. The representation uses a single
64-bit word with one strand bit, 28 position bits, and 35 available hash bits.

The scalar window minimum is a circular buffer plus a saved minimum.  A new
candidate replaces the saved minimum on \emph{less than or equal}. Consequently
the entering candidate is the rightmost equal minimum.  When the saved
candidate expires, the ring is scanned from oldest to newest with a
\emph{greater than or equal} comparison, again ending on the closest
(rightmost) equal candidate.  The first full window and expiry path also emit
other equal-hash, different-identity candidates.  This chronology is more
specific than the often-quoted rule ``deduplicate minimizer positions''.
Algorithm~\ref{alg:minimap-scalar-events} makes the first-window, expiry, tie,
and final-flush branches explicit.

\begin{algorithm}[H]
\caption{Minimap-style scalar event collector, including the semantic branches}
\label{alg:minimap-scalar-events}
\small
\textbf{Input:} packed or decoded sequence \(S\), \(k\), and \(w\).

\textbf{Output:} the chronological minimizer event stream.

\begin{enumerate}
  \item Initialize the forward and reverse rolling encodings, then set
    \[
      \textit{ring}[0..w-1]\gets\infty,
      \qquad
      \textit{current}\gets\infty.
    \]
  \item For each base \(s_i\), perform the following steps.
    \begin{enumerate}
      \item Select a candidate.
        \begin{itemize}
          \item If \(s_i\) is ambiguous, reset the valid-run length and both
            rolling encodings, then set
            \(\textit{candidate}\gets\infty\).
          \item Otherwise, roll \((F,R)\) and increment the valid-run length.
            If there are at least \(k\) clean bases and \(F\ne R\), set
            \[
              \textit{candidate}\gets
              \bigl(H_{\mathrm{mm}}(\min(F,R)),i,
              \operatorname{strand}(F,R)\bigr).
            \]
            Otherwise, set \(\textit{candidate}\gets\infty\).
        \end{itemize}
      \item Overwrite the next circular-buffer slot with
        \(\textit{candidate}\).
      \item If this is the first full window, emit other identities tied with
        \(\textit{current}\).
      \item Apply the minimum-update branch.
        \begin{itemize}
          \item If
            \(\textit{candidate.hash}\le\textit{current.hash}\), emit the old
            \(\textit{current}\) when the stream is armed, then set
            \(\textit{current}\gets\textit{candidate}\).
          \item Otherwise, if the overwritten slot held
            \(\textit{current}\), emit the old \(\textit{current}\), rescan the
            ring with \(\ge\), and emit other identities tied with the
            rescanned minimum.
        \end{itemize}
    \end{enumerate}
  \item Unconditionally emit the final live \(\textit{current}\).
\end{enumerate}
\end{algorithm}

An ambiguous input character resets the clean-base counter and rolling
$k$-mer, ensuring that no emitted $k$-mer spans an $N$.  The original
minimap2 C loop skips a palindromic $k$-mer with \texttt{continue}. The
BioSeqDB scalar reference instead advances the ring with a max-valued sentinel.
The palindrome still cannot become a minimizer, but it consumes a window slot.
This was chosen so scalar and vector lanes share one chronological window
shape.  It is a disclosed structural deviation from minimap2, not an accidental
implementation detail.

\section{Eliminating data-dependent rescans}
\label{sec:two-stack-minimum}

The minimap2 ring is an excellent scalar design.  Its rescan branch is taken
only when the saved minimum expires, approximately once every $w$ candidates.
Lane-parallel execution changes that probability.  With $L$ independent
streams and a scalar rescan probability near $1/w$, the probability that at
least one lane requests the slow path in a vector step is
\[
  1-\left(1-\frac{1}{w}\right)^L.
\]
For $w=10$ and four NEON lanes this is approximately $34.4\%$, rather than
$10\%$.  Each divergent step must mask unaffected lanes or spill state to a
temporary matrix.  This is why BioSeqDB's first literal SIMD port performed
more work even though it computed four hashes at once.

\subsection{Deque, rescan, and two-stack formulations}

There are three standard ways to maintain a sliding minimum.
Table~\ref{tab:sliding-minimum-formulations} separates their state updates from
the control-flow tradeoff that determines SIMD suitability.

For a hash sequence $a_0,\ldots,a_{n-1}$, let block
$B_q=(a_{qw},\ldots,a_{qw+w-1})$.  Define
\[
  P_i=\min(a_{qw},\ldots,a_i),\qquad
  Q_i=\min(a_i,\ldots,a_{qw+w-1})
\]
for $i\in B_q$.  If a window begins at $j$ and ends at $e=j+w-1$,
\[
  \min(a_j,\ldots,a_e)=\min(Q_j,P_e).
\]
Both input and control flow are therefore regular.  A tie-aware combine can
carry $(h,p_\ell,p_r)$ instead of a single hash, retaining the leftmost and
rightmost positions that attain $h$.

\subsection{Rolling ntHash}
\label{sec:rolling-nthash}

SIMD-Minimizers combines the data-independent minimum with the ntHash rolling
family \cite{nthash_2016,groot_koerkamp_simd_minimizers_2025}. Associate each
nucleotide with a pseudo-random 32-bit constant $f(b)$, let
\(\operatorname{comp}(b)\) denote its Watson--Crick complement, and choose a
rotation $r$ (BioSeqDB freezes $r=7$). For a $k$-mer beginning at $i$,
\[
\begin{aligned}
 H^F_i &= \bigoplus_{j=0}^{k-1}
       \operatorname{rotl}\!\left(f(s_{i+j}),r(k-1-j)\right),\\
 H^R_i &= \bigoplus_{j=0}^{k-1}
       \operatorname{rotl}\!\left(f(\operatorname{comp}(s_{i+j})),rj\right).
\end{aligned}
\]
After the $O(k)$ initialization, the forward state advances in constant time:
\[
 H^F_{i+1}=
 \operatorname{rotl}(H^F_i,r)
 \oplus \operatorname{rotl}(f(s_i),rk)
 \oplus f(s_{i+k}).
\]
The reverse-complement recurrence rotates in the opposite direction and
replaces the outgoing and incoming complement contributions.  In the
BioSeqDB PNT1 scheme the canonical key is the wrapping 32-bit sum
\[
  h_i=H^F_i+H^R_i \pmod {2^{32}},
\]
while the stored strand records whether $H^R_i<H^F_i$.  This differs
fundamentally from applying minimap2's integer scramble to
$\min(F_i,R_i)$. The two schemes cannot share a persisted index.

endpoint. It then suppresses identical adjacent identities. This produces a
reverse-complement-symmetric endpoint superset without importing the upstream
window-orientation counter. Table~\ref{tab:upstream-pnt-delta} makes the

Algorithm~\ref{alg:paper-nthash} summarizes BioSeqDB's tie-aware, eight-stream
PNT1 collector.

\begin{algorithm}[H]
\caption{BioSeqDB PNT1 data-independent ntHash minimizers}
\label{alg:paper-nthash}
\small
\textbf{Input:} DNA4 sequence \(S\), compile-time \(k\), and \(w\).

\textbf{Output:} reconciled minimizer events from the eight logical streams.

\begin{enumerate}
  \item Split \(S\) into eight logical streams with \(k+w-2\) bases of
    context.
  \item Initialize vector forward and reverse ntHash states and a
    \(w\)-slot ring.
  \item For each lock-step packed-symbol vector, perform the following steps.
    \begin{enumerate}
      \item Decode ranks directly from packed sequence words.
      \item Update forward and reverse ntHash with rotations, exclusive OR
        (XOR), and table lookup.
      \item Set
        \[
          h\gets H^F+H^R\pmod{2^{32}},
        \]
        and record the per-\(k\)-mer strand from \(H^R<H^F\).
      \item Update the block prefix minimum with
        \((h,p_\ell,p_r,z_\ell,z_r)\).
      \item If the \(w\)-slot block wrapped, rebuild all suffix minima in a
        fixed reverse loop.
      \item Combine one prefix and one suffix minimum.
      \item Emit the left endpoint if its identity differs from the last
        output. Emit the right endpoint too when the minimum is tied.
    \end{enumerate}
  \item Reconcile the first and last identities of adjacent logical streams.
\end{enumerate}
\end{algorithm}

\subsection{Eight logical streams on variable-width SIMD}

The original Rust implementation fixes eight 32-bit lanes.  It splits the
sequence into eight contiguous chunks and overlaps neighboring chunks by
$k+w-2$ bases so that each owned window has enough left and right context.
Window minima are produced lane-wise, transposed back to sequence order, and
deduplicated at chunk joins.

BioSeqDB preserves the eight-\emph{logical}-stream decomposition but implements
it with Highway. On AArch64 NEON, four physical 32-bit lanes require two
independent vector registers per step. On an eight-lane target one register is
enough. The execution proof requires
\[
  \textit{registers-per-step}\times\textit{physical-lanes}=8.
\]
Input is not converted to the Rust library's packed type.  The kernel consumes
the existing \texttt{compact\_sequence\_range} through the project's packed
iterator, fixes the final-stream tail mask explicitly, computes segment-local
positions, and lets the segmented caller add a checked global base offset.
The first event of logical lanes 1--7 is withheld until the preceding lane's
last identity is known, so cross-stream deduplication uses only bounded
metadata. The resulting event identities are deterministic, but the current
collector does not promise a global append order across the eight lock-step
streams. Persisted MPF output establishes its canonical order later by sorting
the pair $(\textit{hash},\textit{encoded position})$ and removing identical
records.

\section{BioSeqDB's CPU implementation history}
\label{sec:minimizer-cpu-history}

\subsection{Why the literal SIMD port failed}

The earliest vector collector kept minimap2's rescan state independently in
each lane.  Two bugs arrived before performance could even be judged.  First,
the strand bit was not carried through every buffer update, so approximately
half of reverse-oriented matches disappeared. DOC0107 records values of 0.958
and 0.972 on its short and medium fixtures after strand masks, strand buffers,
and duplicate-emission propagation were corrected. The archived record does
not define the metric and denominator precisely enough to promote these values
to an accuracy claim. Second, each lane's data-dependent rescan forced
horizontal tests and masked buffer updates.  The SIMD unit was busy, but the
instruction stream did more bookkeeping than the scalar loop.

Micro-optimizations could not repair that algorithmic shape.  DOC0108 replaced
general complement work with DNA4 XOR, hoisted palindrome masks, and fused
lane predicates.  Its measured collector moved only from approximately
40.8 to 39.6 ms while the scalar reference remained near
12.7--12.9 ms.  Later direct packed access removed an eager conversion, but
also exposed a least-significant-bit-first (LSB-first) ordering error in the
first helper. Correcting that
error restored identity, not speed.

The long-sequence report DOC0113 gives the honest intermediate result.  For
the 903 kbp case, whole-pipeline minimap2, scalar BioSeqDB, and SIMD BioSeqDB
were 185.6, 158.4, and 170.7 ms. For 5 Mbp they were 1062.1, 994.5, and
1047.2 ms.  The vector route was still 5--8\% slower than BioSeqDB scalar.
The report attributes the gap to horizontal \texttt{AllFalse} checks, spills,
output-buffer traffic, and runtime shifts.  These archived figures should not
be compared numerically with the current XXL benchmark: they use different
inputs, binaries, and whole-pipeline configurations.

\subsection{The V4--V15 branch: useful ideas and misleading names}

DOC0114 and DOC0118 then moved the collector to a prefix/suffix minimum
inspired by SIMD-Minimizers.  This branch produced several techniques that
remain useful:

\begin{itemize}
  \item direct traversal of packed sequence storage.
  \item static $w=10,k=15$ specialization.
  \item two independent vector streams on NEON to expose instruction-level
        parallelism.
  \item explicit transposition and stable compression of lane outputs.
  \item forced inlining of the packed-iterator callback.
  \item preallocation and bounded boundary deduplication.
\end{itemize}

It also produced an important naming trap.  The public benchmark name
\texttt{two\_stack}\allowbreak\texttt{\_nthash} was used while some versions ordered canonical
two-bit words lexicographically, mixed them with a golden-ratio multiplier, or
deferred the minimap scramble until emission.  A non-order-preserving scramble
cannot be deferred while retaining the same minimizer set. Later forensic work
in
\path{main/DOCS/CURRENT/REPORTS/0370_BIOSEQ_SLOWNESS_DEBUGGING_EVENT_LOG.md}
found that the exceptionally fast report-76 row was the older
resident eight-stream prefix/suffix collector: it disabled palindrome
detection on its long dual-stream route and had stream-topology-dependent
boundaries.  It is therefore historical approximate evidence, not a
byte-for-byte baseline for today's ExactSimd continuation.

The optimization sequence was nevertheless informative.  The V8 ordering
change roughly halved the expensive inner work, V11 interleaved two independent
streams, and V12 removed a surviving out-of-line lambda. The recorded inner
phase fell to approximately 9.23 ms on that report's case.  V13's largest win
was actually downstream: replacing a sort in \texttt{mm\_est\_err} with prefix
counts reduced that region from 7.88 to 0.85 ms.  A destructive
\texttt{prefix\_kmer} experiment collapsed the effective hash to 14 bits and
caused a 36-fold pipeline regression, so it was reverted.  V14 implemented a
true ntHash table lookup, adding about 2 ms of sketch time while saving only
0.38 ms in seed lookup on its measurement.  At that checkpoint it was
correctly rejected as a net loss.  The later PNT1 backend succeeds because it
changes the entire hash/window scheme coherently and records that new scheme,
not because a table lookup was dropped into a legacy index.

\section{Current BioSeqDB minimizer backends}

\subsection{ExactSimd: segmented minimap-compatible continuation}
\label{sec:exact-simd}

The exact segmented kernel was written to answer a different question from
the paper backend: can vector instructions reproduce BioSeqDB's legacy
minimap-style event stream over a lazy, fragmented packed sequence without
falling back to scalar sketching?  Its public checked driver is in
\path{main/bioseq/backend/sequences/kmers/two_stacks_minimizers.cppm}.
Despite historical function names containing \texttt{nthash}, this path
canonicalizes the two-bit forward/reverse $k$-mer and applies the minimap
integer scramble.  It is not ntHash.

\subsubsection{Bounded state across arbitrary fragments}

For a static $W,K$, \texttt{TwoStackContinuationState} retains:
\begin{itemize}
  \item at most $K+W-1$ normalized nt4 codes;
  \item candidate hashes, raw records, and ordinals;
  \item less than one pending SIMD block;
  \item the current minimum;
  \item counters;
  \item execution proof.
\end{itemize}
A fragment boundary neither resets nor replays the biological algorithm.  The
next call completes the pending chronological block and continues from the
saved carries.  The memory bound depends on $K$, $W$, and the vector width,
not on sequence length or fragment count.

boundary from an ambiguity event that resets biological state.

For DNA5, packed symbols do not form a continuous bit stream across storage
words because three bits per symbol leave unused high bits.  The generic
decoder therefore prepares source-word addresses and shifts per active lane,
then performs rank extraction, rank-to-nt4 normalization, and ambiguity
classification as Highway vector operations.  Scalar orchestration is
reported separately and never hashes, canonicalizes, selects a minimum, or
emits a record.  Unsupported alphabets, storage shapes, position ranges, or
scalar Highway targets return a checked status and are converted into
\texttt{ExactSimdRuntimeError}. The selected Exact backend does not silently
call the scalar collector.

An ambiguous base is also not an implicit fragment finalization.  The kernel
flushes any pending valid candidate block, clears the $K$-mer context and
clean-run length, then advances one max-valued candidate through the ring.
It does not clear the $W$-candidate tail, reset its chronological ordinal, or
emit the current minimum.  End-of-input alone performs minimap2's
unconditional final-current flush.

\subsubsection{The common $k=15,w=10$ B8 specialization}

The generic chronological kernel reconstructs overlapping canonical $k$-mers
and scans $W$ candidates for each vector group. The same uniquely named
slowness event log showed why this exact approach regressed. On a 500 Mbp
target an older two-lane version executed
about 250 million vector batches but 9.75 billion scalar-orchestration steps,
behaving like $O(N(K+W)/2)$ rather than a rolling hash plus amortized minimum.

The retained specialization processes eight candidates at a time.  It takes
the $K+B-1=22$ needed DNA4 codes and applies SIMD within a register (SWAR) to
pack them into 44 bits.  Fixed shifts extract eight overlapping 30-bit K15
words.  The implementation forms forward and reverse orientations in two
independent \texttt{u32} streams, applies the exact minimap scramble, and
carries 64-bit position/strand metadata separately.  The $W=10$ reduction
still scans ten chronological slots, deliberately using \texttt{<=} so each
lane ends on the rightmost equal minimum.  This is more work than the paper's
prefix/suffix combine, but it preserves the deployed event chronology.

Most windows have no equal-hash, different-identity event.  The common path
therefore performs a stable \texttt{CompressStore} directly.  A hash-only
prefilter guards the expensive raw-aware tie matrix.  In report 100 the target
prefilter rejected 46,654,429 possible-tie lanes. Only 1,051 batches reached
the raw verifier and tie matrix.  When that rare route is needed, the kernel
constructs event 0 (the old minimum) plus up to $W$ tied identities per lane,
transposes the event matrix in registers, and stable-compresses rows in
chronological order.

Algorithm~\ref{alg:exact-b8} isolates the specialized exact block and its rare
tie-recovery path.

\begin{algorithm}[H]
\caption{ExactSimd B8 block, simplified}
\label{alg:exact-b8}
\small
\textbf{Input:} \(K=15\), \(W=10\), eight pending DNA4 positions, and the
continuation state.

\textbf{Output:} chronological events and the updated continuation state.

\begin{enumerate}
  \item Load \(22=K+8-1\) context symbols and SWAR-pack them.
  \item Extract eight overlapping forward K15 integers by fixed shifts, then
    construct eight reverse-complement integers.
  \item Set \(c\gets\min(f,r)\), mark palindromes as max sentinels, and set
    \(h\gets H_{\mathrm{mm}}(c)\).
  \item Pack \((h,p,z)\) in raw metadata.
  \item Concatenate the saved \(W-1\) candidate tail and eight new candidates.
  \item For each of the \(W\) chronological slots, update eight lane minima
    using \(\le\), so the rightmost equal candidate wins.
  \item Derive the entering-minimum, expiry, first-window, and final event
    masks.
  \item Select the emission path.
    \begin{itemize}
      \item If there is no actual equal-hash, different-identity event,
        stable-compress ordinary events directly.
      \item Otherwise, build and transpose the exact tie-event matrix, then
        stable-compress all chronological events.
    \end{itemize}
  \item Save the final \(W-1\) candidates and current minima as continuation.
\end{enumerate}
\end{algorithm}

The source still contains a separately attested full-resident
\texttt{vector\_stream} route for borrowed contiguous DNA4/\texttt{u32} data
and the historical XXL shape.  It is intentionally distinguished in
\texttt{TwoStackExecutionProof} from the B8 continuation.  Because later
forensics found that historical route did not satisfy all exact palindrome and
boundary semantics, it must be treated as an approximate resident control, not
as proof that the segmented Exact scheme has reached report-76 speed. The
audited continuation is therefore the production-targeted ExactSimd route when
\texttt{two\_stack\_nthash} is selected explicitly. Ordinary initialization
remains Scalar. PNT1 keeps a separate name because it is a different seed
contract, not because it repairs the resident control's compatibility.

\subsection{PNT1: a versioned paper-derived alternative}
\label{sec:pnt1}

The SIMD-Minimizers result was ultimately useful, but not as a drop-in faster
implementation of the minimap2 sketch.  Its canonical hash selects an extreme
minimum using the orientation of the complete $(K+W-1)$-base window. Minimap2
instead hashes every canonical $K$-mer and applies the rightmost-minimum event
rules defined in Section~\ref{sec:minimizer-definition}.  Those definitions
can choose different seeds even
when both implementations are internally correct.  BioSeqDB therefore gives
the paper-derived implementation a distinct, versioned identity:
\texttt{PackedPaperNthash}. The persisted manifest stores scheme identifier
$1$ and scheme version $1$. The checked kernel independently reports proof
magic \texttt{0x504E5431}, which reads as \texttt{PNT1}. This decision converts
a tempting hidden substitution into an explicit index contract without
confusing execution evidence with the wire identifier.

The public PNT1 route currently accepts only $K=15$, $W=10$, and packed DNA4.
It requires a contiguous borrowed or admission-materialized \texttt{u32}
interval, a minimizer representation with all 32 hash bits, a representable
position range, and a Highway target with four or eight physical \texttt{u32}
lanes. The kernel keeps eight logical streams and maps them onto one or two
physical vector registers. Forward and reverse-complement rolling hashes use seven-bit
rotations. Each stream retains both extreme equal minima. The upstream
canonical algorithm chooses one extreme from complete-window orientation.
BioSeqDB instead emits the left extreme and then the right extreme when their
identities differ. This tie contract is deterministic at the level of event
identity, but global collector append order across logical streams remains
unspecified.

PNT1 does not carry rolling or minimum continuation state across physical
fragments. A bounded query request borrows one contiguous interval or
materializes that interval under memory admission before invoking the checked
kernel. The persisted MPF producer handles fragmented storage at a different
level. For each physical core $[c_\ell,c_h)$ it rescans a bounded interval with
a halo of $W+K-2$ bases, accepts only events whose global positions lie in the
half-open core, sorts them by $(\textit{hash},\textit{encoded position})$, and
removes identical records. Disjoint core ownership prevents a legitimate
event from surviving in two cores. If any storage, vector-shape, position, or
scheme proof is missing, the selected backend fails closed. It does not
reinterpret DNA5 bytes and it does not fall through to a differently named
scheme.

Algorithm~\ref{alg:pnt1} shows how bounded replay, half-open ownership, and
canonical sorting turn fragmented input into one PNT1 MPF generation.

\begin{algorithm}[H]
\caption{PNT1 MPF replay over fragmented packed storage}
\label{alg:pnt1}
\small
\textbf{Input:} manifest scheme \((1,1)\), a packed DNA4 sequence, and
physical cores.

\textbf{Output:} a published MPF generation with manifest scheme \((1,1)\).

\begin{enumerate}
  \item Require \(K=15\), \(W=10\), full-\texttt{u32} hash storage, representable
    positions, and a four- or eight-lane vector shape.
  \item For each core \([c_\ell,c_h)\) in logical order, perform the following
    steps.
    \begin{enumerate}
      \item Set
        \[
          r\gets W+K-2,\qquad
          s_\ell\gets\max(0,c_\ell-r),\qquad
          s_h\gets\min(|S|,c_h+r).
        \]
      \item Plan contiguous \texttt{u32} access for \([s_\ell,s_h)\).
      \item Borrow the interval or materialize it under memory admission.
      \item Run the checked eight-stream PNT1 kernel on the bounded interval.
      \item Require an accepted proof with magic
        \texttt{0x504E5431}, zero fallback, and zero fail-closed counters.
      \item Translate segment-local positions to global positions.
      \item Retain only events with positions in \([c_\ell,c_h)\).
      \item Sort by \((\textit{hash},\textit{encoded position})\), then remove
        identical canonical events.
    \end{enumerate}
  \item Publish the MPF generation with manifest scheme \((1,1)\).
\end{enumerate}
\end{algorithm}

\subsection{Vulkan Phase C: exact DNA4 extraction and conservative superset extraction}
\label{sec:vulkan-minimizers}

The GPU implementation follows a different optimization path.  Its purpose is
not to reproduce the eight-stream PNT1 decomposition, but to execute the
minimap-compatible scalar-derived state machine over device-resident packed
sequences. Exact event parity is currently verified for DNA4. The DNA5 and
tested generic DNA5/\texttt{u8}-packing routes instead use a conservative
contract: every scalar event must be present and the number of additional
events is bounded. It belongs to Phase C of the GPU pipeline: metadata, packed
bases, sketch events, seed hits, and downstream work can remain on the device. This
avoids making a fast kernel irrelevant by repeatedly materializing sequences
or events on the host.

\subsubsection{Relationship to G3SA}

G3SA demonstrated that seed generation and alignment preparation can be
structured as a resident CUDA pipeline \cite{g3sa_paper}. Its
minimap2-derived sketch kernel
assigns one block to a read, uses a 32-thread warp and 128-base tiles, and has
thread zero compact the events.  The supplied reference kernel reconstructs a
$K$-mer from characters for each position, so its core work is
$O(K)$ per candidate rather than an $O(1)$ rolling update.  It also assumes a
small DNA-plus-\texttt{N} alphabet and treats an invalid character as a local
\texttt{continue}. That is not equivalent to resetting every window that
spans the symbol.

BioSeqDB adopts the useful system-level lesson of keeping data and successive
stages resident, but not G3SA's sketch semantics.  The implementation uses
Vulkan compute shaders, packed generic sequence descriptors, rolling
forward/reverse encodings, and an exact minimap scramble. Its compact output
route uses count/scan/emit. Its persisted sorted-pair route uses atomic append
followed by stable device sorting. Table~\ref{tab:g3sa-comparison} makes the
distinction concrete.

\subsubsection{Tiles are storage units, not independent sequences}

An output event depends on the preceding $K-1$ bases and on a minimizer window
of $W$ candidate positions.  Starting every tile with empty state would
therefore invent resets and lose boundary events.  Phase C solves this with
replay and ownership. For a tile whose owned trigger interval is $[b,e)$, the
shader begins earlier by a conservative overlap currently bounded by $K+W+1$,
replays scalar-derived state, and emits only events whose trigger position lies
in $[b,e)$. The half-open trigger filter is intended to prevent neighboring
tiles from owning the same event. Exact cross-tile event parity is verified for
DNA4. For DNA5 and the tested DNA5/\texttt{u8}-packing route, the oracle
instead requires every scalar triple to be present and limits additional triples to
\[
  2\,T\,(K+W+1),
\]
where $T$ is the tile count. This bound is a conservative acceptance contract,
not a claim that every additional event has been localized to a particular
boundary.

The planner targets approximately 256 logical bases and rounds storage
according to the sequence representation. A DNA5 packing shape therefore
commonly produces 252-base logical tiles.  The Phase C application binary
interface (ABI) bounds the supported span
and currently admits up to 384 bases including replay.  Those numbers are
planner parameters, not algorithmic constants: correctness follows from
replay coverage and half-open ownership, not from the nominal tile size.

and deterministic count/scan/emit path.

The output cardinality is data dependent. Ties and expiry events mean that a
window does not imply exactly one stored record. The compact target/query route
executes the state machine twice. The first pass counts events per descriptor.
An exclusive prefix scan assigns offsets matching those counts. The second pass
replays and writes only to the assigned interval. This provides deterministic
event order and makes allocation failure visible before emission.

Phase C also exposes an independent sorted-pair API used by MPF persistence.
That route allocates a proved worst-case capacity, performs one kernel pass
with a global atomic append counter, and then stable-sorts pairs on the device
first by encoded position and then by hash, which makes hash the primary key.
The atomic append order is not the persisted order. The subsequent sort
establishes that order. Algorithm~\ref{alg:phase-c-minimizers} therefore models
the compact two-pass route rather than every Phase C caller.

\begin{algorithm}[H]
\caption{Phase C compact count/scan/emit minimizer extraction}
\label{alg:phase-c-minimizers}
\small
\textbf{Input:} packed sequence descriptors, \((K,W)\), and half-open tile
ownership.

\textbf{Output:} the counted and emitted compact minimizer array.

\begin{enumerate}
  \item For each pass in
    \(\{\textsc{count},\textsc{emit}\}\), perform the following steps.
    \begin{enumerate}
      \item For every tile in a grid-stride loop, perform the following steps.
        \begin{enumerate}
          \item Start at the tile's replay origin with empty scalar-derived
            state.
          \item For each logical symbol through the owned interval, decode its
            rank from the representation-specific packed layout and set
            \(\textit{candidate}\gets\infty\). If the symbol is invalid, reset
            the rolling encodings and valid-run length. Otherwise, roll the
            forward and reverse encodings. If the clean run has length at
            least \(K\) and is not palindromic, canonicalize, scramble, and
            assign \(\textit{candidate}\). Then overwrite the next ring slot
            with \(\textit{candidate}\) and apply the first-window,
            rightmost-tie, and expiry rules. For every event triggered at this
            position, count it or write it at the scanned tile offset only if
            its trigger lies in the half-open owned interval.
          \item If this tile owns sequence end and the final minimum is live,
            count or emit that minimum.
        \end{enumerate}
      \vspace{0.25\baselineskip}
      \item After all tiles have completed, if the pass is \textsc{count},
        exclusive-scan tile counts and allocate the counted output.
    \end{enumerate}
\end{enumerate}
\end{algorithm}

\subsubsection{Why the first GPU version was not the final one}

The development record is instructive because each intermediate version was
plausible in isolation:

\begin{enumerate}
  \item Phase B used a mixture of host metadata and specialized GPU work.  A
  4096-base DNA5 case produced 859 events where the scalar oracle produced
  795.  Changing padding and inserting \texttt{N} symbols did not remove the
  excess, pointing to ownership/state rather than input corruption
  (DOC0348).
  \item The Phase C ABI made packed storage and descriptor metadata available
  everywhere, then DOC0351--DOC0352 retired the Phase-B route and forced one
  semantics-bearing path for all supported representations.
  \item The first Phase C shader still reconstructed too much state and left
  work concentrated in too few lanes.  DOC0353 replaced that structure with
  rolling hash updates and an all-lanes, grid-stride tile schedule. The
  measured DNA4 configuration remained bit-exact while sketch throughput
  increased from about 73 to 494\,Mbp/s in the recorded benchmark.
\end{enumerate}

This sequence matters more than the name of a kernel. The final design combines
an ABI proof, explicit replay ownership, a parallel schedule, and a
representation-specific oracle contract. That contract is exact for DNA4 and
is a bounded conservative superset for DNA5 and the tested DNA5/\texttt{u8}-packing
route. Removing any one of those properties reproduces a previously observed
failure mode.

identifies the exact minimap-compatible backend. PaperNtHashSimd remains a
separately selectable scheme with its own manifest identity.

\subsection{Why older ``wins'' are retained but not promoted}

The archive contains faster-looking numbers which are valuable as engineering
history but invalid as final claims.  Report 76 measured a 1.982\,s resident
vector route against a 9.416\,s scalar route, yet later forensic work found
approximate lexicographic/golden-ratio hashes, missing dual-stream palindrome
semantics, and topology-dependent boundaries.  Report 90 restored exactness
but regressed to 66.273\,s. Later specialization reduced that to 13.413\,s and
eventually the historical report-103 value of 9.256\,s. Those experiments show
why performance must be attached to an audited contract, not merely to the class name
\texttt{TwoStackMinimizer}\allowbreak\texttt{Algorithm}.

The same caution applies to the SIMD tie path. Report 100 recorded
40,464,168 candidate batches and 46,654,429 rejected ordinary lanes, with only
1,051 raw/tie-matrix batches reaching the expensive exact path. That
demonstrates that the rare-path prefilter works. It does not by itself prove
that the remaining ordinary path beats scalar code.

\subsection{The resulting selection policy}
\label{sec:minimizer-selection}

Scalar is the current initializer-level runtime default and semantic oracle.
ExactSimd is the production-targeted CPU collector selected explicitly as
\texttt{two\_stack\_nthash}. The other backends remain explicit because
portability, a different seed contract, or device residency can require a
different route. The pipeline chooses an algorithm only after it has chosen a
compatible sketch/index scheme:

\begin{description}
  \item[\texttt{Scalar}.] The initializer-level default, portability backend,
  and semantic oracle. It is the reference for invalid-symbol resets,
  equal-hash identities, duplicate events, position widths, and final flushes.

  \item[\texttt{ExactSimd}.] This production-targeted CPU implementation is
  selected explicitly. It realizes the minimap-compatible scheme and uses the K15/W10
  B8 specialization when that shape is proved and otherwise uses the supported
  generic exact-vector route. The selected backend accepts only a proof with
  zero scalar biological counters. A declined proof is an error, not an
  implicit scalar call.

  \item[\texttt{PaperNtHashSimd}.] A versioned unequal-work
  alternative/prototype for packed DNA4 when both sides carry manifest scheme
  $(1,1)$. It realizes the eight-stream rolling idea while making BioSeqDB's
  tie rule and hash width part of a persistent contract. It cannot open or
  query a minimap-compatible index by treating every minimizer as an
  interchangeable 32-bit integer.

  \item[\texttt{VulkanSegment}.] The device implementation of the legacy
  minimap-style hash and reset contract when Phase C admission proves the
  representation, tile span, buffer capacity, and device features. Current
  DNA4 checks require exact parity. DNA5 and the tested DNA5/\texttt{u8}-packing route
  require all scalar events with a bounded number of additional events. It is
  favored when the next stages remain resident. The planner may select a
  compatible host backend before Vulkan execution begins. Once VulkanSegment
  is selected, a device decline is an error rather than a silent host fallback.
\end{description}

\subsection{Limitations and open measurements}
\label{sec:minimizer-limitations}

Several limitations remain visible rather than hidden behind automatic
fallbacks. PNT1 currently requires:
\begin{itemize}
  \setlength{\itemsep}{0pt}
  \setlength{\parsep}{0pt}
  \item $K=15$,
  \item $W=10$,
  \item proved contiguous or admission-materialized \texttt{u32} DNA4,
  \item a full-\texttt{u32} hash field,
  \item representable positions, and
  \item a four- or eight-lane Highway shape.
\end{itemize}
ExactSimd's best specialized continuation is the common $K=15,W=10$,
eight-position shape. Other supported shapes use its generic exact-vector
route. If ExactSimd admission fails, dispatch may select Scalar explicitly
before ExactSimd execution begins. Once ExactSimd is selected, failure is an
error. The Phase C tile owns one serial scalar-derived replay state, so
positions within a tile are not independently parallel. Parallelism comes
from many tiles and grid-stride work distribution.
Its semantic acceptance remains representation-specific: exact for DNA4 and a
bounded conservative superset for DNA5 and the tested DNA5/\texttt{u8}-packing route.
The compact route deliberately runs count and emit to obtain deterministic
output. The sorted-pair persistence route instead uses atomic append followed
by a stable device sort. Finally, the historical full-resident route remains
in the source for comparison and must not be mistaken for an exact
compatibility proof.

The most useful next measurements are therefore not another isolated hash
loop. They are:
\begin{enumerate}
  \item a preregistered equal-work comparison of complete ExactSimd, PNT1, and
        Phase C configurations at 2 and 4\,Gbp.
  \item cold and warm target-index builds reported separately.
  \item adversarial ambiguity at every fragment and tile boundary.
  \item tie-heavy synthetic inputs that force the exact identity path.
  \item cross-machine throughput with the emitted seed stream compared
        byte-for-byte against the appropriate oracle.
\end{enumerate}

\section{Conclusion}

Minimizer extraction began as a familiar rolling-hash loop and became a lesson
in systems correctness. The observable object is not merely the minimum hash
of a window. Its identity depends on:
\begin{itemize}
  \setlength{\itemsep}{0pt}
  \setlength{\parsep}{0pt}
  \item canonicalization,
  \item hash width,
  \item tie direction,
  \item equal-hash $K$-mer identity,
  \item palindromes,
  \item ambiguity resets,
  \item fragment ownership,
  \item position width, and
  \item the final flush.
\end{itemize}
ExactSimd and the compact Phase C route expose a chronological event stream.
The PNT1 collector instead leaves cross-stream append order unspecified, while
MPF persistence establishes canonical order through sort/unique. The scalar
implementation makes the minimap-compatible rules explicit. The two-stack
work shows how to remove rescans without changing them, and its failures show
that SIMD width alone does not provide a speedup.

The current initializer-level CPU default is Scalar. ExactSimd retains the
minimap-compatible contract as a production-targeted, explicitly selected
all-SIMD route and fails closed when its execution proof is not accepted. PNT1
is a separately versioned paper-derived alternative/prototype bound to manifest
scheme $(1,1)$. Historical report 103 demonstrates a valid configuration, but
newer evidence does not support presenting it as a wholesale replacement for
ExactSimd. The GPU solution adopts G3SA's resident-pipeline insight
\cite{g3sa_paper} and reconstructs the sketch around BioSeqDB's packed
representations, reset semantics, and replay ownership. Its current oracle
contract is exact for DNA4 and a bounded conservative superset for DNA5 and
the tested DNA5/\texttt{u8}-packing route. Its compact route uses deterministic
count/scan/emit allocation. Its sorted-pair persistence route uses atomic
append followed by a stable device sort. In every route, an optimization is
accepted only when the seed scheme, storage proof, boundary ownership,
execution evidence, and measured downstream result agree.
