\section{Remote biological databases as relations}
\label{sec:external-relations}

Public sequence databases are indispensable, but they do not expose one common
data model. NCBI separates taxonomy, gene, assembly, and sequence retrieval
among several services~\cite{ncbi_datasets_v2_api}. UCSC organizes sequence by
genome assembly and genomic interval~\cite{ucsc_rest_api}. UniProt centers its
interface on protein accessions and protein-specific
annotations~\cite{uniprot_programmatic_access}, while the EBI Search API
provides discovery over several domains~\cite{ebi_search_rest_api}. Their
identifiers, paging rules, response schemas, rate
limits and failure modes differ.  A conventional analysis script therefore
contains a substantial amount of code that is not part of the biological
question: URL construction, authentication, JSON decoding, retries, FASTA
parsing, identifier translation and conversion into local records.

BioSeqDB treats this integration problem as a database access problem.  It
exposes six logical relations in the \texttt{bioseq\_external} schema:
\texttt{taxonomy}, \texttt{catalog}, \texttt{record\_genes},
\texttt{record\_locations}, \texttt{sequences} and
\texttt{sequence\_chunks}.  A query against one of these relations does not read
a local heap. PostgreSQL constructs a \texttt{BioseqExternalScan}. The scan
translates supported SQL predicates into a provider-neutral query, contacts the
selected service, and returns ordinary typed tuples.  Consequently, a remote
record can participate in a join, projection or residual PostgreSQL filter
without first being downloaded by an external script.

This design is not equivalent to wrapping an HTTP call in a scalar SQL
function.  A scalar function has no natural place to represent a stream of
records, cannot conveniently expose provider capabilities to planning, and
encourages one remote request per evaluated row.  It also makes cancellation
and memory bounds accidental properties of the function implementation.  The
external table instead gives the remote operation a PostgreSQL Custom Scan
lifecycle~\cite{postgresql17_custom_scan}:
\texttt{BeginCustomScan}, repeated \texttt{ExecCustomScan},
\texttt{ReScanCustomScan}, \texttt{EndCustomScan}, and
\texttt{ExplainCustomScan}.  The scan can defer network access until the first
tuple is requested, retain state between calls, apply backpressure, and cancel
its producer during rescan or query teardown.

The six relation declarations are not handwritten SQL.  The annotated C++ row
types in
\path{main/bioseq/backend/pg/external/sql_catalog.cppm}, namespace
\texttt{bioseq::external::sql\_rows}, are consumed by the SQL generation
machinery described in the following source-generation chapter. Every type
specifies \texttt{access\_method = "bioseq\_external"}.  The sequence-bearing
columns use the real \texttt{bioseq.seq} PostgreSQL type, while provenance and
provider attributes are typed as \texttt{jsonb}.  The schema revokes public
access by default, which is important because a SELECT can cause outbound
network traffic.

\subsection{What each relation means}

The schema separates discovery from retrieval. \texttt{taxonomy} normalizes
taxon identifiers, names, ranks and lineage.  \texttt{catalog} is the
cross-provider record inventory: it carries the original identifier,
normalized accession, molecule kind, title, sequence length, assembly
information and a \texttt{retrievable} flag.  \texttt{record\_genes} and
\texttt{record\_locations} explode nested provider metadata into relational
rows with stable per-record indices.  \texttt{sequences} returns a complete
record as one \texttt{bioseq.seq} datum.  \texttt{sequence\_chunks} returns an
ordered sequence of datums with \texttt{chunk\_index},
\texttt{base\_offset} and \texttt{end\_of\_record}.

The distinction between the last two relations is a resource contract, not
only a presentational choice.  A complete \texttt{sequences} row must
materialize one record or assembly segment. In contrast,
\texttt{sequence\_chunks} can keep its working set independent of a
multi-megabase record's length.  The current NCBI chunk size is
\(1\,048\,572\) bases. It is four symbols below one Mi-symbol. Because the
payload owns one-byte raw letters at this boundary, it is also four bytes below
one MiB. The size is divisible
by the internal block geometry used by the implementation. A one-chunk
look-ahead keeps the final non-empty chunk pending, so a record whose length is
an exact multiple of the chunk size receives no spurious empty row and exactly
one row has \texttt{end\_of\_record=true}.

The first implementation therefore solved the \emph{control-plane} problem:
turn a supported SQL predicate into a provider request, validate and execute
that request, parse the response, and normalize it into rows. It did not yet
solve the \emph{data-plane} problem for large nucleotide assets. A generated
client returned a heap-owned \texttt{std::string} response body, and the
provider adapter parsed it after the complete response arrived.  This is
appropriate for bounded metadata pages, but makes peak memory proportional to
the size of a genome.

The final architecture keeps generated clients for metadata and adds a
separate byte-streaming route for large assets.  The two routes converge only
after provider-specific parsing, at the
\texttt{owning\_provider\_message} model.  Figure~\ref{fig:external-dataflow}
shows the implemented paths and, crucially, where whole-response ownership
still exists.

This split is more than a transport optimization. Metadata requests and asset
transfers have different correctness criteria.  Metadata is usually a bounded
JSON document whose value lies in its structure.  A sequence asset may be
hundreds of megabytes, and its useful representation is a stream of symbols.
The control plane needs typed parameter validation and provider-specific JSON
normalization. The data plane needs byte caps, incremental decoding, archive
safety, record boundaries, backpressure and an emission rule that determines
whether a failed request may be retried.

\section{Generated clients and handwritten adapters}
\label{sec:external-generated-boundary}

Provider integration is divided into three layers.  The descriptor layer
states what an upstream API accepts.  The generated client layer implements
safe, typed HTTP mechanics for the supported OpenAPI subset.  The handwritten
adapter layer assigns BioSeqDB meaning to the response.

Source descriptors are the C++ modules
\path{main/bioseq/external/ncbi.cppm},
\path{main/bioseq/external/ucsc.cppm},
\path{main/bioseq/external/ebi.cppm},
\path{main/bioseq/external/uniprot.cppm} and
\path{main/bioseq/external/swiss_model.cppm}.  They contain the
\texttt{bioseq::api\_client} annotation and embedded OpenAPI input.  They should
not be confused with the runtime provider adapters under
\path{main/bioseq/external/providers/}.

The current generator is implemented under
\path{main/codegen/external/}. The annotation parser uses cppast/libclang on a
normalized shadow source. The OpenAPI parser accepts GET operations, typed
path/query/header parameters, HTTPS server metadata and a restricted API-key
security model.  It rejects unsupported or ambiguous constructs at build time.
The client renderer emits a C++ module named
\texttt{bioseq.external.api.<provider>}.  The artifact handler writes
\texttt{client/index.cppm}, a generated integration test, a CMake fragment,
\texttt{manifest.tsv} and \texttt{provenance.txt}.  Artifacts live in the build
tree and are updated with \texttt{write\_if\_different}. Generated source is not
treated as a manually maintained copy in the repository.

The generated public API is intentionally small.  A request consists of an
operation identifier and a span of typed \texttt{parameter\_value} objects.
The client validates required parameters, multiplicity and location before
percent-encoding the path and query.  It then executes \texttt{get},
\texttt{get\_with\_accept}, or \texttt{get\_batch}.  Batch transport work is
distributed through \texttt{GlobalPool}. Completed responses are materialized
serially.  A response owns its body as \texttt{std::string}, with a default
64~MiB limit.  This heap ownership is deliberate: an earlier attempt to place a
large transient HTTP body into the small-block result arena could exceed the
arena's allocation geometry.  Provider adapters parse the body once into
bounded owning messages, after which the transient string can be released.

The following simplified C++26 model captures the actual provider contract:

\begin{verbatim}
template<class S>
concept external_api_session_implementation =
  requires(S& s, provider_message_sink_ref out, std::stop_token stop) {
    { s.run(out, stop) }
      -> std::same_as<std::expected<provider_statistics, external_error>>;
    { s.request_stop() } noexcept -> std::same_as<void>;
  };

template<class P>
concept external_api_provider_implementation =
  requires(normalized_external_query const& q,
           typename P::plan_type const& plan,
           external_slot_budget const& budget) {
    typename P::plan_type;
    typename P::session_type;
    requires external_api_session_implementation<typename P::session_type>;
    { P::plan(q, provider_capability_snapshot{}, budget) };
    { plan.execution_fingerprint() };
    { P::open(/* memory, pool, runtime, credentials, */ plan, budget) };
  };
\end{verbatim}

The complete definitions are in
\path{main/bioseq/external/provider/concepts.cppm}.  There is no virtual
provider base class.  The template
\texttt{external\_api\_provider<Providers...>} in
\path{main/bioseq/external/provider/pack.cppm} checks type and stable-ID
uniqueness at compile time.  At run time it performs one dispatch from the
provider string to the concrete adapter type.  Dispatch does not occur for each
row or chunk.  Adding a provider therefore means implementing one type that
satisfies the concept and adding it to the configured pack. The hot row path
does not gain a virtual call.

Each adapter lowers a provider-neutral query into an immutable plan, opens a
session, calls the generated client, and converts provider JSON into the
canonical model.  NCBI reads \texttt{NCBI\_API\_KEY} for generated metadata
calls and passes it as an owning generated \texttt{credentials} value.  UCSC
maps BioSeqDB's zero-based half-open interval directly to its sequence
endpoint. UniProt normalizes protein catalog and gene fields but rejects
sequence targets because the PostgreSQL sequence materializer is currently
nucleotide-oriented.  EBI is discovery-only.  The generator thus owns
syntactic HTTP correctness. The adapter owns biological and relational
semantics.

\section{Planning and executing a remote table scan}
\label{sec:external-custom-scan}

\subsection{A table access method with no local tuples}

The \texttt{bioseq\_external} table access method is defined in
\path{main/bioseq/backend/pg/external/relation.cppm}.  It does not create a
physical storage fork and does not contact a provider.  Its ordinary physical
scan callbacks cannot produce tuples. The custom scan is the legal read path.
The path builder in
\path{main/bioseq/backend/pg/external/scan.cppm},
\texttt{bioseq\_\allowbreak{}external\_\allowbreak{}try\_\allowbreak{}add\_%
\allowbreak{}paths}, recognizes the access method,
removes core-generated paths and inserts one non-parallel
\texttt{CustomPath}.  Its current cost is a fixed \(1.0\), and its row estimate
falls back to \(1000\).  This differs from BioSeqDB's alignment-function custom
scan: there is no competing scalar remote-table implementation whose high cost
must be beaten.  A physical sequential scan would be semantically invalid, so
the external custom path is exclusive.

\texttt{bioseq\_external\_plan\_custom\_path} preserves the real relation OID
in \texttt{scanrelid}.  PostgreSQL therefore provisions a scan slot with the
declared table descriptor and applies the plan's projection and residual
filters normally.  \texttt{BioseqExternalScanState} places
\texttt{CustomScanState} at offset zero, as required by PostgreSQL's node ABI.
The C++ runtime object is separately allocated and registered with the query
memory context's reset callback.  This prevents a C++ container from being
silently abandoned when PostgreSQL exits through its error long jump.

Network execution is postponed from \texttt{BeginCustomScan} until the first
call that requests a tuple.  Consequently, ordinary \texttt{EXPLAIN} without
\texttt{ANALYZE} reports the selected provider and entity without issuing a
remote request.  \texttt{EXPLAIN ANALYZE} exercises the provider, because the
executor must consume rows.

\subsection{Predicate lowering and provider selection}

PostgreSQL calls WHERE-clause expressions qualifications, or \emph{quals}.
Every relation has a \texttt{provider} column. An equality predicate selects
one provider, while \texttt{provider = ANY(array)} selects several.  Without an
explicit predicate, the current defaults are NCBI for taxonomy, locations and
sequence retrieval, UniProt for gene rows, and UCSC for the catalog.  Column
names are mapped back to the canonical \texttt{external\_field} enumeration.
The scan currently pushes equality predicates over text, integer and boolean
constants, plus \texttt{= ANY(...)}.  Unsupported expression shapes and types
remain PostgreSQL residual filters.

The canonical query model in
\path{main/bioseq/external/provider/query.cppm} is broader than this first
lowering implementation.  It represents targets, typed scalar values, flat
post-order predicate nodes and pushdown quality.  The executor currently sets a
provider request limit of \(1000\). An SQL \texttt{LIMIT} is still enforced by
PostgreSQL rather than being derived into that value.  Likewise, inequalities
such as \texttt{start0 < end0} remain local even though the provider-neutral
model can represent richer operators.

An array predicate is expanded into equality-only subqueries because the
current adapters consume equality accessions. The Cartesian expansion emits at
most 64 combinations. When the bound is reached, the scan warns that further
combinations were not queried. PostgreSQL residual filtering cannot recover
rows that were never requested, so the returned union is incomplete in this
case.

Rows from successful provider/query pairs are unioned and de-duplicated by
stable keys. If another pair fails, its first error is surfaced only when the
complete union contains no rows. A query can therefore return a partial union
without reporting the failed pair as an SQL error. This behavior is an explicit
current limitation rather than ordinary fault tolerance.

Algorithm~\ref{alg:external-scan} summarizes first-fetch initialization and
subsequent row production.

\begin{algorithm}[htbp]
  \caption{Current external-scan execution, simplified from
  \texttt{bioseq\_external\_scan\_next}.}
  \label{alg:external-scan}
  \begin{description}
    \item[Input:] relation entity, SQL quals, and provider set.
  \end{description}
  \begin{enumerate}
    \item Lower supported quals to a normalized external query.
    \item On the first tuple request:
      \begin{enumerate}
        \item If the entity is a sequence or sequence chunk, the provider is
        NCBI, and an accession exists, start the NCBI producer and a bounded
        message channel.
        \item Otherwise:
          \begin{enumerate}
            \item expand \texttt{ANY} predicates and run provider plans to
            completion.
            \item collect and de-duplicate owning messages.
          \end{enumerate}
      \end{enumerate}
    \item If the query is streaming:
      \begin{enumerate}
        \item Repeat until an item or terminal state is observed:
          \begin{enumerate}
            \item timed-pop one charged message lease.
            \item on timeout, call \texttt{CHECK\_FOR\_INTERRUPTS}.
          \end{enumerate}
        \item Pack one payload into the PostgreSQL slot and release its charge.
      \end{enumerate}
    \item Otherwise, translate the next collected message or sub-row into the
    scan slot.
    \item Let \texttt{ExecScan} apply residual quals and projection.
  \end{enumerate}
\end{algorithm}

\section{The NCBI streaming data plane}
\label{sec:ncbi-streaming}

The streaming path is selected by \texttt{is\_streaming\_query} in
\path{main/bioseq/backend/pg/external/scan.cppm}: the target must be
\texttt{sequences} or \texttt{sequence\_chunks}, the provider set must contain
only NCBI, and an equality-constrained accession must be recoverable from the
normalized query. Other provider/target combinations use the synchronous
\texttt{run\_external\_query} bridge in
\path{main/bioseq/external/providers/run.cppm}, which collects messages in a
vector.

\subsection{Pulling bytes without buffering the body}

For an ordinary nucleotide accession, the producer constructs an NCBI
E-utilities FASTA request. Before opening a socket,
\texttt{validate\_candidate} in
\path{main/bioseq/external/transport/locator.cppm} checks the HTTPS scheme,
allowed host suffix, URL length, absence of user information and the currently
implemented address-scope rules.  It resolves the host and requires every
returned address to pass the classifier.  The numeric addresses are attached
to an otherwise non-constructible
\texttt{validated\_transfer\_request}, and libcurl receives them through
\texttt{CURLOPT\_RESOLVE}~\cite{libcurl_url_api}. Redirects, proxies and
automatic decoding are disabled.  These controls prevent redirect-based
allowlist bypasses and pin the approved DNS result for the lifetime of the
transfer.

The address classifier is an explicit deny list rather than a complete
global-unicast test.  It rejects the implemented unspecified, loopback,
private or unique-local, link-local, CGNAT and multicast ranges.  It does not
yet exhaust every special-use range or comprehensively handle IPv4-mapped IPv6
addresses.  The implementation therefore narrows the usual DNS-rebinding and
private-service exposure, but the stronger claim that every non-public endpoint
is excluded remains a security-hardening objective.

\texttt{remote\_byte\_source} in
\path{main/bioseq/external/transport/remote_source.cppm} satisfies the shared
\texttt{bioseq::io::io\_source} concept.  It cooperatively drives a libcurl
multi handle on the producer thread.  The write callback appends into a carry
buffer whose default capacity is 256~KiB.  If the next callback would exceed
that capacity, it returns \texttt{CURL\_WRITEFUNC\_PAUSE}. Draining
\texttt{read\_into} resumes the transfer. Hence BioSeqDB's carry buffer retains
at most the configured capacity rather than a complete FASTA response. This is
not a bound on libcurl or TLS internal allocations. The source
also applies a 15-second connect timeout, a low-speed threshold of one byte per
second over 120 seconds, an optional total timeout, TLS peer and host
verification, a wire-byte cap, and a one-second maximum poll interval for
cooperative stop checks.

The incremental \texttt{fasta\_chunk\_emitter} in
\path{main/bioseq/external/io/sequence_stream.cppm} discards headers and
whitespace while retaining the first header token as the record identifier.
For \texttt{sequence\_chunks}, it flushes fixed-size base chunks and holds one
chunk until it knows whether it is final.  For \texttt{sequences}, it
intentionally accumulates a complete record before publication. This is
necessary to return one SQL datum and means that the whole-record relation is
not record-size-independent.  Multi-record archive members reset
\texttt{base\_offset} for each record while keeping a global
\texttt{chunk\_index}, so the pair \((\textit{queried accession},
\textit{chunk index})\) remains unique.

NCBI assembly accessions beginning with \texttt{GCF\_} or \texttt{GCA\_} take a
different route through
\path{main/bioseq/external/io/datasets_stream.cppm}. The Datasets API returns a
ZIP package~\cite{ncbi_datasets_v2_api}. The current implementation downloads
the compressed ZIP into a bounded in-memory vector with a 64~MiB default wire
cap, then makes two libarchive passes.  The first pass reads bounded control
members.  During the second pass, the extractor materializes one selected
decoded member in a \texttt{std::string}, checks its MD5, and only then feeds
the verified bytes to the shared FASTA emitter.  The configured path enforces a
512~MiB total decoded cap and an expansion-ratio cap, while its per-member
decoded cap is zero.  A single selected member may therefore approach the total
cap.  For the whole-record \texttt{sequences} target, an additional
record-sized payload may coexist with the buffered member.

This path is verify-before-emit and bounded by explicit caps, but neither the
package transport nor selected-member extraction is incremental.  A seekable
temporary spool for packages above the in-memory cap, a bounded member spool
that preserves verify-before-emit, and the dehydrated \texttt{fetch.txt}
re-fetch strategy remain explicitly deferred.

\subsection{Backpressure and PostgreSQL cancellation}

The producer must never call PostgreSQL APIs. \texttt{start\_streaming} creates
a \texttt{std::jthread}. That thread runs either
\texttt{run\_ncbi\_sequence\_stream} or
\texttt{run\_ncbi\_datasets\_stream} and communicates only by owning messages.
This current implementation differs from the project guideline, which
normally prefers TBB work submission, and from the fused provider tasks
proposed by the dated common-provider specification.
The current channel is bounded to 8~MiB and four items.  Its implementation in
\path{main/bioseq/external/provider/bounded_channel.cppm} charges both bytes and
items.  A popped item remains charged until its move-only lease is released,
preventing the consumer from nominally emptying the queue while retaining
unaccounted payload memory.  One oversized item may enter an otherwise empty
channel. The admission equation accounts for that staging item and thereby
avoids producer deadlock.

The PostgreSQL thread calls \texttt{pop\_for} with a 100~ms timeout.  A timeout
releases the channel mutex before \texttt{CHECK\_FOR\_INTERRUPTS} is invoked.
This ordering is essential: PostgreSQL cancellation may long-jump, and jumping
while holding a C++ mutex would permanently block the producer.  Teardown first
cancels the channel, waking a producer blocked in \texttt{push}, and then lets
the \texttt{jthread} join before destroying the channel. Rescan follows the
same sequence of cancellation, join, and state reset.

Retries obey an \emph{emission barrier}.  The direct FASTA path retries
transport errors, HTTP 408, 429 and selected 5xx statuses with bounded
exponential backoff and jitter, but only while the emitter has published zero
rows.  Once a chunk is visible to the executor, restarting the transfer could
duplicate rows.  A subsequent failure is terminal.  The archive path similarly
retries the download before extraction, but never restarts after extraction has
begun to emit.  The current backoff waits use
\texttt{std::this\_thread::sleep\_for} rather than a stop-token-aware wait.
Cancellation requested during a retry delay is observed only after the current
interval completes, which can be about 1.8 seconds including jitter on the
direct path and 1.6 seconds on the archive path.

\section{From remote letters to a compact PostgreSQL sequence}
\label{sec:external-packing}

Provider messages remain PostgreSQL-independent.  The current
\texttt{owning\_sequence\_payload} in
\path{main/bioseq/external/provider/model.cppm} owns raw base letters in a
\texttt{std::string}, together with accession, interval, chunk and audit
metadata.  It is not itself a \texttt{compact\_sequence\_range}.  This is a
deliberate boundary: network parsing can be built and tested without PostgreSQL
headers or memory contexts.

Packing occurs on the PostgreSQL thread in
\texttt{set\_seq} within
\path{main/bioseq/backend/pg/external/row_writer.cppm}.  The function calls the
active SIMD target's
\texttt{stdc\_\allowbreak{}convert\_\allowbreak{}from\_\allowbreak{}cstr<%
\allowbreak{}bioseq::\allowbreak{}pg\_\allowbreak{}types::\allowbreak{}seq,...>}
with
\texttt{pg\_alloc}. It normalizes nucleotide input according to the configured
PostgreSQL sequence alphabet and creates a varlena \texttt{bioseq.seq} datum in
the current memory context.  A chunk lease is released only after this datum
has been copied into the virtual tuple slot.  Downstream operators therefore
receive exactly the same packed type as locally loaded sequences. Alignment
code does not need a provider-specific representation.

This conversion currently involves one raw-letter payload and one packed
PostgreSQL allocation per emitted row. The common-provider specification dated
11 July 2026 proposed a richer
\texttt{sink\_control} and packing-parser path that could write directly into a
reserved sink.  That refactor is not yet part of the proven implementation.
The existing boundary trades one bounded conversion for a much simpler
ownership rule: worker code owns ordinary C++ values, while only the backend
thread owns PostgreSQL datums.

\section{Authentication, transport policy and errors}
\label{sec:external-policy}

\subsection{Authentication and configuration}

Generated clients support an OpenAPI API-key scheme in either a header or query
parameter.  Credentials are currently owning \texttt{std::string} values.  The
NCBI adapter reads \texttt{NCBI\_API\_KEY} when it creates the generated
metadata client. The direct nucleotide FASTA path is unauthenticated and does
not place the key in its URL.  The broader DOC0372 design proposed
non-owning/redacted credential views and richer per-provider policy profiles.
The concepts expose \texttt{request\_policy\_profiles()} and
\texttt{locator\_policy\_profiles()}, but all four current provider adapters
return empty spans.  Locator enforcement for the NCBI stream is instead
provided directly by \texttt{ncbi\_eutils\_policy}.

The metadata transport in
\path{main/bioseq/external/https.cppm} uses blocking Oat++ I/O over a custom
OpenSSL stream.  It requires TLS~1.2 or newer, system trust roots, SNI,
certificate-chain verification and hostname verification.  Socket reads and
writes have 30-second timeouts.  A per-client connection pool is configured
for up to 32 connections, a 30-second idle lifetime and a 10-second acquisition
timeout.  Request targets, header names and header values are validated before
transmission, and decoded response bodies are bounded.

The streaming transport has the stricter locator firewall described above.
Its current DNS resolution uses the system \texttt{getaddrinfo} call before
pinning the result.  The proposed cancellable c-ares/OpenSSL endpoint connector
for the Oat++ control plane remains deferred. Cancellation is therefore
cooperative rather than immediate.  A blocking \texttt{getaddrinfo} call can
defer stop observation according to the system resolver, and a retry backoff
can defer it until the current interval finishes.  Once libcurl is actively
driving the transfer, its poll and timeout settings bound the regular stop
checks.  There is no immediate cross-thread socket close.

\subsection{Rate limits and failure representation}

The provider core defines a structured, bounded
\texttt{external\_error} in
\path{main/bioseq/external/provider/errors.cppm}.  Its kinds distinguish invalid
queries, unsupported capabilities, transport and timeout failures, HTTP
errors, rate limits, incomplete responses, size limits, parsing, integrity,
cancellation and provider-contract violations.  Diagnostics, response
excerpts, operation names and identifiers have compile-time length caps, so an
untrusted upstream body cannot become an unbounded error object.

\texttt{gcra\_request\_policy} in
\path{main/bioseq/external/provider/rate_limit.cppm} implements a process-local
generic cell-rate algorithm (GCRA) with burst tolerance, in-flight slots,
\texttt{Retry-After} penalties and a credential/origin/tier bucket key. The
DOC0374 session-5 receipt dated 13 July 2026 reports tests for atomic rollback
and concurrent slot accounting. The policy is not yet wired into
the provider request path, and it is not cluster-wide across PostgreSQL
backends.  The current NCBI stream instead uses local per-request retry loops.
Consequently, several simultaneous backends can still exceed a shared public
quota. The same report records implementation of a shared-memory GCRA variant
and a multi-backend proof as future work.

The intended PostgreSQL mapping assigns \texttt{0A000} to unsupported
capabilities, \texttt{08000} to connection-class failures, \texttt{22000} to
data/parse/integrity failures, \texttt{54000} to size limits and
\texttt{57014} to cancellation.  The current custom scan implements only the
most important distinction: unsupported or unimplemented operations become
\texttt{0A000}. Other provider errors are presently collapsed to
\texttt{38000} (external routine exception).  C++ exceptions are caught at
every PostgreSQL callback boundary, and message text is copied into
PostgreSQL-managed storage before \texttt{ereport(ERROR)} performs a long jump.
The richer mapping documented in
\path{main/bioseq/backend/pg/external/errors.cppm} is therefore a design
contract that has not yet been fully connected to the scan.

\section{Final architecture and remaining work}
\label{sec:external-final}

The retained solution is a two-plane system. Generated Oat++ clients provide
a reproducible, validated control plane for small JSON responses.
Concept-checked provider adapters translate these responses into one canonical query
and message model.  A storage-free PostgreSQL access method forces reads
through a custom scan.  For the large NCBI nucleotide path, a validated
libcurl source, incremental FASTA emitter and byte/item bounded channel form a
separate data plane.  The PostgreSQL thread alone packs letters into
\texttt{bioseq.seq} and interacts with executor slots.

Relative to the generated-client-only baseline, direct NCBI
\texttt{sequence\_chunks} retrieval removes the complete response body from
the record-length-dependent working set. Sections~\ref{sec:ncbi-streaming},
\ref{sec:external-packing}, and \ref{sec:external-policy} delimit the
exceptions. Metadata, non-NCBI retrieval, Datasets archive verification, and
whole-record \texttt{sequences} still retain bounded but package-sized or
record-sized values. The remaining security, admission, scheduling,
rate-policy, and SQLSTATE work defines the scope of the result without
changing this measured distinction.

Within that scope, remote biological databases appear as typed PostgreSQL
relations. Provider-specific HTTP details remain outside SQL. Nucleotide
chunks enter the same compact sequence type as local data. The direct NCBI
FASTA path has explicit backpressure and measured memory bounds.
