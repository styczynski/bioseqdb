\section{From local seed hits to candidate mappings}
\label{sec:chaining-purpose}

Minimizers identify short agreements between a query and a reference, but a
set of minimizer hits is not yet an alignment. Repetitive sequence can produce
many incompatible hits. A plausible mapping is usually represented by a
sparser subset that advances in both coordinate systems and stays near one
diagonal. Chaining selects this subset before base-level alignment.

BioSeqDB supports scalar dynamic programming, range minimum query (RMQ)
chaining, two single instruction, multiple data (SIMD) policies, and a Vulkan
graphics processing unit (GPU) path. These choices share an anchor model, but
do not all use the same edge score or stopping rule. The
scalar algorithm defines the main forward-pass semantics. Exact SIMD preserves
that contract. Bounded SIMD and GPU execution use stated approximations. RMQ
changes both candidate selection and part of the pair score.

\section{Anchor geometry and ordering}
\label{sec:chaining-geometry}

A seed hit is represented by an anchor
\[
  a_i=(r_i,q_i,\sigma_i,\ell_i,g_i,\phi_i),
\]
where \(r_i\) and \(q_i\) are inclusive seed-end coordinates on the reference
and query, \(\sigma_i\) is the strand, \(\ell_i\) is the query span, \(g_i\)
identifies a query segment, and \(\phi_i\) stores additional ordering flags.
Reference and query positions are stored as 64-bit values. The scalar and SIMD
pair scorers nevertheless require local coordinate differences to fit signed
32-bit arithmetic. Full-width storage therefore permits large absolute
coordinates, but it does not remove the bound on a single predecessor gap.

Figure~\ref{fig:chaining-dotplot} shows the geometric interpretation. Valid
predecessors lie below and to the left of the current anchor. A chain can move
between nearby diagonals to represent an insertion or deletion, but large
diagonal changes receive a penalty or fall outside the chaining bandwidth.

The diagonal coordinate \(r_i-q_i\) is constant for anchors from an exact,
gap-free segment. An increasing diagonal coordinate indicates that reference
advance has exceeded query advance, as expected across a deletion relative to
the query. A decreasing value indicates the converse. Chaining does not decide
the base-level gap placement. It tests whether the displacement is plausible,
charges the corresponding edge cost, and passes the interval between selected
anchors to extension. This separation lets sparse seed geometry restrict the
expensive alignment problem without treating each seed as an independent
mapping.

The dynamic program requires a deterministic topological order. Anchors are
sorted first by strand and reference coordinate, then by query metadata and
coordinate. Two packed comparison keys express the established order:
\begin{equation}
\begin{split}
 K_r(a_i) &=
   (\sigma_i \ll 63)\mathbin{\vert}
   \bigl(r_i\mathbin{\&}(2^{63}-1)\bigr),\\
 K_q(a_i) &=
   (g_i\ll48)\mathbin{\vert}(\phi_i\ll40)
   \mathbin{\vert}(\ell_i\ll32)
   \mathbin{\vert}(q_i\bmod 2^{32}).
\end{split}
\label{eq:chaining-order}
\end{equation}
Comparison is lexicographic in \(K_r\), \(K_q\), and the full \(q_i\). The
final comparison resolves equal packed low words. The reference ordering
reserves its high bit for strand, so canonical reference positions must be
below \(2^{63}\). The query projection is a compatibility order rather than a
globally increasing full-width order once query coordinates exceed \(2^{32}\).
Ordinary per-query mapping remains well below this boundary.

The first and last anchor endpoints are converted to half-open mapping
coordinates after chaining. On the forward strand,
\[
 q_{\mathrm{start}}=q_{\mathrm{first}}+1-\ell_{\mathrm{first}},
 \qquad
 q_{\mathrm{end}}=q_{\mathrm{last}}+1.
\]
For a reverse-strand query of length \(L\), the normalized interval is mapped
back to \([L-q_{\mathrm{end}},L-q_{\mathrm{start}})\).

\section{Scalar chaining recurrence}
\label{sec:chaining-scalar}

The scalar algorithm follows the single-segment, non-complementary-DNA branch
of minimap2 chaining \cite{minimap2_paper}. For a current anchor \(i\) and an
earlier anchor \(j\), define
\[
 d_r(i,j)=r_i-r_j,
 \qquad
 d_q(i,j)=q_i-q_j,
 \qquad
 \delta(i,j)=|d_r(i,j)-d_q(i,j)|,
\]
and
\[
 h(i,j)=\min\{d_r(i,j),d_q(i,j)\}.
\]
A candidate is admissible when both differences are positive, both anchors
have the same strand, the coordinate differences fall inside their active
windows, and \(\delta(i,j)\le B\), where \(B\) is the chaining bandwidth.

The reward for linking \(j\) to \(i\) is
\begin{equation}
\begin{aligned}
\alpha(i,j)
&=\min\{\ell_j,h(i,j)\}\\
&\quad-
\begin{cases}
0,&\delta(i,j)=0\ \land\ h(i,j)\le \ell_j,\\[1mm]
\left\lfloor
 \lambda_g\delta(i,j)+\lambda_s h(i,j)
 +\frac{1}{2}\operatorname{fastlog}_2(\delta(i,j)+1)
\right\rfloor,&\text{otherwise.}
\end{cases}
\end{aligned}
\label{eq:chaining-edge-score}
\end{equation}
The first term rewards newly covered query sequence. The remaining terms
penalize diagonal drift and long skips. The default coefficients are derived
from minimizer length \(k\):

\[
 \lambda_g=0.01k\,s_g,
 \qquad
 \lambda_s=0.01k\,s_s,
 \qquad
 s_g=0.8,
 \qquad
 s_s=0.
\]

The best score ending at anchor \(i\) and its predecessor are
\begin{equation}
\begin{split}
 f_i &=
   \max\left(
     \ell_i,
     \max_{j\in W_i}\{f_j+\alpha(i,j)\}
   \right),\\
 p_i &=
   \arg\max_{j\in W_i}\{f_j+\alpha(i,j)\}.
\end{split}
\label{eq:chaining-dp}
\end{equation}
If no predecessor improves the seed span, the chain starts at \(i\) and
\(p_i=-1\). Sorting makes the recurrence a sparse longest-path calculation in
a directed acyclic graph.

Candidate search is bounded in three ways. Reference and query windows are
raised to at least the bandwidth, so their effective limit is
\(M=\max(\text{max-gap},B)\). At most the newest \(I\) anchors in the active
window are examined, with a default \(I=5000\). The ordered scan can also stop
after the visited-generation skip counter exceeds its limit, which is 25 by
default. These bounds make dense repetitive regions tractable, but they make
control order part of the algorithm.

The standard reference-gap limit is 5000 bases and the standard bandwidth is
500 bases. Increasing the gap limit expands the active predecessor set.
Increasing the bandwidth admits larger insertion and deletion candidates.
Changing the iteration or skip limit changes only how much of that admissible
set is inspected. These parameters are related, but none can replace the
others without changing the selected graph edges.

The three bounds serve different purposes. The reference window permits an
ordered expiry pointer because anchors are sorted by reference position. The
query window and diagonal bandwidth are pairwise tests because query
coordinates need not increase monotonically across all active anchors. The
iteration limit restricts the number of newest candidates considered after
geometric expiry. The skip rule can end this restricted scan even earlier
when recent predecessor paths repeatedly indicate that older candidates are
unlikely to improve the score.

Equation~\ref{eq:chaining-edge-score} also distinguishes seed overlap from a
true gap. When two anchors lie on one diagonal and their displacement does not
exceed the predecessor span, the new contribution is only the non-overlapping
coverage and no gap penalty is charged. For a diagonal change or a larger
displacement, the linear diagonal term is supplemented by a logarithmic
correction. The optional skip term depends on the smaller coordinate advance.
An edge contribution may be negative. It can still be selected when the
predecessor's accumulated score makes the total exceed the current best.

\begin{algorithm}[tbp]
\caption{Scalar chaining with bounded predecessor search}
\label{alg:scalar-chaining}
\small
\textbf{Input:} canonically sorted anchors and chaining parameters

\textbf{Output:} endpoint scores \(f\) and predecessor indices \(p\)

\begin{enumerate}
  \item For each anchor \(i\), expire anchors outside the strand and reference
    window, then set \(f_i\gets\ell_i\), \(p_i\gets-1\), and \(c\gets0\).
  \item Visit at most \(I\) active candidates \(j\) from newest to oldest.
    Ignore candidates that fail the geometric tests.
  \item For an admissible candidate, set \(v\gets f_j+\alpha(i,j)\).
    \begin{enumerate}
      \item If \(v>f_i\), set \(f_i\gets v\), \(p_i\gets j\), and
        \(c\gets\max(0,c-1)\).
      \item Otherwise, increment \(c\) when \(j\) carries the current
        generation mark. Stop when \(c\) exceeds the skip limit.
      \item If the scan continues and \(p_j\ge0\), mark \(p_j\) for the
        current generation.
    \end{enumerate}
  \item If the strongest completed endpoint was outside the scanned suffix,
    evaluate it once and accept it only on a strict improvement.
\end{enumerate}
\end{algorithm}

Strict improvement means that the newest candidate wins a score tie. The
visited-generation rule is not a count of arbitrary non-improving anchors. It
increments only for marked candidates, marks \(p_j\) rather than \(j\), and
decrements after a later improvement. Reordering candidates or reducing a
batch before replaying these events can change the stopping point. The final
step in Algorithm~\ref{alg:scalar-chaining} is the global-best rescue. It
preserves a strong older endpoint that early stopping would otherwise omit,
but it does not make the search exhaustive.

\section{Endpoint selection and backtracking}
\label{sec:chaining-backtracking}

The forward pass computes a possible chain endpoint at every anchor.
Backtracking ranks endpoints by \((f_i,i)\) in descending order, then follows
predecessors until the path ends or reaches an anchor already claimed by a
stronger path. A path is retained only if it meets the minimum chain score and
minimum anchor count, whose defaults are 40 and 3.

When a new walk joins a claimed suffix, its attributed score is reduced by the
score at the merge endpoint. This prevents a weak prefix from inheriting the
complete score of a stronger path. Claimed anchors also make endpoint order
observable. Path discovery may proceed in parallel, but commits must respect
the endpoint ranking when paths overlap.

\begin{algorithm}[tbp]
\caption{Ranked chain recovery}
\label{alg:chain-backtracking}
\small
\textbf{Input:} scores \(f\), predecessors \(p\), and chain thresholds

\textbf{Output:} compacted chains in descending endpoint order

\begin{enumerate}
  \item Rank all endpoint indices by descending \((f_i,i)\).
  \item For each unclaimed endpoint in that order, follow \(p\) and collect
    anchors until the walk terminates or reaches a claimed anchor.
  \item If the walk reaches a claimed suffix, subtract the score at the merge
    endpoint from the candidate prefix score.
  \item Mark the traversed anchors. Retain the path only when its adjusted
    score and anchor count meet their thresholds.
  \item Reverse each retained predecessor walk into forward coordinate order
    and append it to the compact chain array.
\end{enumerate}
\end{algorithm}

Rejected walks remain claimed. This detail prevents later, weaker endpoints
from traversing the same prefix and changes which alternatives survive. The
forward peak-score vector is not used to reproduce every upstream drop rule.
The resulting contract is therefore a ranked recovery of BioSeqDB predecessor
paths, not the complete minimap2 chain-compaction procedure.

Recovered paths are compacted into chain records that contain the score,
anchor count, and offset into the ordered anchor array. The mapping stage then
classifies the highest-scoring region as primary. For a later region, let \(o\)
be query overlap with existing primaries, \(u\) be uncovered query length, and
\(m_{\min}\), \(m_{\max}\) be the smaller and larger region spans. The region
is secondary when
\[
 \frac{o}{m_{\min}}-\frac{u}{m_{\max}}>\text{mask-level}
 \quad\land\quad
 u\le\text{mask-length}.
\]
A secondary region is retained when its score is sufficiently close to its
parent:
\[
 s_{\mathrm{secondary}}\ge \rho s_{\mathrm{parent}}
 \quad\lor\quad
 s_{\mathrm{secondary}}+\Delta_{\min}\ge s_{\mathrm{parent}}.
\]
The default ratio is \(\rho=0.8\). A global secondary limit and
parent-coordinate duplicate removal follow this comparison. Primary regions
are retained.
This classification occurs after chaining, yet a change in endpoint or
backtracking order can still change which region becomes primary.

\section{Range minimum query chaining}
\label{sec:chaining-rmq}

The scalar method can evaluate \(O(nI)\) pairs for \(n\) anchors and a maximum
of \(I\) predecessors per anchor. RMQ chaining reduces candidate lookup to
\(O(\log n)\) operations by isolating the part of the gap cost that is linear
in predecessor coordinates. Each active predecessor receives the priority
\begin{equation}
 \pi_j=-\left[f_j+\frac{\lambda_g}{2}(r_j+q_j)\right].
\label{eq:rmq-priority}
\end{equation}
An augmented balanced tree is keyed by \((q_j,j)\). Every node caches the
minimum priority in its subtree. A query interval can therefore combine the
nodes on its boundary with cached values from fully covered subtrees.

For each reference-coordinate group, RMQ chaining performs four operations:

\begin{enumerate}
  \item Remove anchors whose reference positions are outside the active
    window.
  \item Query the tree over the permitted query-coordinate interval and obtain
    the index with minimum cached priority.
  \item Re-evaluate the proposed edge with the RMQ pair score, then compare it
    with starting a new chain.
  \item Insert the newly scored group and update subtree minima during tree
    rebalancing.
\end{enumerate}

The delayed insertion preserves the strict positive reference difference.
Including the anchor index in the tree key gives deterministic behavior when
query coordinates are equal. Expiry and insertion each cost
\(O(\log n)\). A covered-subtree query also costs \(O(\log n)\), while the
stored tree and its augmentation require \(O(n)\) space in the worst case.

A capacity limit bounds the active tree in highly repetitive input. The tree
result is only a predecessor proposal. The RMQ pair scorer assigns the edge
value, and starting a new chain remains an alternative.

The current RMQ path is an algorithmic variant rather than a faster execution
of Equation~\ref{eq:chaining-dp}. Its simplified penalty condition tests the
query distance against predecessor span, while the scalar condition uses the
minimum of reference and query distance. Its primary range query can admit an
equal-query predecessor and does not independently reject every candidate
outside the diagonal bandwidth. An optional second tree is inactive in the
standard configuration. RMQ is therefore useful for dense anchor sets, but it
does not provide scalar-equivalent endpoint selection.

\section{SIMD chaining on the CPU}
\label{sec:chaining-simd}

For one target anchor, pair-score arithmetic over several predecessors is
independent. BioSeqDB stores reference positions, query positions, and spans in
structure-of-arrays buffers and evaluates these pairs with portable SIMD.
Coordinate subtraction uses low 32-bit words, so the full differences must
satisfy
\[
 0<d_r(i,j)\le\operatorname{INT32\_MAX},
 \qquad
 0<d_q(i,j)\le\operatorname{INT32\_MAX}.
\]
The reference window supports the first bound. The query bound must also hold
for the input. Admissibility masks suppress invalid lanes, and explicit masks
protect the final partial vector.

\subsection{Exact ordered decisions}

The exact policy vectorizes score production and preserves scalar decision
order. A batch that cannot improve the current best can process its generation
marks together. If any lane can improve, candidates are replayed from newest
to oldest. This replay preserves strict ties, skip-counter decrements, marked
predecessors, and early termination. The global-best rescue is found with a
vector scan and then applied through the scalar eligibility rule.

This division is necessary because the arithmetic is lane-independent while
the stopping state is ordered. Exact SIMD therefore means equality with the
BioSeqDB scalar score and predecessor contract, not that every decision is a
vector reduction.

For each vector batch, the exact policy first computes coordinate masks,
coverage rewards, penalties, and candidate scores. A comparison mask identifies
lanes that can exceed the current best. If this mask is empty, only the marked
lane count can affect the ordered state. If the mask is nonempty, scalar replay
consumes the batch in descending predecessor order and can stop before reaching
its oldest lane. This two-level procedure avoids scalar pair arithmetic while
retaining the event sequence that determines \(p_i\).

\subsection{Bounded batch approximation}

The bounded policy processes candidates in newest-first batches of \(L\)
lanes. Its non-improving batch budget is
\begin{equation}
 C_{\max}=\max\left(1,
 \left\lfloor\frac{\text{max-skip}}{L}\right\rfloor+1\right).
\label{eq:bounded-batch-budget}
\end{equation}
Any improvement resets the counter. When the budget is reached, older batches
are omitted. Equal maxima within the examined interval select the largest
predecessor index. The global-best candidate is tested only if it lies beyond
the cutoff.

This rule does not reproduce visited-generation events. A valid older
predecessor can lie beyond the omitted interval, so bounded SIMD cannot
guarantee the same endpoint for every anchor set. Its name and policy boundary
make this approximation explicit.

The bounded rule gains regularity by replacing per-candidate marks with one
counter per completed vector batch. It can reduce all lane maxima before making
a control decision. The trade-off is structural rather than numerical. Pair
scores inside the visited interval use the same arithmetic, but the set of
visited predecessors can differ from both scalar and exact SIMD.

Both SIMD forward policies use vector-assisted backtracking. Independent
ranked starts occupy lanes and contiguous predecessor runs use a fast path.
Commits still follow endpoint rank because paths can meet through the shared
claimed-anchor state. A selected SIMD policy also fails when no valid
multi-lane target is available instead of silently switching algorithms.

\section{Memory locality in GPU chaining}

source-at-a-time organization repeatedly reads one completed source score and
scatters updates across separated target scores. Tiled chaining first resolves
the triangular dependencies within a tile. It then keeps completed sources in
shared memory and target accumulators in registers while evaluating the
tile-to-tile pairs. Figure~\ref{fig:chaining-memory-access} reconstructs these
two access patterns. The tiled organization follows the locality argument used

The G3SA CUDA design applies this decomposition with different kernels for

reducing memory traffic, but its current Vulkan score generator has a different
execution structure.

\subsection{Vulkan score generation}

BioSeqDB divides anchors into hard ranges when strand changes or the reference
gap between adjacent anchors exceeds the configured maximum. One 32-lane
subgroup processes each range. Targets advance sequentially because target
\(i+1\) may depend on the score for target \(i\). For each target, the subgroup
scores predecessor batches from newest to oldest, reduces the batch maximum,
and chooses the largest predecessor index on a tie. A workgroup barrier follows
each completed target.

The shader reads each anchor span and checks 64-bit coordinate differences
before narrowing. It stores absolute predecessor indices. These choices differ
from fixed-span and relative-predecessor layouts used by the original CUDA
design. Chaining remains independent of alphabet after anchors have been
formed.

Table~\ref{tab:gpu-chaining-comparison} separates the shared memory-locality
idea from the execution details. G3SA uses a prologue and a rotated tiled tail
for its larger ranges. The Vulkan implementation uses sequential target
completion with 32-wide predecessor batches. It therefore should not be
described as a direct translation of the CUDA kernels.

\subsection{Completion and result projection}

Rich result projections expose the complete score and predecessor arrays to a
CPU backtracker after GPU completion. Coordinate-only projections can instead
use a GPU reducer that repeatedly chooses the strongest unclaimed endpoint and
traces one chain. The standalone reducer examines at most 16 endpoint starts,
so a valid later start can be missed after 16 rejected traces. An eligible
resident path keeps seed-hit processing, sorting, range construction, score
generation, and coordinate reduction on the device. It returns only a compact
mapping result.

GPU selection is explicit. It requires a suitable device, coherent mapped
buffers, and successful memory admission. Failure does not cause an implicit
switch to the CPU. This behavior makes the selected execution contract visible
to a database query and prevents an approximate GPU request from being
reported as a scalar execution.

\section{Summary}

Chaining turns local seed hits into a small set of collinear candidate
mappings. The scalar recurrence rewards newly covered sequence and penalizes
diagonal drift. Its bounded windows, visited-generation rule, strict tie
handling, and global-best rescue make scan order observable. Ranked
backtracking then recovers competing chains for primary and secondary region
selection.

RMQ replaces repeated candidate scans with an augmented tree but has distinct
pair and boundary semantics. Exact SIMD vectorizes independent arithmetic and
replays ordered decisions. Bounded SIMD trades scalar equivalence for a fixed
batch cutoff. GPU chaining reduces memory traffic through range-oriented score
generation and compact result routes, while candidate caps and long-range
sampling make it approximate. Keeping these contracts separate allows callers
to choose an execution method without confusing algorithmic ancestry with
equivalent behavior.
