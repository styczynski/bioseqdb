\section{From local seed hits to candidate mappings}
\label{sec:chaining-purpose}

Minimizers identify short local agreements between a query and a reference, but
they do not by themselves constitute an alignment.  A repetitive genome can
produce thousands of mutually incompatible hits, while a true mapping is
usually represented by a sparse, approximately collinear subset.  The purpose
of chaining is to select that subset.  It is therefore the first stage at which
the mapper reasons about the geometry of a complete candidate mapping rather
than about individual \(k\)-mers.

This chapter presents the chaining implementation that BioSeqDB uses.  The
project contains four generations of designs.  A minimap2-compatible scalar
dynamic program provides the semantic baseline.  An augmented tree implements
range minimum queries (RMQs).  Two single instruction, multiple data (SIMD)
policies accelerate execution on the central processing unit (CPU).  A Vulkan
path inspired by G3SA targets a graphics processing unit (GPU).

These policies do not have identical semantics.  Historical SIMD variants
traded exact stopping behavior for speed.  Other SIMD changes regressed after
increasing instruction-cache pressure.  The GPU path changes the candidate set
for very long ranges.  BioSeqDB therefore exposes the implementations as
explicit policies.

\section{The geometric problem}
\label{sec:chaining-geometry}

After seed lookup, BioSeqDB represents a hit by an anchor
\[
  a_i=(r_i,q_i,\sigma_i,\ell_i,g_i,\phi_i),
\]
where \(r_i\) and \(q_i\) are the reference and query end coordinates,
\(\sigma_i\) is the strand, \(\ell_i\) is the query span contributed by the
seed, \(g_i\) is the query segment identifier, and \(\phi_i\) contains the
remaining flags.  The current C++ object occupies 24 bytes.  Both positions are
stored as full 64-bit values, the strand has a dedicated 32-bit field, the span
is an 8-bit value, and the segment and flags occupy the remaining fields.  The
64-bit physical storage matters for database-resident references because a
concatenated collection need not fit in the 32-bit coordinate model assumed by
older standalone mappers.  The canonical reference key reserves its high bit
for the strand, however, and the region conversion casts coordinates to signed
64-bit values.  The supported canonical reference-coordinate domain is
therefore below \(2^{63}\).  Nor does the physical layout imply end-to-end
64-bit chaining arithmetic.  The current scalar and SIMD pair scorers narrow
coordinate differences to signed 32-bit values and are valid only when the
positive differences fit that domain.  This limitation is revisited below.

Figure~\ref{fig:chaining-dotplot} gives the usual dot-plot interpretation.
Each anchor is a point.  A plausible chain advances in both axes and remains
near one diagonal.  Isolated points and points on an incompatible diagonal are
decoys.  A deletion relative to the reference increases \(r\) faster than
\(q\).  An insertion does the opposite.  Chaining does not resolve either event
base by base.  It merely pays a gap cost and passes the selected region to the
final aligner.

\subsection{Canonical order is part of the contract}

All forward dynamic programs assume anchors are sorted first by strand and
reference coordinate, then by query metadata and coordinate.  BioSeqDB obtains
this order through two packed keys:
\begin{equation}
\begin{split}
 K_r(a_i) &=
   (\sigma_i \ll 63)\mathbin{\vert}
   \bigl(r_i\mathbin{\&}(2^{63}-1)\bigr),\\
 K_q(a_i) &=
   (g_i\ll48)\mathbin{\vert}(\phi_i\ll40)
   \mathbin{\vert}(\ell_i\ll32)
   \mathbin{\vert}(q_i\bmod 2^{32}).
\end{split}
\end{equation}
The comparison is lexicographic in \(K_r\), \(K_q\), and finally the full
\(q_i\).  Thus the reference projection is the strand bit followed by the low
63 coordinate bits.  Physical storage remains 64-bit, but a reference position
at or above \(2^{63}\) is outside the ordering and region-conversion contract.
The last query comparison is not redundant: the packed query key retains
only the low 32 coordinate bits, so it disambiguates anchors only when those
packed low words are equal.  The resulting order is a compatibility order, not
a globally increasing full-\(q\) order once coordinates exceed \(2^{32}\).
The present pipeline normally chains one query whose length is far below that
boundary.  A future database-wide query-coordinate space would require a
different key and arithmetic contract.

The packed keys should not be confused with the physical representation of an
anchor.  They are comparison projections.  Earlier project reports describe
a 16-byte anchor and sorting networks designed around that historical layout.
The present implementation is the 24-byte, full-coordinate representation.
This is one example of why the thesis gives precedence to current source and
to the most recent design documents over older benchmark notes.

The stored seed positions are inclusive \(k\)-mer end coordinates.  For a
forward chain, the region stage converts the first anchor to
\(q_{\mathrm{start}}=q_{\mathrm{first}}+1-\ell_{\mathrm{first}}\) and the
last anchor to \(q_{\mathrm{end}}=q_{\mathrm{last}}+1\).  Reverse-strand
anchors are normalized before chaining and converted back as
\([L-q_{\mathrm{end}},L-q_{\mathrm{start}})\), where \(L\) is query length.
External mapping regions are consequently conventional zero-based,
half-open intervals even though the dynamic program (DP) operates on inclusive
seed endpoints.

\section{The scalar dynamic program}
\label{sec:chaining-scalar}

The scalar implementation is the semantic reference when chaining is invoked
through Structured Query Language (SQL).  It is derived from minimap2's
single-segment, non-cDNA recurrence, where cDNA denotes complementary DNA,
while specializing away branches that BioSeqDB does not need at this
stage \cite{minimap2_paper}.  The exact code comparison in this chapter uses
the bundled \path{main/bench/tool_minimap2/minimap2/lchain.c}.  Let
\[
  d_r(i,j)=r_i-r_j,\qquad
  d_q(i,j)=q_i-q_j,\qquad
  \delta(i,j)=|d_r(i,j)-d_q(i,j)|,
\]
and let
\begin{equation}
  h(i,j)=\min\{d_r(i,j),d_q(i,j)\}.
\end{equation}
A predecessor is geometrically admissible only when it is earlier on the same
strand, both coordinate differences are positive, it lies within the active
reference and query windows, and
\(\delta(i,j)\le B\), where \(B\) is the chaining bandwidth.  The outer loop
maintains the reference-distance condition.  The pair scorer checks the
remaining conditions.  Writing \(\lambda_g\) and \(\lambda_s\) for the gap
and skip coefficients, BioSeqDB assigns the edge contribution
\begin{equation}
\alpha(i,j)=
\min\{\ell_j,h(i,j)\}
-
\begin{cases}
0,&\delta(i,j)=0\ \land\ h(i,j)\le \ell_j,\\[2mm]
\left\lfloor
 \lambda_g\delta(i,j)+\lambda_s h(i,j)
 +\frac{1}{2}\operatorname{fastlog}_2(\delta(i,j)+1)
\right\rfloor,&\text{otherwise.}
\end{cases}
\label{eq:chaining-edge-score}
\end{equation}
All terms inside the floor are non-negative, so the conversion in the C++
implementation is equivalent to truncation toward zero.  The logarithmic term
is evaluated only for a nonzero diagonal difference.  The default coefficients
are derived from the minimizer length \(k\):
\(\lambda_g=0.01k\,s_g\) and
\(\lambda_s=0.01k\,s_s\), with default scales \(s_g=0.8\) and
\(s_s=0\).  Other default limits are a reference gap of 5000 bases, bandwidth
500, \(25\) skip events, and at most \(5000\) examined predecessors.

The best score ending at anchor \(i\) and its predecessor are
\begin{equation}
\begin{split}
 f_i &=
   \max\left(
     \ell_i,\;
     \max_{j\in W_i}\{f_j+\alpha(i,j)\}
   \right),\\
 p_i &=
 \arg\max_{j\in W_i}\{f_j+\alpha(i,j)\},
\end{split}
\label{eq:chaining-dp}
\end{equation}
where \(W_i\) is the bounded set of admissible earlier anchors.  A chain may
begin at \(i\), in which case \(f_i=\ell_i\) and \(p_i=-1\).  This is a sparse
longest-path problem in a directed acyclic graph: sorting provides the
topological order, and every admissible edge points forward.

The effective reference and query search limits in the scalar entry point are
both raised to at least the bandwidth,
\(M=\max(\text{max-gap},B)\).  This avoids the contradictory state in which a
configured diagonal band is wider than the coordinate window that is supposed
to contain it.  The iteration cap then takes the newest
\(\text{max-iterations}\) anchors from that geometric window.

Algorithm~\ref{alg:scalar-chaining} makes the ordered stopping behavior and the
global-best rescue explicit around the recurrence.

\begin{algorithm}[tb]
\caption{BioSeqDB scalar chaining, with control semantics made explicit}
\label{alg:scalar-chaining}
\small
\textbf{Input:} anchors sorted by the canonical order and the chaining
parameters.

\textbf{Output:} score vector \(f\) and predecessor vector \(p\).

\begin{enumerate}
  \item For \(i=0,\ldots,n-1\), perform the following steps.
    \begin{enumerate}
      \item Expire predecessors outside the strand/reference window.
      \item Set
        \[
          f_i\gets\ell_i,\qquad p_i\gets-1,\qquad c\gets0.
        \]
      \item Set
        \[
          j_{\min}\gets
          \max(\text{window-begin},i-\text{max-iterations}).
        \]
      \item Visit \(j=i-1,\ldots,j_{\min}\) in descending order. Whenever
        \((a_j,a_i)\) is geometrically admissible, perform the following
        updates.
        \begin{itemize}
          \item Set \(v\gets f_j+\alpha(i,j)\).
          \item If \(v>f_i\), set
            \[
              f_i\gets v,\qquad
              p_i\gets j,\qquad
              c\gets\max(0,c-1).
            \]
          \item Otherwise, if candidate \(j\) is already marked for generation
            \(i\), set \(c\gets c+1\). Break the descending visit when
            \(c>\text{max-skip}\).
          \item If the descending visit was not broken and \(p_j\ge0\), mark
            predecessor \(p_j\) for generation \(i\).
        \end{itemize}
      \item If the best earlier global endpoint was not scanned and improves
        \(f_i\), adopt it as \(p_i\). This is the global-best rescue.
    \end{enumerate}
  \item Produce \(f,p\).
\end{enumerate}
\end{algorithm}

\subsection{Why the control flow is semantically observable}

Equation~\ref{eq:chaining-dp} is the conceptual objective, but a faithful
implementation must also preserve several details of minimap2's bounded
search.  Candidates are visited newest-to-oldest, an update requires a strict
improvement, and therefore the newest predecessor wins a score tie.  The
\texttt{max\_skip} condition is not simply ``stop after 25 bad anchors.''
The algorithm stores generation marks and increments the counter when a
non-improving candidate was previously marked as the predecessor of a newer
candidate in the same descending scan.  After processing candidate \(j\), it
marks \(p_j\), not \(j\), for the current generation.  A later improvement
decrements the counter.  Reordering the scan or reducing a vector batch before
replaying these events can therefore change both the stopping point and the
selected predecessor even when every pair score is numerically exact.

The global-best rescue is a second subtlety.  Early stopping can leave an old,
high-scoring endpoint outside the scanned suffix.  BioSeqDB tracks the best
completed endpoint and tests it separately if it was not visited.  This does
not turn the bounded heuristic into exhaustive dynamic programming, but it
protects an important class of long-range paths.  Both the exact SIMD
implementation and the endpoint-qualification corpus test this behavior
explicitly.

The scalar score corresponds to the non-cDNA, single-segment path of the
bundled minimap2 \texttt{lchain.c}.  Upstream minimap2 also carries
multi-segment and cDNA-specific branches in the same routine.  Those branches
are not latent features of BioSeqDB's scorer and should not be inferred from
the common ancestry.  Conversely, BioSeqDB preserves full 64-bit reference
and query coordinates in the anchor object rather than relying on a 32-bit
stored position.

There is nevertheless a live large-coordinate boundary.  The scalar scorer
casts \(q_i-q_j\) and \(r_i-r_j\) to signed 32-bit integers before testing
them, and the SIMD scorer intentionally subtracts low 32-bit words.  The
full-width reference window prevents ordinary distant reference candidates
from reaching the scorer, but a query difference larger than \(2^{31}\), or
one congruent to a small value modulo \(2^{32}\), can be misinterpreted.
The Vulkan shader checks unsigned 64-bit distances before narrowing and does
not share this particular failure mode.  Thus BioSeqDB has 64-bit anchor
\emph{storage}, but scalar/SIMD chaining is presently proven only for bounded
per-query coordinate differences.

\section{Recovering chains and competing mappings}
\label{sec:chaining-backtracking}

The forward pass computes an endpoint score for every anchor, not a single
mapping.  Backtracking ranks endpoints by the pair \((f_i,i)\), walks them in
descending score order, and follows \(p_i\) until the path terminates or reaches
an anchor already claimed by a stronger path.  A newly recovered path is kept
only when it satisfies both the minimum chain score and minimum seed-count
thresholds (defaults 40 and 3).  The stored chain record contains its score,
number of anchors, and offset into the compacted anchor array.

If a walk merges into an already claimed path, the score attributed to the new
prefix is reduced by the score at the merge endpoint.  This prevents a weak
alternative from inheriting the entire score of a stronger chain merely
because the two share a suffix.  Rejected traversals remain marked, which also
affects later candidate endpoints.  The resulting list represents competing
candidate regions.  Later mapping-region logic decides parent/secondary
relationships and computes mapping quality.

The shared scalar/RMQ backtracker is intentionally simpler than the complete
upstream minimap2 \texttt{mg\_chain\_backtrack} plus
\texttt{compact\_a} sequence.  In particular, the current \mbox{BioSeqDB}
helper has
no explicit \texttt{max\_drop} parameter and does not reproduce minimap2's
final target-position ordering step byte for byte.  The forward peak-score
array is passed to the helper but currently unused.  Thus ``minimap2-compatible
score and predecessor search'' is a more accurate description than
``identical minimap2 chaining.''  This boundary is consequential when
interpreting exactness tests: they verify the project-defined contract and
selected endpoint coordinates, not every internal array permutation of the
upstream program.

\subsection{From competing chains to primary and secondary regions}

After coordinate derivation, the pipeline score-sorts chain regions and treats
the highest-scoring region as primary.  For each later region it computes the
union of query overlap with existing primaries and the query span not explained
by that overlap.  Let \(o\) denote overlap, \(u\) uncovered length, and
\(m_{\min},m_{\max}\) the smaller and larger spans of the two regions.  The
candidate becomes secondary when
\[
  \frac{o}{m_{\min}}-\frac{u}{m_{\max}}
    > \text{mask-level}
  \quad\land\quad
  u\le\text{mask-length}.
\]
This formulation discounts a candidate that overlaps strongly but also adds a
substantial novel query interval.  The defaults use a mask level of \(0.5\)
and an effectively unbounded mask length.

Filtering always retains primary regions.  A secondary is retained only when
its score is sufficiently close to its parent:
\[
 s_{\mathrm{secondary}}\ge
   \rho\,s_{\mathrm{parent}}
 \quad\lor\quad
 s_{\mathrm{secondary}}+\Delta_{\min}\ge s_{\mathrm{parent}},
\]
subject to a global \texttt{best\_n} limit (default 5).  Coordinate-identical
duplicates are removed.  The default score ratio is \(\rho=0.8\).  These rules
are downstream of the chaining DP, so a change in backtracking order can still
change which candidate is presented first and hence influence classification.

\section{An augmented-tree RMQ formulation}
\label{sec:chaining-rmq}

The scalar recurrence can examine up to \(I\) predecessors per anchor, giving
\(O(nI)\) work in a dense range.  BioSeqDB also implements the RMQ
reformulation used by modern minimap2.  The insight is to separate the part of
the edge penalty that is linear in the predecessor coordinates.  Candidate
\(j\) receives the priority
\begin{equation}
  \pi_j =
  -\left[
    f_j+\frac{\lambda_g}{2}(r_j+q_j)
  \right].
\label{eq:rmq-priority}
\end{equation}
An Adelson-Velsky and Landis (AVL) tree is keyed by \((q_j,j)\), and every node
caches the minimum priority in its subtree.  This supports insertion, expiry,
and a minimum query over a query-coordinate interval in \(O(\log n)\).  Ties
remain deterministic because the anchor index is part of the key.

reduces a range query to the boundary path and fully covered subtrees.

Anchors sharing a reference position are inserted only after that complete
position group has been scored.  Otherwise an anchor could become the
predecessor of another hit with zero reference distance.  Entries expire when
they leave the reference window, and an explicit tree-size cap prevents
unbounded storage under pathological repetition.  The tree proposes an
endpoint.  BioSeqDB then evaluates that endpoint with the RMQ path's simplified
pair scorer rather than treating the tree priority as a final chain score.

There are two qualifications.  First, the RMQ path calls a simplified scoring
routine whose penalty trigger tests whether the query distance exceeds the
predecessor span, whereas the scalar routine tests the minimum of reference
and query distance.  The paths are consequently algorithmic variants, not
merely two data structures around one bit-identical kernel.  Second, the code
contains an optional inner-tree refinement, but the standard trait dispatch
sets its inner distance to zero.  The common SQL RMQ path therefore uses the
primary augmented tree only.  Its attraction is asymptotic behavior on dense
anchor sets, while its cost is pointer-rich tree maintenance and a semantic
surface distinct from the scalar oracle.

\subsection{Current RMQ correctness boundary}

Source inspection found two live differences from the bundled minimap2 RMQ
routine that are more serious than the intentional simplified score.  The
primary BioSeqDB query computes the diagonal width but does not reject a
candidate whose width exceeds the configured bandwidth.  Its closed query
interval can also include an equal-\(q\) predecessor, while minimap2's sentinel
keys exclude both the lower boundary and equal-query hits.  Since the
simplified pair scorer does not repeat the full validity checks, such a
candidate can be selected.

The disabled inner-tree path has additional differences in its skip
accounting and capacity management.  No direct RMQ unit test or operation-level
RMQ proof record was found in the current tree.  For this reason the RMQ
implementation is documented here as an important intermediate algorithm and
an optimization target, not as an exact replacement for either scalar
BioSeqDB or minimap2 RMQ.  Existing benchmark rows labeled
\texttt{minimap2\_rmq} cannot close this gap: the wrapper does not set
minimap2's \texttt{MM\_F\_RMQ} flag, so that comparison actually executes its
scalar dynamic program.

\section{SIMD chaining on the CPU}
\label{sec:chaining-simd}

Chaining resists naive vectorization.  Pair scores for a fixed \(i\) are
independent, but the decision to stop scanning is an ordered state machine.
Backtracking is even less regular because predecessor paths have data-dependent
lengths and collide through a shared visited array.  BioSeqDB uses the Highway
portability library to select vector widths at compile time while retaining one
source for supported vector instruction targets.

\subsection{Structure-of-arrays scoring}

The SIMD forward pass projects anchors into 32-bit structure-of-arrays (SoA)
buffers
for reference position, query position, and span.  Pairwise differences are
formed modulo \(2^{32}\).  Low-word subtraction equals the full difference only
when the actual values satisfy
\[
  0<d_r(i,j)\le\texttt{INT32\_MAX}
  \quad\text{and}\quad
  0<d_q(i,j)\le\texttt{INT32\_MAX}.
\]
The reference window helps establish the first bound, but it does not by itself
prove the query-distance bound.  Absolute 64-bit coordinates may be large if
their local differences satisfy both conditions.  Outside this domain,
wraparound can alias a distinct difference to the same low word.  The full
anchor representation and ordering remain 64-bit.  Only the local arithmetic
projection is narrow.

For each predecessor vector, Highway first evaluates admissibility masks and
coordinate-derived gaps.  It then computes base rewards, linear penalties, and
the logarithmic correction under those masks.  Tail lanes are masked
explicitly.  When the default skip scale is zero, a specialized instantiation
removes the corresponding multiplication and loads instead of relying on
cross-template constant propagation.

\subsection{\texttt{exact\_visited}: vector arithmetic, scalar decisions}

The exact policy vectorizes score production but preserves the scalar
candidate event order.  A batch that cannot improve the current best can count
its visited-generation hits in bulk.  If any lane may improve, the relevant
lanes are replayed newest-to-oldest so that strict ties, counter decrement, and
early termination match the scalar control path.  Since the common
predecessor relation is \(p_j=j-1\), contiguous generation marks can be stored
as a vector.  The global-best rescue is likewise located with a vector scan,
then applied under the scalar eligibility rule.

This design illustrates a useful principle: exact SIMD need not mean that
every operation is vectorized.  It means that vectorization is placed where
lanes are independent and ordered effects are retained where they are
observable.  Historical attempts to replace small reductions with horizontal
SIMD operations did not automatically improve this balance.  A May 2026
regression report measured a 39.1\% slowdown in one very-long-read chaining
configuration after such a reducer change.  Template duplication also increased
instruction-cache pressure.  The change was reverted.  Those measurements are
historical and configuration-specific, but they explain why the current code
avoids equating ``more vector instructions'' with ``faster chaining.''

\subsection{\texttt{bounded\_batch\_approximate}: a deliberate speed policy}

The bounded policy processes candidates newest-to-oldest in Highway batches
and maintains lane-resident best values.  Its non-improving-batch budget is
\begin{equation}
  C_{\max}=
  \max\left(1,\left\lfloor
    \frac{\text{max-skip}}{L}
  \right\rfloor+1\right),
\label{eq:bounded-batch-budget}
\end{equation}
where \(L\) is the hardware lane count.  Any improvement resets the counter.
After \(C_{\max}\) consecutive non-improving batches, the older unscanned
interval is discarded.  When different lanes produce an equal maximum, the
largest predecessor index wins, recovering the newest-candidate tie rule
within the examined interval.  A global-best candidate is tested only when it
lies in the discarded interval.

This policy does \emph{not} simulate the scalar visited-generation heuristic.
An adversarial old predecessor can be placed beyond the batch cutoff, so no
static proof can guarantee the same endpoint for all anchor sets.  BioSeqDB
therefore names it approximate and qualifies it empirically.  The qualification
metric compares primary chain endpoints against both the exact SIMD policy and
the bundled minimap2 executable:
\begin{equation}
 D=\max\{
 |q_s-q'_s|,\ |q_e-q'_e|,\
 |r_s-r'_s|,\ |r_e-r'_e|
 \}.
\label{eq:endpoint-distance}
\end{equation}
The fixed corpus accepts a comparison only for \(D<15\) bases and also checks
missing mappings, endpoint mismatches, and a dedicated global-rescue fixture.
Passing that corpus is evidence about the tested distribution.  It is not a
mathematical equivalence result.

\subsection{Vector backtracking}

Both SIMD forward policies use a dedicated SIMD backtracker.  Primary paths
are consumed in vector chunks, with a fast path for contiguous predecessor
indices.  Remaining ranked starts occupy independent lanes, but lanes are
committed in endpoint-rank order because overlap through the visited array is
observable.  Consequently the implementation vectorizes path discovery while
retaining scalar orchestration at collision points.  There is no hidden call
to the shared scalar backtracker and no scalar fallback if a selected SIMD
target cannot provide a valid multi-lane implementation.  Selection is a
contract rather than a best-effort hint.

\section{From G3SA to the Vulkan implementation}
\label{sec:chaining-vulkan}

The GPU implementation began from the observation developed by G3SA: chaining
is expensive not only because it performs many score evaluations, but because
the conventional CUDA organization repeatedly reads source anchors and
writes target scores through global memory.  G3SA tiles the dynamic program.
In a \emph{prologue}, anchors within one tile depend on earlier anchors in that
same tile, producing a triangular dependency pattern.  In the \emph{tail},
completed source values reside in shared memory while target accumulators stay
in registers.  Threads rotate their source assignment so that a tile-to-tile
all-pairs comparison reuses shared data.

Figure~6 in the G3SA paper by Y.~Han and colleagues
\cite{g3sa_paper}.

\subsection{What the original G3SA implementation did}

The copied G3SA CUDA source divides ranges into short
(\(\le512\) anchors), medium (\(513\) to \(5120\)), and long
(\(>5120\)) classes.  The short kernel uses 32 threads.  The medium and long
kernels use 512 and 1024 threads respectively, and their tiled path stages
1024 anchors in shared memory.  It rotates source assignments with a
modulo-1024 index.  A temporary predecessor within the tile is represented as
a signed 16-bit relative distance.  The global predecessor array stores a
signed 64-bit relative distance.

The copied wrapper compiles the chaining search cap as
\texttt{MAX\_ITER\_CHAIN=5000}.  Its reference-distance and query-distance
limits are both 5000.  The bandwidth is zero, and the gap-penalty scale is
\(0.12\).  The wrapper records \texttt{max\_chain\_skip=0}, while the DP path
assumes a query span of 15.  No \texttt{max\_chain\_skip} argument reaches the
kernel.  The kernel therefore does not implement minimap2's visited-generation
heuristic and instead updates source-to-target scores within the fixed
iteration cap.  Agreement with minimap2 endpoints is consequently an empirical
property of an evaluated corpus, not semantic identity.

G3SA keeps its bulk RMQ, backtracking, and compaction intermediates on the GPU,
which reduces round trips through the mapping pipeline.  It does not eliminate
every host interaction.  The copied runtime transfers medium- and long-range
counts to the host, and the paper allows exceptionally complex branching reads
to be resent to the CPU.  On the paper's single RTX A6000 and Threadripper PRO
7985WX system, the reported stage-wise chaining geometric mean was \(3.15\times\)
relative to mm2-fast and \(1.24\times\) relative to mm2-gb.  The authors also
reported 100\% chaining accuracy on their evaluated datasets under the
same-chained-seeds metric \cite{g3sa_paper}.  Maximum-score and position
agreement is the paper's extending metric, not its chaining metric.  Those
measurements use different hardware, baselines, inputs, and pipeline boundaries
from BioSeqDB's PostgreSQL experiments, so they are context for the design
lineage rather than a direct performance comparison.

Those choices target a CUDA program tuned to a fixed GPU.  They do not transfer
directly to a PostgreSQL extension that may be called with different alphabets,
seed lengths, devices, and projection requirements.  BioSeqDB adopted the
score-generation motivation and an explicit GPU execution contract, but not
the complete kernel topology.

\subsection{The live Vulkan kernel}

The current shader assigns one 32-lane subgroup to one hard range.  Hard ranges
are split when orientation changes or when the reference gap between adjacent
anchors exceeds the configured maximum.  Anchors are advanced sequentially.
For each target anchor, the subgroup scores predecessors in newest-first
batches of 32 and reduces the batch maximum.  Equal scores select the largest
predecessor index.  A workgroup barrier follows every completed target because
the next target can depend on it.

This organization differs from the older 384/512/1024-workgroup selector still
mentioned in comments and old tests.  The live selector returns a 32-thread
subgroup key.  It also differs from G3SA in three parameter-handling choices.
The shader reads each anchor's span instead of assuming 15.  It checks full
64-bit coordinate differences before scoring.  It stores absolute predecessor
indices.  Chaining itself is alphabet-neutral once anchors have been produced.

It is also deliberately approximate.  The device iteration limit is
\[
  I_{\mathrm{GPU}}=\min(I_{\mathrm{requested}},3000),
\]
so the standard CPU limit of 5000 is not honored.  When
\texttt{max\_chain\_skip} is positive, the shader stops after
\(\lfloor\text{max-skip}/32\rfloor+1\) non-improving predecessor batches
instead of replaying scalar visited-generation events.  A nonpositive value
disables this batch cutoff.  The normal default is positive, and the shader has
no global-best rescue.  A hard range longer than 131072 anchors is thinned
toward 65536 anchors by preserving its endpoints and sampling the interior at
an adaptive stride.  Experiments with targets of 16384, 32768, and 49152 moved
endpoints beyond the accepted tolerance.  The 65536 target was the last focused
configuration to pass, not a proof that it preserves every input.

\subsection{Standalone and resident completion routes}

The standalone rich-projection route allocates \(f\) and \(p\) in
host-visible coherent mapped buffers.  After fence completion it validates
score and predecessor invariants, then invokes the shared CPU backtracker.  The
operation named \texttt{download\_locked} returns spans that alias those mapped
buffers.  It is a logical host read, not a device-to-host copy.

The standalone coordinate route still allocates and fills the complete device
\(f\) and \(p\) arrays.  A GPU reducer probes the best currently unvisited
start, marks an unsuccessful trace visited, and repeats for at most 16 starts.
It returns one selected trace, so the host does not run the shared CPU
backtracker or consume the full arrays.  This removes host-side completion
work rather than the device DP storage.  A valid seventeenth start can be
missed after sixteen rejected probes.  The host also contains a
coordinate-chain helper with equivalent intent, but it has no current caller.

Resident Phase~C has both single-query and batched paths.  Its strict eligibility
gate requires Vulkan minimizer extraction, Vulkan seed-hit processing, the
fused front end, Vulkan chaining, and a coordinate-only projection.  Edit
distance, exact-edit, and prefilter modes must be inactive.  Seed-hit emission,
sorting, hard-range construction, DP, and reduction remain device-resident, and
only a compact result crosses the boundary.  These routes still allocate
device \(f\) and \(p\) storage internally.

The Vulkan route is fail-closed rather than opportunistic.  It rejects software
devices, requires host-visible coherent unified buffers, performs an explicit
memory-admission check, and does not silently fall back to the CPU.  This makes
an EXPLAINed GPU choice meaningful, but it also means the caller must opt in
with a trusted device.  Some trait metadata still says that
\texttt{max\_chain\_skip} is unused and that backtracking is always on the CPU.
It also labels score generation as \texttt{g3sa-tiled-dp} and retains the
historical mode name \texttt{VULKAN\_TILED\_DP}.  The live subgroup shader,
standalone reducer, and resident Phase~C routes make all four descriptions
stale.

\section{How the implementation evolved}
\label{sec:chaining-evolution}

The current policy split is the result of intermediate failures as well as
successful optimizations.

\paragraph{Template and reducer experiments.}
Early 2026 work attempted wider template dispatch, SIMD sorting, horizontal
maximum reducers, and multiple \texttt{SIMD\_MM2} variants.  Some experiments
improved isolated operations but harmed the complete chaining stage through
extra dispatch, code size, or scratch traffic.  The regression investigation
superseded the earlier optimistic implementation notes and restored the
baseline reducer.  A separate \texttt{SIMD\_MM2\_V2} route was removed rather
than retained as an ambiguous second ``SIMD'' mode.

\paragraph{Exact SIMD as an oracle.}
The next milestone separated pair-score vectorization from ordered decisions.
Exact-visited SIMD gained bit-for-bit forward-state comparisons against the
BioSeqDB scalar path, dedicated overlap tests for the vector backtracker, and
fail-closed target checks.  This provided an executable oracle that was faster
on the qualified cases without weakening the contract.

\paragraph{Approximation as a named policy.}
Historical very-fast SIMD results came from a batch cutoff that did not
preserve minimap2's visited-generation control.  Rather than describe the
speedup as exact, the final design names the behavior
\texttt{bounded\_batch\_approximate}, retains a constructed counterexample,
and requires endpoint qualification.  The exact and bounded policies share
the vector score and vector backtracking infrastructure but differ in their
forward stopping semantics.

\paragraph{GPU specialization.}
The G3SA port first motivated larger tiled workgroups.  The live Vulkan code
instead converged on a one-subgroup kernel, range compaction, and a projection-
dependent coordinate reducer.  This is a database-oriented compromise:
the standalone coordinate path avoids CPU backtracking even though it still
creates complete device score and predecessor arrays.  Resident Phase~C keeps
the fused front end, chaining, and reduction on the device and returns a compact
result.  Richer standalone projections retain CPU backtracking.  The accepted
65536-anchor compaction target emerged from failed more-aggressive targets and
remains an empirical operating point.

\section{The final execution policy}
\label{sec:chaining-final-policy}

The final design does not choose a single universally best chainer.  It defines
a policy boundary that exposes semantic and hardware trade-offs.  Both the
\texttt{Minimap2Params} object and the PostgreSQL configuration parameter
default to the scalar minimap2-compatible implementation.  A C++ caller that
selects SIMD without
overriding its policy receives \texttt{exact\_visited}.  PostgreSQL finalization
maps an explicitly selected SIMD algorithm to
\texttt{bounded\_batch\_approximate}.  Every non-SIMD backend resets the SIMD
policy to exact so stale options cannot leak across calls.  Vulkan and RMQ are
explicit choices, and selected backends fail instead of falling back silently.

Table~\ref{tab:chaining-policy} summarizes where each policy is exact,
approximate, experimental, or projection-dependent.

This separation prevents three category errors.  A benchmark-qualified
approximation is not treated as a theorem.  Shared ancestry with minimap2 is
not treated as byte-identical behavior.  A G3SA-inspired Vulkan shader is not
presented as a direct CUDA port.  The separation also lets the planner and a
future cost model account for projection requirements.  A coordinate-only
query can use standalone GPU reduction or an eligible resident Phase~C route.
A caller that requires scalar stopping behavior can retain the scalar or exact
SIMD contract.

\section{Summary}

Chaining converts a cloud of minimizer hits into a small set of collinear
candidate mappings.  BioSeqDB's scalar recurrence rewards non-overlapping seed
coverage and penalizes diagonal drift, while bounded predecessor windows,
visited-generation stopping, strict ties, and global-best rescue make its
control behavior more subtle than the recurrence alone suggests.  Backtracking
then claims ranked predecessor paths and leaves primary/secondary
classification to the region stage.

The implementation history produced three different acceleration strategies.
RMQ changes the data structure and asymptotic search, but the current port
still needs correctness repairs.  Highway SIMD preserves the scalar contract
under exact-visited replay or trades it explicitly for batch-bounded speed.
Vulkan adopts the GPU locality motivation of G3SA while using a distinct
32-lane kernel, full-width shader checks, range compaction, and
projection-dependent completion.  Report 192 shows why the distinction
matters: exact SIMD reduced inclusive chaining-kernel P50 by 11.6\%, while
bounded SIMD reached 41.9\% by skipping hundreds of millions of candidates.
The latter passed the fixed endpoint corpus with zero observed difference, but
remains approximate by construction.  When its strict eligibility gate is
satisfied, resident Vulkan Phase~C also keeps the fused front end through
coordinate reduction on the device.

The next chapter begins where chaining ends.  It examines how the selected
query and reference regions become base-level alignments, and how final
alignment backends preserve or relax the candidate contracts established here.
