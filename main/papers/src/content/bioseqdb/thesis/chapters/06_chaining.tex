\section{From local seed hits to candidate mappings}
\label{sec:chaining-purpose}

When minimizers are generated and we take the intersection (by hash value) of the minimizer sets between the query and the reference, we get a set of seed hits which is encoded as anchors.

\section{Anchor geometry and ordering}
\label{sec:chaining-geometry}

A seed hit is represented by an anchor
\[
  a_i=(r_i,q_i,\sigma_i,\ell_i,g_i,\phi_i),
\]
where \(r_i\) and \(q_i\) are inclusive seed-end coordinates on the reference
and query, \(\sigma_i\) is the strand, \(\ell_i\) is the query span, \(g_i\)
identifies a query segment, and \(\phi_i\) stores additional ordering flags.

Below you can see the physical representation of the anchor in memory in minimap2 and in our implementation. We could potentially use adaptive representation similar to minimizers, but anchors are fewer than minimizers, so the benefit would be limited for additional complexity of C++ templates.

An increasing diagonal coordinate indicates that in reference we matched more symbols than in the query (meaning insertion/deletion has occured). As we would like to have some well defined order of anchors, we sort them by strand and reference coordinate first, then by the additional metadata:
\begin{equation}
\begin{split}
 K_r(a_i) &=
   (\sigma_i \ll 63)\mathbin{\vert}
   \bigl(r_i\mathbin{\&}(2^{63}-1)\bigr),\\
 K_q(a_i) &=
   (g_i\ll48)\mathbin{\vert}(\phi_i\ll40)
   \mathbin{\vert}(\ell_i\ll32)
   \mathbin{\vert}(q_i\bmod 2^{32}).
\end{split}
\label{eq:chaining-order}
\end{equation}

Comparison is lexicographic in \(K_r\), \(K_q\), and the full \(q_i\). The hashing doesn't need full 64 bits for query position i.e if query coordinates $q_i$ exceed \(2^{32}\) we still have correct order as the leftmostpart is still the fragment number $g_i$ (fragments won't be larger than $2^{32}$). Fragmentation of sequences is discussed later in the storage chapter.

\subsection{Shared pair score}

Let's say we have two anchors with coordinates $q_j, q_i$ and $r_j, r_i$ on the query and reference.
Let's assume the minimizer span is always $k$. We now can say that after incorporating $(r_j, r_i)$ anchor we will cover $q_i-q_j$ symbols on the query and $r_i-r_j$ symbols on the reference, however those two jumps can be interpreted as
taking some symbols from query and assuming they form replacement and the rest forms a gap. For example let's say $q_i-q_j > r_i-r_j$. This means that we match more symbols in query than in reference, so indicates some deletion in the reference.
So we can say $r_i-r_j$ symbols are replaced (or stay the same) while the leftover $(q_i-q_j)-(r_i-r_j)$ symbols form this deletion. This thinking is symmetrical so we just only need to use minimum and absolute value to make it more generic.

Now we introduced $g(j,i)$ (the advance shared by the reference and query) and $\delta(j,i)$ (the remaining advance in whichever sequence moves farther).
As k-mers represent hashed fragment of length $k$ we can assume that in our match we have exactly $\min\{q_i-q_j, r_i-r_j, k\}$ new symbols that matched.
Hence we now define our first primitive score as $\min\{q_i-q_j, r_i-r_j, k\} = \min\{g(j,i), k\}$.

This scoring has some problems with the most important one being that it doesn't penalize the case when we have a large gap in the reference sequence just to match one or two symbols in the query. This is improbable that some very large fragment was replaced during evolutionary processes by just a few bases.
For that reason we will use function $\left\lfloor\text{Penalty}(\delta, g)\right\rfloor$. The penalty function should satisfy the following properties:
\begin{itemize}
  \item There's no penalty for doing nothing at all: $\text{Penalty}(0, 0) = 0$
  \item For $g \leq k \land \delta = 0$ there's no gap so there's shouldn't be any penalty: $\text{Penalty}(0, g) = 0$
  \item Penalty should be monotonically increasing with respect to $\delta$: $\text{Penalty}(\delta, g) \leq \text{Penalty}(\delta+1, g)$
  \item Penalty should be increasing slower than linearly with respect to $g$: $\text{Penalty}(\delta, g+1) < \text{Penalty}(\delta, g) + 1$. This guarantees that increasing $g$ without touching $\delta$ benefits overall score (we prefer replacement region over gap region)
  \item For small $g$ and $\delta$ our penalty function should prefer increase in $g$ rather than $\delta$. This is equivalent of saying that we want to stay close to the diagonal and reduce the gap size introduced: $\text{Penalty}(\delta+1, g) \geq \text{Penalty}(\delta, g+1)$
  \item For large $g$ and $\delta$ our penalty function should be asymptotically the same for both $\delta$ and $g$. This is equivalent of saying that if we encounter very large gaps, then it doesn't matter if we increase the matching region between two fragments or increase the gap as both fragments are very dissimilar: $O_{\delta}(\text{Penalty}(\delta, g = \text{const})) = O_{g}(\text{Penalty}(\delta = \text{const}, g))$
\end{itemize}

\info{Symmetry}{Using $g$ and $\delta$ as only parameters for penalty function guarantees that scoring is symmetric. Symmetry makes sure that gap costs are the same for both query and reference.}

Our final score is then something of the following structure:
\begin{equation}
\begin{gathered}
\text{Score}(j,i) = \min\{g(j,i), k\} - \left\lfloor\text{Penalty}(\delta(j,i), g(j,i))\right\rfloor \\
= \min\{g(j,i), k\} - \left\lfloor \alpha * g(j,i) + \beta * \delta(j,i) + \gamma * f(\delta(j,i)) \right\rfloor \\
1 \leq \alpha, \beta, \gamma \geq 0
\end{gathered}
\end{equation}

The minimap2 scoring definition $E$ looks exactly as what we have just specified:
\begin{equation}
\begin{aligned}
 d_q(j,i) &= q_i-q_j, & d_r(j,i) &= r_i-r_j,\\
 \delta(j,i) &= \lvert d_r(j,i)-d_q(j,i)\rvert,
 & g(j,i) &= \min\{d_r(j,i),d_q(j,i)\}.
\end{aligned}
\label{eq:chaining-distances}
\end{equation}

\begin{equation}
 E(j,i)=\min\{\ell_j,g(j,i)\}-P(j,i),
\label{eq:chaining-link-score}
\end{equation}
where
\begin{equation}
P(j,i)=
\begin{cases}
0,
  & \delta(j,i)=0\ \land\ g(j,i)\leq\ell_j,\\[2pt]
\left\lfloor
  \lambda_g\delta(j,i)+\lambda_s g(j,i)
  +\dfrac{1}{2}\operatorname{mglog}_{2}\!\bigl(\delta(j,i)+1\bigr)
\right\rfloor,
  & \text{otherwise}.
\end{cases}
\label{eq:chaining-penalty}
\end{equation}
The function \(\operatorname{mglog}_{2}\) is minimap2's polynomial
approximation of \(\log_2\). So far in the abstract definition of scoring we didn't mention diagonal, but nonnegative coefficient \(\lambda_g\) can be viewed as diagonal-gap penalty (further away from diagonal we penalize more), where the nonnegative coefficient \(\lambda_s\) is the penalty for distance. The value \(\ell_j\) is the
query span of predecessor \(j\). (In our example above we used $k$ for all k-mers sizes, but as mentioned before minimap2 with specific settings can compress regions of same repeating symbols so we just replace $k$ with kmer span $\ell_j$. All the logic stays the same) \coderef{minimap2/lchain.c}
{Minimap2 chaining link score}{comput_sc}{113}

\info{Score units}{In this definition we view scoring function as expressed in number of matched symbols (not some arbitrary large numbers), so the coefficients must be set accordingly so the values are scaled correctly. In the dynamic programming formulation we then can take maximum of $E$ value and $\ell_i$ to make sure that in the worst case scenario we assume that we at least matched the length of the minimizer. There are no formal limitations on this normalization, but it makes reasoning about the scores easier.}

It's worth noting that defined scoring is also symmetrical in terms of coordinates i.e the score doesn't take $r_i, q_i$ positions as parameters so reversing coordinate systems doesn't change the outcome.
However, in dynamic programming we often want to use the locally close predecessor as the best one. 
Consider for example situation in which we have two possible candidates for some anchor $i$: one is very close to our position while offering lower cummulative score for the chain, while the other one is very far away but offers high cummulative score. This scenario can happen if we have very good chain with narrow gaps and slightly worse chain with larger gaps, but the two are very far away from current position.
We can have selection function that not only takes the best score, but also adds function dependent on current anchor position to make sure to formally express that preference:
\begin{equation}
\begin{aligned}
  f_j = \max_{i < j}\{f_i+E(j,i)\}, \\
  \text{Selection}(i) &= f_j + \phi(r_i, q_i)
\end{aligned}
\end{equation}

There shouldn't be any difference in behaviour for query and reference so $\phi$ should be symmetric. Additionally $\phi$ should be monotonic to express the fact that we prefer closer predecessors: $\phi(r_i, q_i) \leq \phi(r_i+1, q_i), \phi(r_i, q_i+1) \leq \phi(r_i+1, q_i+1)$.
Please note that the difference here is that it's not a cummulative chain score. It's only used to select the best predeccesor for current anchor (if we tried to sum this score up we would get total score having $O(n^2)$ terms, which would severly alter the scoring behaviour discussed earlier).

In the later chapters we discuss selection function that uses artithmetical average of positions:
\begin{equation}
\begin{aligned}
  \operatorname{Selection}(j) = f_j+\phi(r_i, q_i) \\
  \phi(r_i, q_i) = \frac{r_i + q_i}{2}
\end{aligned}
\end{equation}

\section{B1: minimap2 dynamic programming}
\label{sec:chaining-b1}

As our scoring model $E(i,j)$ depends only on two anchors we can define recursive equations for dynamic programming:
\begin{equation}
 f_i=\max\!\left(
   \ell_i,
   \max_{j\in\mathcal{C}_i}\{f_j+E(j,i)\}
 \right),
 \qquad
 p_i=\operatorname*{arg\,max}_{j\in\mathcal{C}_i}\{f_j+E(j,i)\}.
\label{eq:chaining-b1-recurrence}
\end{equation}
Where $\mathcal{C}_i$ is the set of valid predecessors (selected by being close to diagonal - this is form of specifying cutoff condition so we don't need to check all possible predecessors all the time).
Maximum function is used here to make sure that in worst case if our definition of $E(i,j)$ yield very low score we can say that we matched at least length of the minimizer span.

If no predecessor improves the base value of score \(\ell_i\), then
\(p_i=-1\).

We will call iteration over $\mathcal{C}_i$ a scan. Minimap2 does this scan by visiting anchors in order from newest to oldest.

After sorting, minimap2 numbers the anchors \(0,1,\ldots,n-1\). When the DP algorithm
reaches anchor \(i\), the scores \(f_0,\ldots,f_{i-1}\) and predecessor
indices \(p_0,\ldots,p_{i-1}\) have already been calculated. It starts a new
chain at \(i\) with
\[
  f_i=\ell_i \qquad\text{and}\qquad p_i=-1,
\]
Minimap2 tests earlier anchors in the order \(j=i-1,i-2,\ldots\) (larger
index is tested first). For every pair that passes the distance checks, it
calculates
\[
  c_j=f_j+E(j,i).
\]
If \(c_j>f_i\), anchor \(j\) becomes the new predecessor:
\(f_i\gets c_j\) and \(p_i\gets j\) (strict equality is important here so we avoid using older anchors with the same score)

Trying every earlier anchor would make this dynamic program expensive. Minimap2 applies the following strategies to limit the work performed:
\begin{itemize}
  \item \texttt{max\_iter} limits how many previous anchors we scan: this is the number of highest-numbered array positions before \(i\).
  \item \texttt{max\_skip} is the limit on skip counter \(s\). It starts at zero for every new \(i\) and is increased by one on marked anchor that fails to improve the score and decreased by one on marked anchor that improves the score. If skip counter exceeds limit we finish scan loop early and do not scan other previous anchors.
  \item \texttt{m} is an extra candidate that is tested after the scan loop. It is the anchor with the highest score among all previously tested anchors (this is a measure to prevent skipping good chains due to too aggressive skip counter limit)
  \item \texttt{CanScore(j,i)} checks the anchor distances to make sure the anchor lies within the band (close to diagonal). It uses $D_x$ and $D_y$ for limits on reference and query distances respectively and $B$ for distance from diagonal.
\end{itemize}

Minimap2 contains separate rules for multi-segment and cDNA input. The key algorithm stays the same and differences are very subtle:
\begin{itemize}
  \item There are differences in handling scoring case of \(g_i=g_j\)
  \item Multi-segment non-cDNA input adds special requirement \(d_r\leq D_y\)
  \item cDNA input does not force \(D_y\geq B\)
  \item There are differences in penatly factors for scoring function $E(j,i)$
\end{itemize}

In description below I assume we talk about default case of one-segment, non-cDNA input.

\info{Different kinds of input}{Multi-segment input is in case of Minimap2 described as a situation in which single query maps to different fragments of the reference section. I do not support this use case in BioseqDB out of the box at this time. This situation is also known as split-read or supplementary alignment and normally occurs due to due to structural variations, translocations, or chimeric artifacts in the genome. cDNA in this case describes the same situation, but has slightly different scoring parameters. Even though that can be interesting, we don't want to describe these modes here since those are very specialized heuristics}

\subsection{Skipping with counters and marked anchors}

As discussed above minimap2 scores only valid pairs of anchors:
\begin{equation}
  0<d_r(j,i)\leq D_x,\qquad
  0<d_q(j,i)\leq\min(D_x,D_y),\qquad
  \delta(j,i)\leq B,
  \label{eq:chaining-b1-pair-checks}
\end{equation}
where \(B=\texttt{bw}\) where all parameters like $\texttt{bw}$ are minimap2's CLI arguments.
\[
  D_x=\max(\texttt{max\_dist\_x},B),\qquad
  D_y=\max(\texttt{max\_dist\_y},B).
\]

After a candidate \(j\) passes this checks, we calculate $E(i,j)$ score and then update $p_j$ if we see better score. We want to that $p_j$ was updated in scan for $i$. This can be understood as building chains in parallel where we want to save information about predecessor for each anchor:
\[
  t_{p_j}\gets i \qquad\text{when }p_j\geq0.
\]
If some time later in other scan we see that $t_{p_j}=i$ then we know that $p_j$ was updated in scan for $i$ (we already tested candidate with a larger anchor). If marked anchor \(x\)
fails to improve \(f_i\), then \(s\) increases by one. A failed unmarked anchor leaves \(s\) unchanged. An improvement subtracts one from a positive
\(s\). It does not necessarily reset the counter to zero. The loop stops only when
\(s>\texttt{max\_skip}\)

\info{Interpretation}{This marking with skip counter can be intuitevely understood as a situation in which we try to improve the best chain by adding new anchor. If repeatedly this chain fails to improve the score, we don't want to waste more time on it.}

We don't perform this marking when this is candidate thatraises \(s\) above
\texttt{max\_skip} (in that case we stop the scan loop early).

Minimap2 keeps the loop index in \(e\). If the skip
test stopped the loop while it was processing \(j\), then \(e=j\). $e$ is used to check if we can score anchor $m$ (if $m<e$ then we can).

\(m\) is additional index saved by minimap2 on the side, which we call the
\emph{saved high-score anchor}. The saved value is
an anchor index whose previously calculated \(f_m\) is large. If \(m\) is absent or has left the reference-distance window (is too far),
minimap2 first rebuilds it by finding the largest \(f_j\) in the current
\texttt{max\_iter} set.

This saved anchor can then remain saved after
\(m<i-\texttt{max\_iter}\). Each time we check $e<m$ (see if we already scored this anchor) and if not we calculate $E(m,i)$ and do update checks similar to other anchors.
$m$ is introduced to make sure to take into consideration anchor that could be potentially a little bit further away. Minimap2 doesn't use priority queue or list here, because chaining accuracy is already good enough and this approach is much simpler.

\begin{algorithm}[H]
\caption{Minimap2's ordered predecessor scan for one query segment}
\label{alg:chaining-b1}
\small
\begin{algorithmic}[1]
  \Require sorted anchors \(a_0,\ldots,a_{n-1}\); ordinary non-cDNA mode;
           configured distance limits, \(B=\texttt{bw}\),
           \texttt{max\_iter}, and \texttt{max\_skip}
  \Ensure chain scores \(f_i\) and predecessor indices \(p_i\)
  \State \(D_x\gets\max(\texttt{max\_dist\_x},B)\)
  \State \(D_y\gets\max(\texttt{max\_dist\_y},B)\)
  \Function{CanScore}{\(j,i\)}
    \State \(d_q\gets q_i-q_j,\quad d_r\gets r_i-r_j\)
    \If{\(a_j,a_i\) use different references or strands}
      \State \Return false
    \EndIf
    \If{\(d_r\leq0\) \textbf{or} \(d_r>D_x\)}
      \State \Return false
    \EndIf
    \If{\(d_q\leq0\) \textbf{or} \(d_q>D_x\) \textbf{or} \(d_q>D_y\)}
      \State \Return false
    \EndIf
    \If{\(\lvert d_r-d_q\rvert>B\)}
      \State \Return false
    \EndIf
    \State \Return true
  \EndFunction
  \State \(t_j\gets0\) for every \(j\); \(m\gets-1\); \(st\gets0\)
        \Comment{\(m\) is one saved anchor index}
  \For{\(i\gets0\) \textbf{to} \(n-1\)}
    \While{\(st<i\) and
      (\(a_{st}\) has a different reference or strand from \(a_i\), or
       \(r_i-r_{st}>D_x\))}
      \State \(st\gets st+1\)
    \EndWhile
    \State \(st\gets\max(st,i-\texttt{max\_iter})\)
          \Comment{hard lower bound for the main scan}
    \State \(f_i\gets\ell_i,\quad p_i\gets-1,\quad s\gets0,\quad
            e\gets st-1\)
    \For{\(j\gets i-1\) \textbf{down to} \(st\)}
      \If{\Call{CanScore}{\(j,i\)}}
        \State \(c\gets f_j+E(j,i)\)
        \If{\(c>f_i\)}
          \State \(f_i\gets c,\quad p_i\gets j\)
          \If{\(s>0\)}
            \State \(s\gets s-1\)
          \EndIf
        \ElsIf{\(t_j=i\)}
          \State \(s\gets s+1\)
          \If{\(s>\texttt{max\_skip}\)}
            \State \(e\gets j\)
            \State \textbf{break}
          \EndIf
        \EndIf
        \If{\(p_j\geq0\)}
          \State \(t_{p_j}\gets i\)
              \Comment{mark one older anchor for this scan}
        \EndIf
      \EndIf
    \EndFor
    \If{\(m<0\), or \(a_m\) has a different reference or strand from \(a_i\),
          or \(r_i-r_m>D_x\)}
      \State \(m\gets-1\)
      \For{\(j\gets i-1\) \textbf{down to} \(st\)}
        \If{\(m<0\) \textbf{or} \(f_j>f_m\)}
          \State \(m\gets j\)
        \EndIf
      \EndFor
    \EndIf
    \If{\(m\geq0\) and \(m<e\)}
      \If{\Call{CanScore}{\(m,i\)}}
        \State \(c\gets f_m+E(m,i)\)
        \If{\(c>f_i\)}
          \State \(f_i\gets c,\quad p_i\gets m\)
        \EndIf
      \EndIf
    \EndIf
    \If{\(m<0\), or (\(a_m,a_i\) use the same reference and strand,
          \(r_i-r_m\leq D_x\), and \(f_i>f_m\))}
      \State \(m\gets i\)
    \EndIf
  \EndFor
\end{algorithmic}
\end{algorithm}

\info{Algorithm details}{We check if \(a_{st}\) has a different reference or strand from \(a_i\), because anchors in minimap2 can originate from different refences. In BioseqDB this won't happen, but we still need to check for strand direction. Also please note that formally we use different values for marking $t_{p_j} \gets i$, but it's main goal is just to detect visited anchors for the same scan pass (like in binary map, but assigning $i$ just means that we don't have to clear it.)}


\section{BioseqDB SIMD dynamic programming: exact B1 and bounded B5}
\label{sec:chaining-simd-forward}

The forward pass in \texttt{chaining\_simd\_forward.cppm} contains two
different algorithms.  The \texttt{exact\_visited} policy is the SIMD
implementation of B1.  It produces the same score, predecessor, and stop
position as the scalar loop.  It uses the same marked-anchor rule; SIMD may
write extra marks below the stop position, but those marks are never read.  The
\texttt{bounded\_batch\_}\allowbreak\texttt{approximate} policy is B5.  It
removes the marked-anchor logic and keeps one temporary winner per SIMD lane.
These policies share the vector calculation of \(E(j,i)\), but they do not
share a stopping rule.

Both policies still calculate targets in the order
\(i=0,1,\ldots,n-1\).  This outer loop cannot be run as independent SIMD lanes
because \(f_i\) reads scores calculated for earlier anchors.  SIMD is used
inside one target: the current anchor \(a_i\) is copied to every lane and each
lane receives a different predecessor \(a_j\).

\subsection{Placing predecessor candidates in SIMD lanes}

Let \(st_i\) be the lower end of the predecessor window after applying the
strand and reference-distance window and \texttt{max\_chain\_iter}.  Let \(L\)
be the number of 32-bit Highway lanes.  Batch \(b=0\) is the newest batch.  For
every batch define
\begin{equation}
  e_b=i-bL,
  \qquad
  s_b=\max(st_i,e_b-L),
  \qquad
  a_b=e_b-s_b,
  \qquad
  j_{b,\lambda}=s_b+\lambda .
  \label{eq:chaining-simd-batch-map}
\end{equation}
Only lanes \(0\leq\lambda<a_b\) are active.  A full batch has \(a_b=L\).
Only the oldest batch can be partial.  Inside a vector, lane zero contains the
oldest candidate and lane \(a_b-1\) contains the newest candidate.  Therefore,
whenever exact B1 must reproduce the scalar order, it reads the lanes in the
order \(a_b-1,a_b-2,\ldots,0\).

For an active lane, the SIMD scorer calculates
\begin{equation}
  C_{b,\lambda}=
  \begin{cases}
    f_{j_{b,\lambda}}+E(j_{b,\lambda},i),
      & \text{if \Call{CanScore}{\(j_{b,\lambda},i\)}},\\
    -\infty, & \text{otherwise.}
  \end{cases}
  \label{eq:chaining-simd-candidate-vector}
\end{equation}
An inactive lane also receives \(-\infty\).  This value prevents rejected and
unused lanes from changing a score, a predecessor, or a counter.

\subsection{Exact SIMD B1}

Exact SIMD B1 starts a target with the same scalar state
\((F,P,s)=(\ell_i,-1,0)\).  It does not keep one \(F\) per lane.  After
calculating \(\mathbf C_b\), it builds two masks:
\begin{align}
  X_{b,\lambda}
    &= [C_{b,\lambda}>F],
    \label{eq:chaining-simd-can-improve}\\
  V_{b,\lambda}
    &= [C_{b,\lambda}\neq-\infty]\land[t_{j_{b,\lambda}}=i].
    \label{eq:chaining-simd-visited-hit}
\end{align}
Here \(X\) says that a candidate can beat the target score at the start of the
batch.  The mask \(V\) says that a valid candidate is marked by a newer
candidate's saved predecessor.  Before reading \(V\), the SIMD code writes
\(t_{p_j}\gets i\) for every valid lane with \(p_j\geq0\).  A predecessor
always has a smaller index than its anchor.  The writes can therefore be made
for the whole batch before the decisions without changing which marks the
newest-to-oldest scan observes.

If every element of \(\mathbf X_b\) is false, no candidate in the batch can
change \(F\).  Exact SIMD counts the true elements of \(\mathbf V_b\) at once.
If that count would make \(s\) exceed \texttt{max\_skip}, it reads only the
bits needed to locate the exact candidate where scalar B1 would stop.

If any element of \(\mathbf X_b\) is true, the code copies the pair scores
\(\boldsymbol\epsilon_b=[E(j_{b,\lambda},i)]_\lambda\) and \(\mathbf V_b\) to
small lane arrays.  It then reads those values from the newest lane to the
oldest lane, forms \(C_{b,\lambda}=f_{j_{b,\lambda}}+epsilon_{b,\lambda}\),
and applies the scalar rules:
\begin{equation}
  \begin{aligned}
  C_{b,\lambda}>F
    &\;\Longrightarrow\;
      (F,P,s)\gets
      (C_{b,\lambda},j_{b,\lambda},\max(0,s-1)),\\
  C_{b,\lambda}\leq F\ \land\ V_{b,\lambda}
    &\;\Longrightarrow\; s\gets s+1.
  \end{aligned}
  \label{eq:chaining-simd-exact-control}
\end{equation}
This second step is a one-by-one control pass over SIMD-produced scores.  It
does not call the scalar pair-scoring function.  Strict comparison keeps the
newest predecessor when two candidates give the same total score.  The saved
high-score anchor \(m\), its possible extra score calculation, and its strict
cache update are the same as in scalar B1.  The extra calculation uses the SIMD
scorer with one active lane.

\subsection{Bounded SIMD B5}

B5 replaces \((F,P,s)\) with vectors of lane winners.  Initially,
\(H^{(-1)}_\lambda=\ell_i\) and \(P^{(-1)}_\lambda=-1\).  For batch \(b\),
\begin{align}
  I_{b,\lambda}
    &= [C_{b,\lambda}>H^{(b-1)}_\lambda],
    \label{eq:chaining-b5-improve-mask}\\
  H^{(b)}_\lambda
    &=\begin{cases}
       C_{b,\lambda},&I_{b,\lambda},\\
       H^{(b-1)}_\lambda,&\text{otherwise,}
      \end{cases}
  &
  P^{(b)}_\lambda
    &=\begin{cases}
       j_{b,\lambda},&I_{b,\lambda},\\
       P^{(b-1)}_\lambda,&\text{otherwise.}
      \end{cases}
  \label{eq:chaining-b5-lane-update}
\end{align}
Thus lane \(\lambda\) compares candidates separated by \(L\) array positions
across successive full batches.  The oldest partial batch starts exactly at
\(st_i\), so its final jump can be smaller than \(L\).  An older equal score
does not replace its newer lane winner.

Let \(S=\texttt{max\_chain\_skip}\).  B5 requires \(S>0\) and positive
\texttt{max\_chain\_iter}.  It uses
\begin{equation}
 U=\max\!\left\{1,\left\lfloor\frac{S}{L}\right\rfloor+1\right\}
\label{eq:chaining-batch-limit}
\end{equation}
and updates one shared counter as
\begin{equation}
 u_b=
 \begin{cases}
   0,&\text{if any }I_{b,\lambda}\text{ is true},\\
   u_{b-1}+1,&\text{otherwise.}
 \end{cases}
 \label{eq:chaining-b5-counter}
\end{equation}
When \(u_b\geq U\) and older candidates remain, B5 stops and records the
omitted interval \([st_i,s_b)\).  This interval is used by the saved-anchor
test.  It is not only diagnostic information.  For \(S>0\), the chosen limit
satisfies \(S<LU\leq S+L\).  These are candidate positions grouped into
whole SIMD batches; they are not the marked failures counted by scalar B1.

After the last scored batch, B5 first calculates
\begin{equation}
 f_i=\max_\lambda H_\lambda,
 \qquad
 p_i=\max\{P_\lambda:H_\lambda=f_i\}.
 \label{eq:chaining-b5-horizontal-reduction}
\end{equation}
The second maximum chooses the largest, and therefore newest, predecessor
index on a tie.  If \(f_i=\ell_i\), B5 sets \(p_i=-1\).  If the saved
largest-score anchor \(m\) lies in the omitted interval, B5 scores that one
candidate with one active SIMD lane and accepts it only when it strictly
improves \(f_i\).  One saved candidate cannot recover every possible winner
from the omitted interval.

The saved anchor also differs between the two policies.  Exact B1, like the
scalar algorithm, does not discard \(m\) merely because
\texttt{max\_chain\_iter} moved \(st_i\) past it.  If \(m\) is still in the
same strand and reference-distance window, exact B1 may score it once outside
the main interval \([st_i,i)\).  B5 recomputes \(m\) whenever \(m<st_i\), so
its one-lane check never reaches beyond the \texttt{max\_chain\_iter} window.

\begin{algorithm}[H]
\caption{Bounded SIMD B5 for one target anchor}
\label{alg:chaining-b5}
\small
\begin{algorithmic}[1]
  \Require target \(i\), window \([st_i,i)\), SIMD width \(L\),
           \(S=\texttt{max\_chain\_skip}>0\),
           \(\texttt{max\_chain\_iter}>0\), saved index \(m\)
  \Ensure \(f_i,p_i\)
  \State \(U\gets\max\{1,\lfloor S/L\rfloor+1\}\)
        \Comment{whole-batch stopping limit}
  \State \(\mathbf H\gets[\ell_i]^L,\quad
         \mathbf P\gets[-1]^L,\quad u\gets0\)
        \Comment{one temporary winner per lane}
  \State \(o\gets st_i\)
        \Comment{no omitted interval yet: \([st_i,o)\) is empty}
  \For{\(b\gets0,1,\ldots\) while \(e_b>st_i\)}
    \State calculate \(s_b,e_b,a_b,\mathbf j_b\) using
           Equation~\ref{eq:chaining-simd-batch-map}
    \State \(\mathbf A\gets[\lambda<a_b]_{\lambda=0}^{L-1}\)
          \Comment{mask unused lanes in the oldest partial batch}
    \State \(\boldsymbol\epsilon\gets
           \Call{PairScoreBatch}{\mathbf j_b,i,\mathbf A}\)
          \Comment{\(E(j,i)\), or \(-\infty\) for a rejected pair}
    \State \(\mathbf C\gets
           \Call{Select}{\boldsymbol\epsilon\neq-\infty,
             \mathbf f[\mathbf j_b]+\boldsymbol\epsilon,-\infty}\)
          \Comment{total candidate scores}
    \State \(\mathbf I\gets(\mathbf C>\mathbf H)\)
          \Comment{strict lane-wise improvements}
    \State \(\mathbf H\gets\Call{Select}{\mathbf I,\mathbf C,\mathbf H}\)
    \State \(\mathbf P\gets\Call{Select}{\mathbf I,\mathbf j_b,\mathbf P}\)
          \Comment{equal older candidates do not replace}
    \If{\(\Call{Any}{\mathbf I}\)}
      \State \(u\gets0\)
    \Else
      \State \(u\gets u+1\)
    \EndIf
    \If{\(u\geq U\) and \(s_b>st_i\)}
      \State \(o\gets s_b\)
            \Comment{batch loop omits \([st_i,o)\)}
      \State \textbf{break}
    \EndIf
  \EndFor
  \State \(f_i\gets\Call{HorizontalMax}{\mathbf H}\)
  \State \(\mathbf T\gets\Call{Select}{\mathbf H=f_i,\mathbf P,-1}\)
  \State \(p_i\gets\Call{HorizontalMax}{\mathbf T}\)
        \Comment{largest predecessor index wins a score tie}
  \If{\(f_i=\ell_i\)}
    \State \(p_i\gets-1\)
  \EndIf
  \If{\(m<st_i\) or \(m\) is outside the current reference and strand window}
    \State \(m\gets\operatorname*{arg\,max}_{st_i\leq j<i}(f_j,j)\)
          \Comment{compare score first, then index}
  \EndIf
  \If{\(st_i\leq m<o\)}
    \State \(\epsilon_m\gets\Call{PairScoreOneSIMDLane}{m,i}\)
          \Comment{\(-\infty\) when the pair is rejected}
    \If{\(\epsilon_m\neq-\infty\)}
      \State \(c\gets f_m+\epsilon_m\)
      \If{\(c>f_i\)}
        \State \(f_i\gets c,\quad p_i\gets m\)
      \EndIf
    \EndIf
  \EndIf
  \If{\(m<0\) or \(f_i\geq f_m\)}
    \State \(m\gets i\)
          \Comment{B5 moves the cache to the newer anchor on a tie}
  \EndIf
\end{algorithmic}
\end{algorithm}

\subsection{Where the SIMD work is lost}

SIMD calculates up to \(L\) pair scores with vector instructions.  It does not
make all other work independent between lanes.  The connection to the naive
SIMD minimizer rescan is one simple pattern: an event in one lane can select
extra work or a decision for the whole batch.  In the minimizer algorithm,
lanes hold different sequence chunks.  Here, lanes hold different predecessor
candidates for one target anchor.

\begin{enumerate}
  \item In exact B1, one lane with \(C_{b,\lambda}>F\) makes the code copy the
        batch results to lane arrays and start a newest-to-oldest control
        replay.  The skip limit may stop this replay partway through.  An older
        candidate processed later may no longer improve after a newer candidate
        raises \(F\), but the batch has already taken the replay path.
  \item The pair scorer has a cheap path for a batch in which no lane needs a
        gap penalty.  If one lane needs the penalty, the vector executes the
        diagonal-gap calculation and approximate logarithm for the batch.
        Masks protect the answers, but do not remove those vector instructions
        for the other lanes.  When \texttt{skip\_penalty} is nonzero, the
        scorer also converts the gap length and multiplies it by that value.
        B5 selects a zero-skip-penalty specialization before the target loop
        when \texttt{skip\_penalty} is zero.  This removes only that conversion
        and multiplication; it does not remove the diagonal-gap penalty or
        logarithm.
  \item In B5, one lane improvement resets \(u\) for every lane.  The example
        in Figure~\ref{fig:chaining-b5-batches} shows the important case: the
        lane improves its own saved value, but does not improve the maximum
        across lanes.  B5 still keeps scanning older batches.
  \item Exact B1 gathers \(f_j\), \(p_j\), and \(t_j\) for lanes whose candidate
        index is active even when the pair scorer has already rejected that
        lane by its distance or band tests.  The validity mask prevents a
        rejected lane from changing the result, but the memory reads still
        happen.
  \item Exact B1 writes the marks \(t_{p_j}\gets i\).  It can use one contiguous
        vector store only when every active lane is valid and every saved
        predecessor is \(p_j=j-1\).  One invalid or irregular lane makes the
        batch use indexed stores instead.
\end{enumerate}

For a full batch, suppose a per-lane event has the same probability \(p\) in
every lane and treat the lanes as independent only for a simple model.  The
probability that at least one lane selects the shared path is
\begin{equation}
  1-(1-p)^L.
  \label{eq:chaining-simd-shared-path-probability}
\end{equation}
For a partial batch, \(L\) is replaced by the active-lane count \(a_b\).
This model applies separately to ``a lane needs a penalty'', ``a lane can
improve exact B1'', and ``a lane improves its B5 lane winner''.  Nearby anchors
are not independent in real data, so
Equation~\ref{eq:chaining-simd-shared-path-probability} only shows why one lane
can make a shared path common; it does not predict a measured rate.

There are two smaller sources of unused lanes.  The oldest partial batch masks
at most \(L-1\) lanes.  A saved-anchor calculation uses one lane and masks the
remaining \(L-1\).  Exact B1 can also score past the scalar stopping point
inside the batch where \texttt{max\_skip} is exceeded.  Let \(x_i\) be the
number of candidate positions examined by scalar B1's main predecessor loop
for target \(i\), and let \(y_i\) be the number scored by exact SIMD's main
batch loop.  The separate saved-anchor check is excluded from both counts.
Then
\begin{equation}
  x_i\leq y_i\leq x_i+L-1.
  \label{eq:chaining-simd-extra-stop-work}
\end{equation}
The extra scores are ignored.  Their temporary generation marks cannot affect
a later target because the next target uses a different mark value.  The
saved-anchor check can add one further vector call with only one active lane;
it can also repeat a pair score that was calculated speculatively in the stop
batch.

Pair-score arithmetic in the main loop uses
\(\lceil y_i/L\rceil\) vector batches for target \(i\), plus at most one
one-lane saved-anchor call.  Exact B1 may nevertheless perform
\(\Theta(y_i)\) scalar control steps when many batches enter the ordered replay.
If \(M=\texttt{max\_chain\_iter}\), the complete forward pass therefore still
has an \(O(n(1+M))\) worst-case bound for fixed hardware width \(L\).  Writing
\(O(nM/L)\) would not give a different asymptotic class when \(L\) is fixed;
the practical point is that an \(L\)-fold speedup is not guaranteed.

B5 removes the ordered replay, but one lane can keep resetting the shared
counter until the loop has covered all \(M\) candidate positions.  Its stopping
rule can inspect fewer or more candidates than exact B1, and it can therefore
select a different predecessor.  B5 is a speed and accuracy trade-off, not an
exact SIMD spelling of scalar B1.

\section{B2: G3SA source-to-target dynamic programming}
\label{sec:chaining-b2}

B1 selects one target \(i\) and examines earlier anchors. B2 selects one source
anchor \(j\) and lets GPU threads update many later targets \(i\). Sources are
processed in increasing order so \(f_j\) can no longer change before it is
used. Updates from one source to different targets can run in parallel.

G3SA reads \(r_i\) from the low 32 bits of \texttt{anchors\_x[i]}. It reads
\(q_i\) from the low 32 bits of \texttt{anchors\_y[i]}. Both values are
interpreted as signed 32-bit integers.

G3SA provides a short-range kernel and a tiled kernel for longer
ranges. The tiled kernel loads a block of source anchors into shared memory.
It first calculates the source scores inside that block in index order. It then
uses those completed scores to update later targets held in registers. Both
kernels implement the intended B2 update. The short and tiled kernels use
different tie orders and distance-boundary checks, described below. The two
tiled launch configurations select different thread counts.

\section{B3: G3SA ranking-value second pass}
\label{sec:chaining-b3}

The G3SA wrapper names the second CUDA pass RMQ. The called CUDA kernel stores
ranking values in arrays. For every source anchor \(j\), it calculates
\begin{equation}
 H_j=f_j+\frac{\lambda_g}{2}(r_j+q_j).
\label{eq:chaining-b3-priority}
\end{equation}
We use \(H_j\) only to rank possible predecessors. It does not include the
pair-specific reward or penalty. GPU threads compare \(H_j\) with the value
saved for each later target that passes the checks below. A target can save at
most one predecessor. When processing reaches a target with a saved
predecessor, the kernel calculates and stores that predecessor's full integer
score.

B3 accepts a source-target pair only when the query coordinate advances by at
most \(20{,}000\) bases, both anchors belong to the same reference sequence and
strand, and their reference coordinates differ. The short kernel considers at most
\(5{,}000\) later anchors and also limits their reference difference to
\(20{,}000\) bases. The first phase within each \(1{,}024\)-anchor tile compares
every source-target pair inside that tile. When the tile updates later targets,
it measures its stopping distance from the tile's last source. An earlier
source can therefore be compared with a target more than \(20{,}000\) reference
bases away. The short kernel compares
ranking values with double-precision arithmetic before storing a float. The
tiled kernel compares floats in both launch configurations. These numeric and
distance-check differences can make
the short and tiled B3 kernels choose different predecessors.
In the pseudocode, \(E_3(j,i)\) is
Equation~\ref{eq:chaining-link-score} evaluated with B3's pair checks and
parameter values.

\section{B4: augmented-tree RMQ dynamic programming}
\label{sec:chaining-b4}

B4 replaces the full predecessor scan with a balanced tree keyed by
\((q_j,j)\). An AVL tree is a height-balanced binary search tree. Minimap2
stores
\begin{equation}
 \pi_j=-H_j,
 \qquad
 H_j=f_j+\frac{\lambda_g}{2}(r_j+q_j),
\label{eq:chaining-rmq-priority}
\end{equation}
Here \(r_j\) and \(q_j\) denote the low 32 bits of minimap2's packed reference
and query coordinates, interpreted as signed 32-bit integers.
A range-minimum query on \(\pi\) returns a range maximum of \(H\). Each node
also stores the smallest \(\pi\) value in its subtree. This cached value lets
one range query skip every node in a fully covered subtree. Anchors at the current
reference coordinate are inserted only after the scan reaches a later
reference coordinate. An equal-reference anchor is not yet in the tree and
cannot be selected.

The primary query uses the closed composite-key interval
\begin{equation}
 \bigl[(q_i-\texttt{max\_dist},\mathrm{INT32\_MAX}),\,(q_i,0)\bigr].
\label{eq:chaining-rmq-key-range}
\end{equation}
At the lower query-coordinate boundary it admits only indices
\(j\geq\mathrm{INT32\_MAX}\). At the upper boundary it admits only \(j\leq0\),
which means index zero because anchor indices are nonnegative. Active keys
strictly between the two query coordinates lie inside the interval. If the
interval contains an active key, the outer query returns an anchor whose stored
\(\pi_j\) is minimum in the interval. Minimap2 then performs the full link
calculation and bandwidth check. If the returned predecessor has equal
reference and query gaps that fit within the predecessor span, no gap penalty
is needed. Otherwise,
when the inner tree is enabled and the signed low-32-bit value of \(q_i\) is
positive, minimap2 scans its anchors in descending \((q_k,k)\) order and stops when
\(q_i-q_k>\texttt{max\_dist\_inner}\). The primary query takes
\(O(\log n)\) time. The inner scan may examine several anchors, so total work
can exceed \(O(n\log n)\).

\caption{B4 augmented-tree RMQ chaining}
\label{alg:chaining-b4}
\small
\begin{algorithmic}[1]
  \Require sorted anchors, \texttt{max\_dist}, tree capacity,
           \texttt{max\_dist\_inner}, bandwidth, and \texttt{max\_skip}
  \Ensure scores \(f_i\) and predecessors \(p_i\)
  \State initialize the augmented outer tree and optional inner tree
  \State initialize temporary generation marks \(t_j\gets0\) for every anchor
         \(j\)
  \For{target \(i\) in coordinate order}
    \State insert completed earlier-reference groups with key \((q_j,j)\)
           and priority \(\pi_j\)
    \State erase anchors outside the active window and enforce tree capacity
    \State \(f_i\gets\ell_i,\quad p_i\gets-1\)
    \State \(j\gets\) outer-tree result from keys
           \((q_i-\texttt{max\_dist},\mathrm{INT32\_MAX})\) through
           \((q_i,0)\)
    \If{\(j\geq0\)}
      \State calculate \(c\gets f_j+E(j,i)\) and its diagonal width
      \If{\(c>f_i\) and the width is within the bandwidth}
        \State \(f_i\gets c,\quad p_i\gets j\)
      \EndIf
      \If{the inner tree is enabled, the signed low-32-bit value of \(q_i\)
           is positive, and either the reference and query gaps differ or
           their shared gap exceeds \(\ell_j\)}
        \State \(s\gets0\)
        \For{candidate \(k\) in descending \((q_k,k)\) order below \(q_i\)}
          \If{\(q_i-q_k>\texttt{max\_dist\_inner}\)}
            \State stop the inner scan
          \EndIf
          \State calculate \(c_k\gets f_k+E(k,i)\) and its diagonal width
          \If{\(c_k>f_i\) and the width is within the bandwidth}
            \State \(f_i\gets c_k,\quad p_i\gets k,\quad s\gets\max(0,s-1)\)
          \ElsIf{the width is within the bandwidth and generation mark
                 \(t_k=i\)}
            \State \(s\gets s+1\)
            \If{\(s>\texttt{max\_skip}\)}
              \State stop the inner scan
            \EndIf
          \EndIf
          \If{the width is within the bandwidth and \(p_k\geq0\)}
            \State \(t_{p_k}\gets i\)
          \EndIf
        \EndFor
      \EndIf
    \EndIf
    \State leave \(i\) pending until its equal-reference group is complete
  \EndFor
\end{algorithmic}
\end{algorithm}

cached \(\pi_j\) values, and its inner scan follows query-key order. Equal

\section{B6: Vulkan per-target batch-limited dynamic programming}
\label{sec:chaining-b6}

B6 scores predecessors in batches and keeps one best score for the target. The
current Vulkan shader uses 32 candidates per batch. Let
\(S\) be the configured skip value. Its batch limit is
\begin{equation}
 U_{\mathrm{GPU}}=
 \begin{cases}
 \left\lfloor S/32\right\rfloor+1, & S>0,\\
 \infty, & S\leq0.
 \end{cases}
\label{eq:chaining-vulkan-batch-limit}
\end{equation}
B5 resets its counter when any vector element's saved score increases. B6
resets its counter only when the target's maximum score increases. A candidate
can therefore reset B5 without resetting B6. A non-positive skip value
disables the B6 batch cutoff.

\subsection{Constructing chains from saved predecessors}

All six algorithms save one score and one predecessor for each anchor.
Minimap2 and BioSeqDB sort qualifying anchor indices by score and then by
index. They process larger scores first and larger indices first when scores
tie. They follow predecessor indices from newest to oldest, then reverse the
collected anchors into oldest-to-newest order. They mark anchors while
following predecessor indices. A predecessor trace later rejected for low
score or too few anchors remains marked and cannot be selected from another
start.

While following predecessors from ranked start \(k\), minimap2 calculates
\(s=f_k-f_i\) at predecessor \(i\). It records the predecessor at the largest
observed \(s\) and stops searching when the largest \(s\) minus the current
\(s\) exceeds \(\texttt{max\_drop}\). The threshold equals the pass bandwidth.
B1 cDNA mode sets it to \(\mathrm{INT32\_MAX}\). Minimap2 copies accepted
chains into one array and sorts them by the packed \(x\) key of their first
anchor. This key contains strand, reference identifier, and reference
position. G3SA filters chains by score and anchor count, follows predecessors,
copies accepted anchors, and labels mappings as primary or secondary. BioSeqDB
uses CPU or SIMD chain construction. These stages consume the saved \(f_i\)
and \(p_i\) values and determine the emitted mappings.

\section{How minimap2 composes B1 and B4}
\label{sec:chaining-minimap2}

Minimap2 selects its first chaining algorithm from the \texttt{MM\_F\_RMQ}
flag. The non-RMQ route runs B1. The RMQ route runs B4. Both routes pass their
saved scores and predecessors to the same chain-construction code.
The default options and the \texttt{map-ont} preset use B1. Assembly presets
and \texttt{lr:hqae} enable B4. An explicit RMQ option also selects B4, but
minimap2 rejects that option together with short-read or splice mode.
\coderef{minimap2/map.c}{Chaining composition in mapping}{mm_map_frag_core}{275}

B1 uses the request-specific reference and query distance limits, including
\texttt{max\_gap\_ref}. The caller passes \texttt{max\_gap} to both B4 calls.
Inside B4, the tree distance is raised to the bandwidth when the bandwidth is
larger. The second pass changes the bandwidth and therefore also changes the
effective tree distance when that new bandwidth is larger.

After initial chaining, minimap2 can run at most one additional pass. The
long-read eligibility test requires a wider configured bandwidth, one query
segment, more than one initial chain, and no splice, short-read, or
disabled-long-join flag. Let \(c=q_{\mathrm{last}}-q_{\mathrm{first}}\), using
the query coordinates of the first and last anchors in the first returned
chain. Let \(L_q\) be the total query length, \(T_s\) the configured size
threshold, and \(T_r\) the configured fraction. If long-read eligibility holds,
minimap2 runs B4 only when \(L_q-c>T_s\) or \(c>T_rL_q\). If this test fails,
it performs no additional chaining.

The wider B4 pass receives only anchors retained in the initial chains.
Minimap2 concatenates those anchors, sorts them by packed \(x\) key, and chains
them again.

Only when the long-read condition fails can minimap2 collect seed hits again
using \(\texttt{max\_occ}\) instead of \(\texttt{mid\_occ}\), then repeat B1.
This branch requires \(\texttt{max\_occ}>\texttt{mid\_occ}\),
\(\texttt{rep\_len}>0\), and an initial B1 pass. Here \(\texttt{rep\_len}\) is
the total query length covered by filtered seeds. B1 repeats only when no chain
exists or the highest-scoring chain omits a query segment.

query segment, multiple initial chains, and the displayed threshold test. The

\(\texttt{max\_occ}>\texttt{mid\_occ}\), a positive repetitive-query length

By default, the main B1 scan visits at most \(5{,}000\) candidates. It uses
\(\texttt{max\_skip}=25\) and may calculate one additional score for cached
predecessor \(m\). Because improvements can decrement the counter, the
scan can examine more than 26 marked candidates before the counter first
reaches 26. The maximum gap is \(5{,}000\) bases and the diagonal bandwidth is
500 bases. B4 uses a \(1{,}000\)-base inner range and allows at most
\(100{,}000\) tree nodes. If initial B4 is explicitly selected with otherwise
default values, it uses a \(5{,}000\)-base tree distance and a 500-base bandwidth.
The optional wider B4 pass uses a \(20{,}000\)-base tree distance and bandwidth.
Its default thresholds are \(T_s=1{,}000\) bases and \(T_r=0.10\). A chain must
contain at least three anchors and have a score of at least 40.

The B1 implementation also tracks cached predecessor \(m\). After the main
scan, if \(m\) lies outside the active reference window, minimap2 replaces it
with the newest maximum-score anchor among the newest \texttt{max\_iter}
candidates. It calculates one full link score when \(m\) exists and the main
scan does not reach it. Strict comparison preserves the selected predecessor
on a tie.

In B4, the augmented AVL node stores a key, a priority, and a pointer to the

\section{How G3SA composes B2 and B3}
\label{sec:chaining-g3sa}

G3SA runs B2 on every range produced by splitting at reference gaps. It follows
saved predecessors to form chains. A chain is retained only if it contains at
least three anchors and has a score of at least 40. This first chain-construction
pass uses a maximum score drop of zero and copies retained anchors into a
contiguous array. A per-read test in \texttt{mm\_gen\_regs\_dp} then decides
whether to run B3. Before this test, G3SA orders retained chains by their first
reference coordinate. Let \(L_q\) be the query length, and let
\(c=q_{\mathrm{last}}-q_{\mathrm{first}}\) for the first chain in that order. A
read enters B3 only when more than one chain remains and either
\(L_q-c>1{,}000\) or \(c>0.10L_q\). Reads that fail this test emit mapping
records after the first chain-construction pass. Selected reads sort their
retained anchors and run B3. G3SA then follows saved predecessors again using
the same count and score thresholds and a maximum score drop of \(20{,}000\).

The start and end indices are inclusive, so a range with
\(d=\textit{end}-\textit{start}\) contains \(d+1\) anchors. Short ranges contain
at most 513 anchors and use 32 threads. Medium ranges contain 514 to
\(5{,}121\) anchors and use 512 threads. Longer ranges use 1024 threads. Both
tiled classes use \(1{,}024\)-anchor source tiles. Each source score is complete
before it is copied to later targets. The wrapper copies the counts of medium
and long ranges to the host before launching their kernels.

B3 uses the same short, medium, and long range-size cases as B2. It compares
\(H_j\) for targets that pass the B3 checks, keeps at most one predecessor
distance for each target, and later calculates the full integer score when a
predecessor was saved.

Within one read, predecessor distances must be followed in sequence because
each one identifies the next older anchor relative to the current index.
Different reads can still be processed in parallel. G3SA's bundled minimap2
source also omits the extra score calculation
for cached predecessor \(m\). A CPU result from that bundled source can
therefore differ from current upstream minimap2.

\section{BioSeqDB implementation}
\label{sec:chaining-bioseqdb}

BioSeqDB stores anchors as consecutive 24-byte records. Each record keeps all
fields for one anchor together, a layout called an array of structures. The
fields are the reference coordinate, query coordinate, strand, span, flags,
and segment identifier. Every CPU route reads the same canonical anchor order
and saves one score and one predecessor per anchor.

\subsection{B1 CPU implementations}

The scalar implementation in \texttt{scalar.cppm} follows the ordered B1
loop. It is the default selected by \texttt{minimap2\_parameters} and the
PostgreSQL configuration. The lower-level \texttt{chaining\_parameters}
structure defaults to \texttt{simd\_dp} with the
\texttt{exact\_visited} mode. This structure is internal, and the high-level
request overwrites its algorithm and mode before execution.

The exact SIMD implementation in
\texttt{chaining\_simd\_forward.cppm} calculates a vector batch of independent
pair scores and then applies score and predecessor updates in B1 order. It
produces the same chains as BioSeqDB scalar B1 for the same anchors and
parameters. Its final mappings can still differ from minimap2 because BioSeqDB
uses the chain-construction rules described next.

BioSeqDB's shared chain-construction stage omits minimap2's
maximum-score-drop test and target-coordinate sort. It leaves final chains in
descending order of the score at each chain's final anchor. When these scores
tie, the chain with the larger final-anchor index appears first.

Scalar and RMQ subtract the 64-bit coordinates and then cast each link delta to
a signed 32-bit value. Exact and bounded SIMD first copy the low 32 bits of
each coordinate into separate coordinate arrays, then use 32-bit modular
subtraction. Both coordinate-arithmetic paths require every scored link delta to fit the signed
32-bit range. Vulkan checks the original 64-bit distances first.

\subsection{B5 bounded CPU mode}

The bounded CPU implementation scores full SIMD batches and one partial final
batch whose unused vector elements are ignored. It applies the limit in
Equation~\ref{eq:chaining-batch-limit} and stops
after the configured number of consecutive batches leave every element's
running score unchanged. If the omitted candidates include the cached
maximum-score anchor in the current \texttt{max\_chain\_iter}-limited predecessor
window, the CPU implementation calculates that one score before storing
\(f_i\) and \(p_i\).

The cached predecessor index also has a B5-specific tie rule. When a new
anchor has the same saved score, B5 moves the cache to the new anchor. Scalar
and exact SIMD B1 keep the previously cached anchor. After an early stop, this
difference can change which omitted candidate receives the extra score
calculation.

An explicit SQL SIMD request selects bounded B5. Exact SIMD is available
through the C++ parameter layer but has no direct SQL selector. For any
non-SIMD algorithm, the dispatcher resets the unused SIMD mode field to
\texttt{exact\_visited} so a value from an earlier request cannot carry over.
Benchmarks must state which SIMD mode they execute.

\subsection{B6 Vulkan mode}

The current Vulkan shader evaluates 32 predecessors together in each batch and
implements B6. For one target it examines at most
\(\min\{\texttt{max\_chain\_iter},3{,}000\}\) predecessors. Let
\(D=\max\{\texttt{max\_gap},\texttt{bandwidth}\}\). BioSeqDB starts a new
processing range at a strand change or when the adjacent reference gap exceeds
\(D\). For a range of \(N>131{,}072\) anchors, it uses stride
\(\lceil N/65{,}536\rceil\), retains the first and final anchors, and retains at
most \(65{,}537\) anchors in total. The Vulkan implementation does not perform
the extra predecessor-score calculation used by CPU B5. The dispatcher names
this B6 shader \texttt{g3sa-tiled-dp}. Both metadata records for this shader
set \texttt{uses\_max\_chain\_skip=false}, even though the shader reads
\texttt{max\_chain\_skip}.

BioSeqDB has two Vulkan result paths. One follows predecessor indices on the
GPU and returns mapping coordinates. It examines at most 16 candidate chain
starts, so it can miss a qualifying start outside those 16. The other returns all saved
scores and predecessors, then constructs chains on the CPU. If Vulkan is
selected and either path fails, the request returns an error.

\subsection{B4 RMQ port}

The RMQ module in \texttt{rmq.cppm} implements an AVL tree with cached subtree
minima, active-window insertion and deletion, and a primary range query. Its
lower query key is \((q_i-\texttt{max\_dist},\mathrm{INT64\_MIN})\). Its
upper query key is \((q_i,\mathrm{INT64\_MAX})\). The range includes both
query-coordinate boundaries. The dispatcher supplies an inner distance of zero, so the
inner refinement tree is disabled.

\warn{Experimental RMQ route}{The primary tree query includes both
query-coordinate boundaries, including anchors with the same query coordinate
as the target. BioSeqDB accepts a strict score improvement without checking the
configured diagonal bandwidth. No direct RMQ unit test covers these cases.
Validate RMQ results separately before comparing them with B1 results.}

BioSeqDB RMQ uses signed 64-bit query keys and converts full coordinates to
\texttt{double} for the tree priority. Minimap2 uses signed low-32-bit
coordinate values for both. Their candidate order can differ after a
coordinate crosses the signed 32-bit boundary.

The configuration layer exposes \texttt{max\_gap\_ref} and
\texttt{bandwidth\_long}, but the chaining parameter copy omits them. The
dispatcher performs exactly one forward chaining call per request, using the
selected initial algorithm. The wider-band B4 pass and frequent-anchor B1
repeat in Figure~\ref{fig:chaining-minimap2-flow} are absent.

\section{Summary}

Six high-level algorithms account for the inspected implementations. B1 is
the ordered predecessor scan used by minimap2, BioSeqDB scalar CPU, and BioSeqDB
exact SIMD.
B2 is G3SA's source-to-target update. B3 is G3SA's ranking-value second
pass. B4 is the augmented-tree RMQ method used by minimap2. BioSeqDB's
experimental RMQ route follows the B4 tree structure but includes both query
boundaries and omits the bandwidth check described above. B5 is BioSeqDB's
per-element batch limit on CPU SIMD. B6 is its per-target batch limit on
Vulkan.

Minimap2 starts with B1 or B4 and may run one of two mutually exclusive
additional passes. G3SA runs B2 for every read and runs B3 for reads that pass
its second-pass test. BioSeqDB selects scalar B1 by default, bounded B5 through
explicit SQL SIMD, experimental B4 through RMQ, and B6 through Vulkan. Exact
SIMD B1 is available through the C++ API. In report 192, both SIMD modes had
lower measured chaining times than scalar B1. The report contains only two
observations per mode and was produced with uncommitted source changes, so it
provides limited performance evidence.
