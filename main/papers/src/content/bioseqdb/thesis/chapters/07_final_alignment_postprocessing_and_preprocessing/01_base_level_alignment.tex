
\section{From a seed chain to a base-level alignment}
\label{sec:final-alignment-role}

Chaining identifies a plausible correspondence between query and target
positions. Final alignment resolves the bases between the anchors: it assigns
a score and, when requested, reconstructs the substitutions, insertions and
deletions as a CIGAR. This is the dynamic-programming problem introduced in
Section~\ref{sec:exact-dp}. BioseqDB divides a chained region into an extension
on each flank and fills between selected anchors. Consequently, the number
and geometry of these subproblems matter as well as the total read length.

\subsection{The two CPU alignment contracts}
\label{sec:final-alignment-cpu-contracts}

KSW2 and Block Aligner both use SIMD, but they do not search the same set of
matrix cells or implement the same scoring contract. KSW2 supports two affine
gap penalties, a fixed band and Z-drop stopping. Z-drop allows extra score
loss when the path moves away from its previous diagonal, so that a long gap
need not stop an extension immediately. The ordinary gap-fill path also uses
an approximate maximum; requests for an exact edit count disable its band
and Z-drop restrictions.

Block Aligner uses the first affine gap penalty and a block that moves,
grows and shrinks through the matrix~\cite{block_aligner_paper}. Fills between
anchors use its global mode; flanks use its own X-drop rule, which requires
two consecutive low-scoring steps. The current pipeline supplies minimum
and maximum block sizes of 16 and 32. Increasing these limits can explore
more cells around gaps, at the cost of more work and trace storage. Neither
the read length nor an end-to-end timing alone establishes which limits
should be changed.

\label{sec:final-alignment-fused-work}
The implementation also tries to prove that an equal-length gap has a unique
straight-diagonal optimum before running Block dynamic programming. A
successful proof produces the score and trace directly; other gaps still use
the adaptive recurrence. This shortcut has its own geometry, sequence-storage
and scoring restrictions. Both aligners otherwise combine dynamic
programming, trace storage, traceback and CIGAR construction in one invocation.
A timer surrounding that invocation therefore measures more than output
formatting. Equal match counts do not establish equal CIGARs, scores or
search effort between the two contracts.

% deletions between those anchors. Final alignment resolves this remaining
% ambiguity. It refines the outer coordinates, assigns a dynamic-programming

% a static band, Z-drop, and minimap-style endpoint rules. Block Aligner uses a

% \section{Affine-gap dynamic programming}
% \label{sec:final-alignment-affine}

% Let \(Q=q_1\ldots q_n\) be a query and \(T=t_1\ldots t_m\) a target interval.
% For substitution score \(s(q_i,t_j)\), an affine gap of length \(k\geq 1\)
% has penalty
% \[
%     g(k)=q+ke,
% \]
% where \(q>0\) is the gap-open penalty and \(e>0\) is the extension penalty.
% The first gap symbol therefore costs \(q+e\). With query positions on the
% vertical axis and target positions on the horizontal axis, the global
% Needleman, Wunsch, and Gotoh recurrence is
% \begin{align}
%  I(i,j) &= \max\{H(i-1,j)-q-e,\ I(i-1,j)-e\},
%  \label{eq:affine-i}\\
%  D(i,j) &= \max\{H(i,j-1)-q-e,\ D(i,j-1)-e\},
%  \label{eq:affine-d}\\
%  H(i,j) &= \max\{H(i-1,j-1)+s(q_i,t_j),\ I(i,j),\ D(i,j)\}.
%  \label{eq:affine-h}
% \end{align}
% The insertion and deletion states record whether a path already ends in a
% gap. A global fill initializes both axes with cumulative gap costs. An
% extension changes the boundary and endpoint rules while retaining the same
% cell recurrence. A full matrix takes \(O(nm)\) time and \(O(nm)\) trace memory
% when every decision is retained \cite{gotoh_1982_affine}.

% The default nucleotide model uses match score \(a=2\), mismatch penalty
% \(b=4\), and two affine families
% \[
%    (q_1,e_1)=(4,2), \qquad (q_2,e_2)=(24,1).
% \]
% KSW2 assigns a gap the lower of the two costs,
% \[
%     g(k)=\min\{4+2k,\ 24+k\}.
% \]
% The short family is cheaper below length 20, both are equal at 20, and the
% long family is cheaper above 20. The recurrence keeps two insertion states
% and two deletion states:
% \begin{align}
%  I_r(i,j)&=\max\{H(i-1,j)-q_r-e_r,\ I_r(i-1,j)-e_r\},\\
%  D_r(i,j)&=\max\{H(i,j-1)-q_r-e_r,\ D_r(i,j-1)-e_r\},
%  \qquad r\in\{1,2\},\\
%  H(i,j)&=\max\{H(i-1,j-1)+s(q_i,t_j),
%  I_1,I_2,D_1,D_2\}.
% \end{align}
% This model charges short sequencing errors and long gaps differently. Block
% Aligner instead uses only the first affine family. Selecting Block Aligner is
% therefore a scoring choice as well as a performance choice.

% \subsection{Banding and stopping criteria}

% Anchors suggest an expected diagonal \(d_0\). KSW2 can restrict evaluation to
% cells satisfying
% \[
%         |(i-j)-d_0|\leq w,
% \]
% where \(w\) is the half-width of the band. Work is then approximately
% \(O(w(n+m))\), but an optimum that leaves the band cannot be recovered. The
% ordinary alignment width is derived from the chaining width as
% \[
%         w_{\mathrm{align}}=\lfloor 1.5w_{\mathrm{chain}}+1\rfloor.
% \]

% Z-drop terminates an extension whose score has deteriorated sufficiently from
% the best cell. If \(S^\star\) is the best score at
% \((i^\star,j^\star)\), termination is permitted when
% \begin{equation}
%  S^\star-S(i,j)>
%  Z+e_z\left|(i-i^\star)-(j-j^\star)\right|.
%  \label{eq:zdrop}
% \end{equation}
% The displacement term allows a long gap to move away from the best diagonal
% without receiving the same stopping penalty as a score loss along that
% diagonal. In the two-piece kernel, \(e_z\) is the long-gap extension penalty.
% Block Aligner does not use this rule. Its outer extensions apply X-drop and
% require two consecutive steps below the threshold before stopping.

% For mandatory KSW2 fills used by an exact edit predicate, banding and Z-drop
% are disabled. This prevents the path between two fixed anchors from ending
% early. The outer candidate window and the selected chain still constrain the
% search, so this setting does not turn the complete mapping task into an
% unbounded full-matrix comparison.

% Each phase returns a score, consumed lengths, endpoint information, and an
% optional trace. A non-dropped global fill consumes both slices. Ordinary KSW2
% fills may instead stop under Z-drop and use their maximum-scoring positions as
% truncated endpoints. Exact-edit KSW2 disables Z-drop. An extension may consume
% only a prefix of the available oriented slices, which moves the
% reported outer coordinate to its selected endpoint. The region result is
% formed by adding phase scores and concatenating phase traces in coordinate
% order. Reversing the left input changes the direction of computation, but not
% the final order of the reported path.

% Stopping state is also phase-specific. A KSW2 Z-drop in an earlier phase can
% suppress a later right extension because the minimap-style control flow treats
% the region as dropped. Block global fills do not use Z-drop. Its left and
% right X-drop extensions are separate searches, so the right extension remains
% eligible after an earlier Block phase. This is a material behavioural
% difference and is retained as a backend rule rather than normalised through a
% shared option.

% The port differs from minimap2 in its supported policy surface. It implements
% the ordinary DNA seed-gap and end-extension structure, but not the splice,
% RNA, inversion-retry, or long-join policies. It also obtains slices from lazy
% sequence representations, including reverse-oriented slices, without first
% copying a complete region. These differences concern the surrounding
% pipeline. The KSW2 recurrence remains recognisable, while Block Aligner uses a
% separate phase contract instead of imitating KSW2 options that it does not
% support.

% \subsection{Difference representation}

% A direct SIMD implementation stores absolute \(H\), \(I\), and \(D\) scores.
% Absolute values grow with sequence length and may require wide lanes. KSW2
% uses the Suzuki and Kasahara observation that differences between neighbouring
% scores remain bounded by the scoring parameters even when the absolute score
% is large \cite{suzuki_kasahara_2018}. Representative differences are
% \[
%     U(i,j)=H(i,j)-H(i-1,j), \qquad
%     V(i,j)=H(i,j)-H(i,j-1).
% \]
% The main recurrence operates on signed byte values derived from these
% differences. Wider scores are reconstructed where exact maxima and endpoints
% are needed. More cells therefore fit in each SIMD vector.

% BioSeqDB expresses this recurrence with portable SIMD operations. Lanes hold
% cells from one alignment problem, usually along an anti-diagonal. This is
% intra-sequence parallelism. It differs from placing several independent
% sequence pairs in the lanes of one vector. A single-affine specialization is
% used when the two penalty pairs are equal. The default parameters select the
% two-piece specialization, with four gap states and their continuation bits.
% Trace decisions are stored for cells inside the admitted band.

% endpoint, with the query-end score and end bonus considered by the selected
% mode. A left extension is computed on reversed slices, after which its CIGAR

% \section{Traceback, CIGAR, and edit counting}
% \label{sec:final-alignment-cigar}

% All alignment routes cross their low-level boundary using packed CIGAR runs
% of the form
% \[
%         \mathit{word}=(\mathit{length}\ll4)\mid\mathit{opcode}.
% \]
% The common opcodes include \(M\) for a diagonal step, \(I\) for an insertion,
% \(D\) for a deletion, and the more explicit equality and mismatch variants
% \(=\) and \(X\). A run records one opcode and its length. Adjacent equal runs
% are merged within a traceback and across phase boundaries.

% The forward calculation and backward trace have separate roles. The forward
% pass selects scores and endpoints. The trace reconstructs the path through
% diagonal and gap states. KSW2 records decisions for its admitted band. Block
% Aligner records decisions for computed strips. The GPU route either retains a
% bounded direction matrix or reconstructs directions tile by tile. All three
% then produce the same run-oriented interface.

% A generic \(M\) run does not reveal whether its diagonal symbols are equal.
% The edit count is therefore computed from the emitted path and the
% corresponding sequence symbols:
% \[
%  E_{\mathrm{path}}=
%  \#\{\text{unequal diagonal steps}\}
%  +\sum_{I\text{ runs}}\mathit{length}
%  +\sum_{D\text{ runs}}\mathit{length}.
% \]
% Block Aligner counts unequal diagonal steps during traceback, while KSW2 can
% replay diagonal runs against the sequence ranks. These CPU routes return the
% unit-cost edit count of the chosen path. It is distinct from the affine score
% and from a seed-derived estimate.

% The CIGAR also defines coordinate consumption. A diagonal run consumes query
% and target symbols, an insertion consumes query symbols, and a deletion
% consumes target symbols. Replaying these rules checks the reported span and
% allows CPU routes to derive aligned lengths and edit count. The complete GPU
% route currently returns CIGAR and match counts, but it does not expose the
% chosen-path edit-count field or accept an exact edit predicate. Reverse-strand
% coordinates are converted only after the phase CIGARs have been assembled in
% alignment order.

% \section{Accelerator boundary and gridded traceback}
% \label{sec:final-alignment-gpu}

% The GPU route begins after candidate windows have been chosen by GPU seeding
% and chaining. If a query needs coordinates only, those windows can be returned
% without base alignment. If it needs CIGAR, each selected query and target
% window is packed as symbol ranks and submitted as one job in a batch. The
% result contains score, endpoints, status, and a slice of packed CIGAR runs.

% This route has an explicit ownership boundary. Its configuration must select
% the complete GPU frontend and an admitted base-alignment identity. The latter
% does not mean that the CPU Block Aligner recurrence runs on the device. It is
% a route selection condition. The general CIGAR kernel uses its own two-piece
% affine global recurrence over the selected coordinate window. Unsupported
% geometry or an unavailable GPU component rejects the route instead of
% continuing with a CPU alignment under the same label.

% Conventional GPU traceback writes one direction value for every computed
% cell. G3SA reduces this traffic by retaining score states at tile boundaries
% and recomputing directions only for tiles reached by the final path
% \cite{g3sa_paper}. BioSeqDB applies the same memory principle in Vulkan. The
% forward pass stores five affine score states along tile borders. Starting from
% the global endpoint, traceback reloads a border, recomputes one tile in fast
% memory, traces to the next boundary, and discards the temporary directions.
% For tile dimensions \(b_q\) and \(b_t\), border storage is proportional to
% \[
%   \left\lceil\frac{n}{b_q}\right\rceil
%   \left\lceil\frac{m}{b_t}\right\rceil
%   \bigl(b_q+b_t\bigr),
% \]
% apart from the constant number of affine states. One reusable tile needs
% \(O(b_qb_t)\) direction storage. The scheme replaces a full \(O(nm)\)
% direction matrix with tile borders and additional arithmetic during
% traceback. It is most useful when writing the full trace matrix would dominate
% device memory traffic.

% Short or structurally simple windows first use specialized scripts, including
% greedy gap scripts that are not guaranteed to maximize the affine score.
% Moderate windows can retain a bounded direction matrix. Longer
% admitted windows use gridded traceback. The current GPU CIGAR recurrence is
% global over the chosen window. It does not apply the KSW2 band, Z-drop, or end
% bonus even if related values are present in the broader request. It should
% therefore be described as a GPU-specific alignment contract, not as a device
% implementation of KSW2 or Block Aligner.

% The alignment route is selected explicitly before region alignment. The
% selected CPU kernel is then specialized for KSW2 or Block Aligner, so the
% inner recurrence does not branch on the backend for each cell. Output needs
% are resolved separately. A coordinate-only query may omit base alignment,
% while CIGAR or exact edit output makes traceback mandatory.

% The GPU route additionally requires the complete accelerated frontend and an
% admitted feature tuple before alignment begins.

% Several limits follow from these contracts. First, KSW2 and Block Aligner can
% return different scores because their gap models and search regions differ.
% Second, the ordinary DNA extension port does not implement every specialised
% minimap2 mode. Third, the GPU route uses a global coordinate window and lacks
% the current CPU endpoint rules. Fourth, adaptive search and finite bands can
% both omit cells that an unrestricted matrix would examine.

% These differences are exposed through route selection rather than hidden
% behind a single claim of algorithmic equivalence. KSW2 is appropriate when
% two-piece affine scoring and minimap-style stopping rules are required. Block
% Aligner is appropriate when its single-affine adaptive search matches the
% requested semantics. The GPU path is appropriate only when the complete
% accelerated route and its global window contract are admitted. When available,
% CIGAR and edit count describe the path produced by the selected route.
