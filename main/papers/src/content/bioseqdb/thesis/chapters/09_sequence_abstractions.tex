\section{One logical sequence, several physical forms}
\label{sec:sequence-abstractions}

The algorithms in the preceding chapters are easiest to describe over an
array of nucleotide codes.  A database system rarely has such an array ready.
The same logical sequence may be an in-memory bit-packed object, an externally
TOASTed PostgreSQL value, a set of columnar fragments, a slice of a provider
object, a concatenation of several values, or a reversed view of any of these.
Converting every case to a byte-per-symbol vector would make the algorithm
interfaces simple, but it would also discard one of the main advantages of
bringing alignment into the database: the ability to read and decode only the
part selected by the query.

BioSeqDB therefore separates four ideas which are easily conflated:

\begin{enumerate}
    \item the \emph{logical sequence}, a length and an ordered stream of
    alphabet ranks;
    \item the \emph{packed geometry}, which states how ranks occupy physical
    storage units;
    \item the \emph{representation}, which owns or locates the symbols and
    determines their lifetime; and
    \item the \emph{access requirement} of a consumer, which decides whether
    streaming is sufficient or a contiguous packed region must be acquired.
\end{enumerate}

This separation is the common data plane beneath minimizer extraction,
indexing, chaining input preparation, alignment, PostgreSQL operators, and GPU
uploads.  It also gives a precise meaning to ``lazy''.  Laziness does not mean
that an expression allocates nothing.  A slice or concatenation may allocate
tree nodes, retain a source handle, and record provenance.  It means that the
complete symbol payload is not decoded and repacked until a consumer declares
a boundary which requires it.

The final design has two principal C++ interfaces.  The
\texttt{compact\_sequence\_range} family describes a resident packed range
whose alphabet and storage-unit type are known at compile time.  The
\texttt{basic\_lazy\_sequence\_view} facade describes a logical rank stream
whose backing representation is selected at run time.  PostgreSQL expanded
values, source-backed pieces, fragmented scanners, and flat packed values are
adapted to the latter.  A consumer which truly needs packed resident storage
uses an explicit access plan to borrow or materialize a region.  Figure
\ref{fig:sequence-abstraction-layers} summarizes these layers.

\section{The compile-time compact range}
\label{sec:compact-sequence-range}

\subsection{Alphabet, container, and range concepts}

The core definitions are in
\texttt{main/bioseq/backend/sequences/sequences.cppm}.  An alphabet type
satisfies \texttt{sequence\_alphabet} when SeqAn can obtain a rank and a
compile-time cardinality from it.  A \texttt{sequence\_custom\_alphabet}
combines that logical alphabet with a physical unit and a chosen bit width.
A proper unpacked sequence container is a sized random-access range whose
reference is an alphabet value.  Finally,
\texttt{supports\_compact\_sequence\_range} identifies source types from which
the packed range family can be formed.  Listing
\ref{lst:compact-range-concepts} presents the public shape; function bodies and
diagnostic details are omitted.

\begin{lstlisting}[
  language=C++,
  basicstyle=\ttfamily\footnotesize,
  breaklines=true,
  caption={Abridged C++26 concepts and packed-range traits from
  \texttt{sequences.cppm}, symbols at lines 37--113 and 874--929.},
  label={lst:compact-range-concepts}]
template<class A>
concept sequence_alphabet = requires (A const a) {
    { seqan3::to_rank(a) };
    { seqan3::alphabet_size<A> };
};

template<sequence_alphabet Alphabet,
         class StorageUnit,
         size_t LetterBitWidth>
struct sequence_custom_alphabet {
    using alphabet_type = Alphabet;
    using storage_unit = StorageUnit;
    static constexpr size_t letter_bit_width = LetterBitWidth;
};

template<class R>
concept sequence_proper_container =
    sequence_alphabet<
        remove_reference_t<ranges::range_reference_t<R>>> &&
    ranges::sized_range<R> &&
    ranges::random_access_range<R>;

template<class R>
concept supports_compact_sequence_range =
    is_sequence_custom_alphabet<R> ||
    sequence_proper_container<R> ||
    sequence_alphabet<R> ||
    is_compact_sequence_stdc_instance<R>;

template<class Derived, class Alphabet, class StorageUnit,
         size_t LetterBitWidth>
struct compact_sequence_range_base {
    struct traits {
        using alphabet_type = Alphabet;
        using storage_unit = StorageUnit;
        static constexpr size_t bits_per_char = LetterBitWidth;
        static constexpr size_t unit_width = sizeof(StorageUnit) * 8;
        static constexpr size_t letters_per_unit =
            unit_width / bits_per_char;
        static constexpr size_t unit_used_bits =
            letters_per_unit * bits_per_char;
        static constexpr size_t unit_leftover_bits =
            unit_width - unit_used_bits;
        static constexpr StorageUnit char_mask =
            (StorageUnit{1} << bits_per_char) - 1;
        static constexpr size_t alphabet_size =
            seqan3::alphabet_size<Alphabet>;
        static constexpr size_t alphabet_size_n =
            alphabet_size + 1;
    };
};
\end{lstlisting}

The abstraction deliberately exposes both the logical alphabet and the
physical unit.  An algorithm such as minimizer extraction can use
\texttt{traits::alphabet\_type} for complement semantics,
\texttt{traits::bits\_per\_char} for masks, and
\texttt{traits::letters\_per\_unit} for vectorized loads without hard-coding
DNA4 or a 64-bit word.  The additional
\texttt{alphabet\_size\_n = alphabet\_size + 1} trait is part of the current
algorithm-facing API; it must not be confused with the true cardinality,
which remains \texttt{alphabet\_size}.

There are two important qualifications.  First,
\texttt{supports\_compact\_sequence\_range} is a construction-domain concept,
not a promise that its argument already owns packed bytes.  A public algorithm
which is intended to consume a range should accept the resulting range or the
new behavioral lazy facade, rather than repeatedly reconstructing it.
Second, storage geometry is not an algorithm's arithmetic state.  The K=27
failure documented in DOC0213 arose when a 32-bit physical DNA4 unit---which
contains only 16 ranks---was also treated as the rolling-hash state.  The
sequence was stored correctly, but the \(k\)-mer was silently shortened.  The
final rule is that packing width controls loads and iteration; a hash,
\(k\)-mer, score, or coordinate type is selected independently from the
mathematical range it must represent.

\subsection{Ranks, symbols, and orientation}

The base range exposes two scalar iterator interpretations.  BP iteration
returns integer ranks, while SYMBOL iteration converts each rank to the
alphabet type.  Algorithms whose inner loops need only small integers avoid
constructing alphabet objects; text output and alphabet-aware validation use
the symbolic form.  The logical length is
\[
  N = U_{\mathrm{count}}L - P,
\]
where \(U_{\mathrm{count}}\) is the number of storage units,
\(L\) is \texttt{letters\_per\_unit}, and \(P\) is the number of trailing
padding slots.  \texttt{bp\_size()} returns \(N\), whereas
\texttt{size()} denotes storage units.  Keeping these names distinct matters:
using unit count as symbol count is correct only when \(L=1\).

The conversion API includes full extraction and range extraction.  The
full \texttt{to\_encoded\_vector()} method is intentionally eager and is
appropriate for a legacy byte-oriented library such as KSW2.  The range form
and \texttt{to\_encoded\_into<IsReversed,WriteReversed>} decode only
\([from,to)\).  The two Boolean dimensions are independent:
\texttt{IsReversed} mirrors logical coordinates and applies complement
semantics for the reverse strand, while \texttt{WriteReversed} controls the
order placed in the destination.  The four combinations are required by
canonical minimizer cursors.  Collapsing the two flags into one ``reverse''
bit once caused source-backed reverse-write calls to read the wrong
coordinates; the current facade preserves the full four-callback table.

\section{Bit layout and reinterpretation}
\label{sec:sequence-bit-layout}

\subsection{Least-significant symbol first}

Let an alphabet contain \(\sigma\) ranks and let
\[
 b=\lceil\log_2 \sigma\rceil
\]
be the number of bits per symbol.  For a physical unit of \(W\) bytes, the
current layout stores
\[
 L=\left\lfloor\frac{8W}{b}\right\rfloor
 \quad\text{symbols and leaves}\quad
 r=8W-Lb
\]
unused high bits.  For logical position \(i\),
\[
  u(i)=\left\lfloor i/L\right\rfloor,\qquad
  s(i)=b(i\bmod L),\qquad
  rank(i)=\bigl(unit[u(i)]\gg s(i)\bigr)\mathbin{\&}(2^b-1).
\]
The first logical symbol occupies the least significant \(b\) bits of the
first unit.  Figure~\ref{fig:lsb-packed-layout} reconstructs a 16-bit DNA4
example.  It is a description of BioSeqDB's source invariant, not a generic
property of every biological file format.

For a resident packed range, reading an arbitrary rank is \(O(1)\): one unit
load, one shift, and one mask.  Sequential traversal is \(O(N)\), with a
constant determined by unit width, iterator form, and vectorization.  Packing
or extracting an interval of \(m\) symbols is \(O(m)\).  The range extraction
path seeks directly to the containing unit; it does not decode the prefix
before \texttt{from}.  These bounds do not imply that a source-backed rank is
always \(O(1)\) in wall time: a provider may need a fragment lookup or bounded
I/O.  The facade's guarantee is that only the requested window is asked for.

\subsection{The bit-casted view}

\texttt{bit\_casted\_view} in \texttt{sequences.cppm}, lines 726--866, changes
how a resident byte stream is stepped without changing its content.  A
DNA4/\texttt{uint64\_t} range may, for example, be viewed as
\texttt{uint32\_t} units when source and target have the same alphabet and
bit width, their unit widths divide one another, and both geometries have no
leftover bits.  The view owns only a reference to its base.  Its
\texttt{read\_cptr} reinterprets the address, while
\texttt{advance\_iter} and \texttt{view\_distance} scale by the power-of-two
width ratio.  Logical length and byte length do not change.

This facility is narrower than an arbitrary codec conversion.  It does not
change alphabet, symbol width, padding semantics, byte order, or lifetime.
Nor does it legalize every typed access.  The lazy access planner has a
separate \texttt{byte\_upload\_compatible} policy for one little-endian
64-to-32-bit case.  That policy returns a descriptor whose bytes may be copied
to a Vulkan buffer; the source allocation still has an effective
\texttt{uint64\_t} type, so a CPU consumer must not dereference it through a
\texttt{uint32\_t*}.  Native typed borrowing and byte-compatible upload are
recorded as different receipt kinds.

\section{A C-compatible packed object}
\label{sec:sequence-stdc}

\subsection{Standard layout and a zero-copy adapter}

An owning C++ range is unsuitable as a PostgreSQL datum because
\texttt{std::vector} is neither a C ABI nor a varlena payload.  The
\texttt{compact\_sequence\_stdc} family, introduced in the DOC0258 work and
subsequently revised, provides the shared flat representation.  Its current
declaration is in \texttt{sequences.cppm}, lines 2076--2255.  Listing
\ref{lst:compact-stdc-api} shows the representation-level API.

\begin{lstlisting}[
  language=C++,
  basicstyle=\ttfamily\footnotesize,
  breaklines=true,
  caption={Abridged standard-layout sequence API.  Methods are declarations;
  implementations and factories are omitted.},
  label={lst:compact-stdc-api}]
struct compact_sequence_stdc_type_params {
    uint8_t alphabet_code;
    uint8_t storage_unit_byte_width;
    static constexpr int32_t encode(...);
    static constexpr compact_sequence_stdc_type_params decode(int32_t);
};

template<class SupportedAlphabets,
         class BpSize = uint32_t,
         class VarlenaHeader = int32_t,
         class SupportedWidths = all_storage_unit_byte_widths>
struct compact_sequence_stdc {
    VarlenaHeader vl_len_;
    typename SupportedAlphabets::alphabet_code_t alphabet_code;
    uint8_t storage_unit_byte_width;
    uint16_t padding_letters;
    BpSize bp_size;
    [[no_unique_address]] alignment_reserved_holder<...> _reserved;
    uint8_t data[1];

    static constexpr size_t header_bytes();
    template<class Handler>
    static constexpr void dispatch_instance(
        alphabet_code_t, uint8_t byte_width, Handler&&);
    template<class Handler> void convert_to(Handler&&) const;
    size_t unit_count() const noexcept;
    size_t payload_bytes() const noexcept;
};

template<class Stdc, sequence_alphabet Alphabet, size_t WidthBytes>
struct compact_sequence_stdc_instance {
    using compact_sequence_stdc_type = Stdc;
    using alphabet_type = Alphabet;
    using storage_unit = /* uint8_t, uint16_t, uint32_t, or uint64_t */;
    static constexpr size_t byte_width = WidthBytes;
    static constexpr size_t letter_bit_width =
        seqan3::detail::ceil_log2(seqan3::alphabet_size<Alphabet>);
};

template<class Instance>
requires is_compact_sequence_stdc_instance<Instance>
struct compact_sequence_range<Instance> {
    using storage_unit = typename Instance::storage_unit;
    explicit compact_sequence_range(
        typename Instance::compact_sequence_stdc_type const&) noexcept;
    size_t padding() const noexcept;
    size_t size() const noexcept;       // physical units
    size_t bp_size() const noexcept;    // logical symbols
    storage_unit const* cbegin() const noexcept;
};
\end{lstlisting}

The header records run-time type parameters, logical length, and last-unit
padding; \texttt{data[]} contains the packed payload.  The reserved field makes
the payload offset a multiple of eight, allowing every enabled 1-, 2-, 4-, or
8-byte instance to form naturally aligned typed loads.  The PostgreSQL
specialization uses a 32-bit base-pair count and a 32-bit varlena header.
On the target little-endian PostgreSQL ABI the stored header uses the
four-byte uncompressed varlena encoding, rather than a raw byte count.  A raw
count would make PostgreSQL interpret only one quarter of the object and
truncate detoasted copies.

\texttt{compact\_sequence\_stdc\_instance} carries no run-time state.  It pins
the two header bytes---alphabet code and physical width---as C++ template
parameters.  Once dispatched, the
\texttt{compact\_sequence\_range<Instance>} specialization holds a const
reference to the datum and points directly at \texttt{data[]}; it does not
create a vector.  Construction validates that header width, logical length,
unit count, and padding agree.  This is the main zero-copy boundary between a
flat PostgreSQL value and the resident algorithm interface.

\subsection{Contrast with minimap2's split representation}

The copied minimap2 reference makes a different, internally consistent
trade-off.  Its input record \texttt{mm\_bseq1\_t} stores an integer length and
\texttt{char*} fields for name, sequence, quality, and comment
(\texttt{main/bench/tool\_minimap2/minimap2/bseq.h}, lines 14--17).  Mapping
entry points such as \texttt{mm\_map} receive the query as
\texttt{const char*}.  The reference index uses another representation:
\texttt{mm\_idx\_t::S} is a \texttt{uint32\_t*} containing a four-bit packed
reference (\texttt{minimap.h}, lines 80--100).  Reverse complementation of an
input record mutates the byte string in place.

This split is well suited to a command-line mapper which reads batches from
FASTA/FASTQ, constructs its own index, and releases batch-owned memory after
mapping.  It is not an SQL value model.  A PostgreSQL slice cannot safely be
represented as a borrowed \texttt{char*}; a concat cannot mutate its operands;
and an expression may outlive the scan node which discovered the source
fragment.

\texttt{mm\_idx\_str} and \texttt{mm\_map} with those strings (lines
218--310).  BioSeqDB-native routes avoid that boundary when their kernels
support compact or lazy ranks.  This is a systems difference rather than a
change to minimap2's seed--chain--extend mathematics.

\subsection{Runtime metadata becomes compile-time specialization}

Alphabet registration is itself type-level.  An
\texttt{alphabet\_entry<A,Name>} pairs an alphabet with a compile-time string.
\texttt{supported\_alphabets<...>} verifies unique types and names, assigns a
small integer code, and supplies code-to-name, name-to-code, and dispatch
operations.  A typical dispatch has the following form:

\begin{lstlisting}[
  language=C++,
  basicstyle=\ttfamily\footnotesize,
  breaklines=true,
  caption={Runtime header dispatch into a compile-time alphabet/width
  specialization.},
  label={lst:alphabet-dispatch}]
#if BIOSEQ_OPTTIMIZATION_LEVEL == 0
using pgseq_supported_alphabets =
    supported_alphabets<
        alphabet_entry<seq::dna4, "dna4">>;
#else
using pgseq_supported_alphabets =
    supported_alphabets<
        alphabet_entry<seq::dna4, "dna4">,
        alphabet_entry<seq::dna5, "dna5">>;
#endif

seq::dispatch_instance(runtime_alphabet_code, runtime_width,
    [&]<class Instance>() {
        using range_type = compact_sequence_range<Instance>;
        using alphabet_type = typename Instance::alphabet_type;
        range_type packed{datum};
        consume<alphabet_type>(packed);
    });
\end{lstlisting}

The exact PostgreSQL profile is in
\texttt{main/bioseq/backend/pg/types/compact\_sequence/flat\_abi.cppm}.
At optimization profile 0, \texttt{pgseq\_supported\_alphabets} contains only
DNA4; higher profiles add DNA5.  Profiles 0 and 1 enable only an eight-byte
physical unit, while profile 2 enables \(\{1,2,4,8\}\).  SQL width requests
are validated and normalized through this policy.  Consequently the symbol
named in some older design notes as \texttt{pg\_supported\_sequences<>} is not
the implemented abstraction.  The current aliases are
\texttt{pgseq\_supported\_alphabets} and
\texttt{pgseq\_supported\_storage\_unit\_byte\_widths}.

Dispatch is paid at the boundary, not in the rank loop.  After the nested
alphabet/width selection, masks, letters per unit, complement operations, and
lane types are compile-time constants.  This is how one stored SQL base type
can remain alphabet-generic without placing a switch statement inside every
symbol operation.

\subsection{Dispatch is not SQL code generation}

A second compile-time-looking mechanism has a different purpose.  The
PostgreSQL type alias is annotated in \texttt{flat\_abi.cppm}:

\begin{lstlisting}[
  language=C++,
  basicstyle=\ttfamily\footnotesize,
  breaklines=true,
  caption={The C++ declaration that owns the generated SQL type metadata.},
  label={lst:seq-type-annotation}]
using seq [[bioseq_sql::type({
    .schema = bioseq::sql::fixed_schema<"bioseq">,
    .internal_length = bioseq::sql::variable_length,
    .alignment = bioseq::sql::type_alignment::double_,
    .storage = bioseq::sql::type_storage::extended,

    pgseq_supported_alphabets,
    uint32_t,
    int32_t,
    pgseq_supported_storage_unit_byte_widths>;
\end{lstlisting}

The \texttt{bioseq\_sql} attributes are consumed by
\texttt{main/codegen/sql}: the annotation model describes entities and
options, the collector reads annotated declarations, the graph layer resolves
dependencies and fmgr facets, and renderers produce installation SQL, C/fmgr
boundary code, and manifests.  Function, result, parameter, operator, and
subscript attributes in \texttt{concat\_reverse.cppm},
\texttt{subscript.cppm}, \texttt{letter.cppm}, and related partitions keep the
SQL signature next to its C++ authority.

This generation path does \emph{not} select a nucleotide alphabet at query
run time.  Conversely, \texttt{supported\_alphabets} does not generate SQL.
The former removes duplicated boundary declarations at build time; the latter
specializes data processing at run time.  Keeping the two mechanisms separate
is important both for understanding the code and for assigning failures to
the correct layer.

\section{From fragmented storage to one lazy facade}
\label{sec:lazy-sequence-facade}

\subsection{Why a packed pointer is not a sufficient interface}

The flat adapter solves only the case in which the entire payload is already
resident in one datum.  Columnar storage and external providers return bounded
pieces.  A range may cross fragment boundaries, and a reverse-strand cursor
may request those pieces in the opposite logical order.  Requiring a single
pointer would force all fragments to be joined before a consumer could inspect
the first rank.

The first BioSeqDB lazy design, still visible in
\texttt{main/bioseq/backend/storage/lazy\_compact\_sequence.cppm}, was
parameterized by a concrete range and scanner.  Its no-fragment specialization
was close to a pointer-sized wrapper.  The fragmented specialization held a
small fragment cache and stitched a requested window into scratch storage when
it crossed a boundary.  This was useful because existing minimizer iterators
could ask for a small contiguous run without knowing how fragments were
loaded.  It was nevertheless representation-specific: an algorithm's type
mentioned the scanner, the underlying range, and the fragment machinery.

The final facade moves the representation choice behind an operation table.
It is specialized by logical alphabet, but not by PostgreSQL width, source
provider, tree shape, or scanner class.  The interface emits rank bytes for
sequential consumers and can optionally describe an already-resident packed
region.  Listing~\ref{lst:lazy-facade-api} shows the essential API from
\texttt{lazy\_compact\_sequence.cppm}, lines 169--568.

\begin{lstlisting}[
  language=C++,
  basicstyle=\ttfamily\footnotesize,
  breaklines=true,
  caption={Abridged declaration-only form of the canonical lazy facade.},

The \texttt{uint8\_t} called \texttt{storage\_unit} in
\texttt{lazy\_rank\_stream\_traits} is a rank-stream element, not the physical
packed unit of the backing object.  DNA4 still contains two logical bits per
symbol.  A facade callback writes one rank per scratch byte only for the
requested window.  This distinction avoids implying that the lazy interface
expands the whole value to bytes.

The state pointer and static operation table form a small
representation-erased object.  Backends provide four \texttt{ptr\_at}
callbacks for the Cartesian product of logical reverse orientation and
destination write order.  A callback may return a pointer into backing
storage when its representation permits it, or return the supplied scratch
buffer after filling the request.  The PostgreSQL facade currently emits
ranks into scratch for both flat and tree traversal; its separate resident
probe is what permits a zero-copy packed borrow.

\subsection{Ownership is part of the abstraction}

A borrowed view without a lifetime is an unsafe pointer with a better name.
\texttt{lazy\_sequence\_call\_owner<Alphabet>} is therefore a move-only RAII
object containing the facade and the release action for its state.  PostgreSQL
constructs these owners in a read-session memory context.  The helper
\texttt{with\_pg\_sequence\_view<Result>} in
\texttt{view\_session.cppm}, lines 995--1064, enforces at compile time that a
callback result is not a pointer, reference, range view, or iterator and is
trivially destructible.  The view cannot accidentally escape after a detoast
copy, source domain, or memory context has been released.

This restriction also addresses PostgreSQL's non-local error model.
Source reads may raise a PostgreSQL error while C++ owners are live.  The
read-session boundary converts the error long enough to unwind registered
owners, then rethrows the original PostgreSQL error.  An ordinary destructor
alone would be insufficient because PostgreSQL \texttt{ERROR} performs a
\texttt{longjmp} across C++ frames.

Worker sharing is explicit as well.  A flat resident value is shareable.
A tree is shareable only if every source leaf's provider says that its state
is shareable.  Current source-backed PostgreSQL views remain on the backend
thread.  A CPU task or Vulkan operation which outlives that call first obtains
an admitted resident owner; both the allocation and its memory permit remain
alive until task completion or the GPU fence.

\section{Persistent SQL expressions as immutable piece trees}
\label{sec:sequence-piece-tree}

\subsection{Leaves, branches, and transforms}

PostgreSQL needs lazy values to survive ordinary expression evaluation,
concatenation, and nested slices.  A raw tuple pointer cannot provide that
lifetime: its memory can be detoasted, copied, or reset, and an arbitrary
slice may begin in the middle of a packed word.  The final representation is
a PostgreSQL expanded object whose payload is an immutable balanced piece
tree.  The public POD shapes are declared in
\texttt{main/bioseq/backend/pg/types/compact\_sequence/tree\_types.cppm},
lines 31--222, and are abridged in Listing~\ref{lst:piece-tree-api}.

A source leaf stores a retained provider handle and stable logical
coordinates, not an address into a tuple.  A literal leaf stores owned packed
or unbound bytes and its validated type.  Concatenation creates a branch.
Each node caches logical length, piece count, and AVL height.  Existing
subtrees are immutable and retained through arena dependencies, so a new
expression shares them rather than copying their symbols.

Reverse and complement state is attached to an edge.  Composing a transform
changes metadata and preserves the subtree.  For a branch reached through a
reversed edge, logical child order is reversed during traversal.  For a
literal or source leaf, coordinate mirroring, output order, and complementation
are applied at the facade callback.  This design makes a reverse or
reverse-complement operation \(O(1)\) in payload size.

The current node kinds deserve emphasis.  Design documents sometimes use
``slice piece'' and ``transform piece'' as conceptual terms, but the source
does not store separate payload nodes with those enum values.  A slice narrows
leaf ranges by splitting the tree and shares unaffected nodes; a transform is
carried by \texttt{piece\_edge}.  Describing the conceptual expression DAG is
useful in SQL \texttt{EXPLAIN}, but the physical piece-tree enum is
\{\texttt{branch}, \texttt{source}, \texttt{literal}\}.

\subsection{Composition and complexity}

\texttt{concat\_pg\_sequences} in
\texttt{packed\_output.cppm}, lines 3306--3361, acquires one writable expanded
value, resolves bound/unbound type adoption, checks the summed logical length,
and joins the two immutable roots.  The join in
\texttt{tree\_ops.cppm}, lines 1665--1765, descends according to subtree
height and performs an AVL single or double rotation when needed.  Work for
already validated roots is bounded by the height-guided join path, not by the
total number of pieces.  Adjacent compatible leaves may be coalesced.

\texttt{slice\_tree} at lines 1887--1911 splits first at the upper and then at
the lower coordinate, releases the two discarded sides, and returns the
middle.  In a balanced tree, each split follows a boundary path; payload
outside those paths is shared.  The cost depends on tree height and boundary
leaf construction, not on the number of symbols in the selected interval.
Reading the selected symbols later remains \(O(m)\) for an interval of length
\(m\), plus provider/fragment overhead.

The arenas make persistent sharing compatible with PostgreSQL memory
contexts.  They reference older arenas and source dependencies, keep
generation ordering, and release dependencies iteratively.  Construction uses
a fixed cleanup ledger because a PostgreSQL error may bypass C++ stack
destructors.  This bookkeeping is not merely defensive infrastructure: it is
what allows an expanded sequence returned by one SQL operator to remain valid
for the next operator without copying the original payload.

\subsection{Bound, unbound, and letter values}

The expanded header carries both physical type parameters and an
\texttt{alphabet\_bound} flag.  A bound value has an alphabet and packing
width.  An unbound SQL literal contains canonical ASCII but has not yet
adopted an alphabet.  Alphabet-independent operations---length, slicing,
reversal, comparison, and unbound concatenation---remain possible.  Combining
one unbound and one bound value validates the unbound symbols and adopts the
bound alphabet.  Two different bound alphabets are never silently recoded.

Element access returns \texttt{bioseq.letter}, a fixed two-byte value
containing \((alphabet\_code,rank)\).  This is more robust than returning a
character: the alphabet identity survives arrays, prepared statements, and
places where PostgreSQL does not retain expression typmods.  An in-range
element of an unbound sequence is an error because no physical alphabet is
known; an out-of-range element is still SQL \texttt{NULL}.

Equality and hashing follow logical content rather than storage.  For unbound
values the key is a state tag and canonical ASCII bytes.  For bound values it
is a different state tag, unsigned alphabet code, and the logical rank stream.
Storage width, padding, flat versus expanded form, source backing, and piece
boundaries are excluded.  Hence a flat value and a many-piece lazy value
compare equal and hash identically when their logical state, alphabet, and
ranks agree.  A bound value is intentionally not equal to an unbound value
with the same printed text.

\section{SQL slicing and logical transforms}
\label{sec:sequence-sql-slicing}

The production subscript handler is implemented with PostgreSQL 17
\texttt{SubscriptRoutines} in \texttt{subscript.cppm}.  Its semantics are
Python-like: indices are zero-based, slices are half-open, negative values are
relative to the logical length, omitted bounds select the corresponding end,
and bounds are clamped.  If the normalized upper bound precedes the lower
bound, it is set equal to the lower bound and the result is a typed empty
sequence.  A missing element produces \texttt{NULL}.  A SQL \texttt{NULL}
bound propagates SQL \texttt{NULL}.  Assignment, steps, and multiple
dimensions are rejected.

\begin{lstlisting}[
  basicstyle=\ttfamily\footnotesize,
  breaklines=true,
  caption={Current SQL coordinate and composition semantics.},
  label={lst:sequence-sql-examples}]
WITH v(s) AS (
  VALUES ('ACGTA'::bioseq.seq('dna4', 32))
)
SELECT s[0]::text,        -- A
       s[-1]::text,       -- A
       s[:2]::text,       -- AC
       s[1:-1]::text,     -- CGT
       bioseq.len(s[4:2]);-- 0

SELECT ('AC'::bioseq.seq('dna4',32) || 'TG')::text;
SELECT bioseq.reverse('AAGC'::bioseq.seq('dna4',32))::text;
SELECT bioseq.reverse_complement(
         'AAGC'::bioseq.seq('dna4',32))::text;
\end{lstlisting}

Concatenation is symmetric for sequences, \texttt{text},
\texttt{varchar}, one-dimensional \texttt{text[]} and
\texttt{bioseq.letter[]} operands.  Empty arrays act as identities; null
elements and multidimensional arrays fail explicitly.  The overloads are
strict, so a null operand yields null without inspecting the other operand.
\texttt{bioseq.reverse} is valid for bound and unbound values because it only
changes order.  Reverse-complement requires a bound alphabet and a complete
complement mapping.

Same-type typmod casts are logical operations.  An identical alphabet/width
is metadata-only; a same-alphabet width change records the target geometry and
delays repacking until a flat consumer requests it.  Binding an unbound
literal validates every symbol.  Relabeling a bound value as another alphabet
fails.  These rules apply equally to flat, TOASTed, expanded, and
source-backed data.

The coordinate convention is a concrete example of why date precedence
matters.  DOC0313 proved that PostgreSQL generic subscripting could be attached
to the custom type, but its proof of concept used PostgreSQL array-style
one-based inclusive bounds and eagerly repacked each slice.  The later
DOC0387 reference and the current \texttt{subscript.cppm} supersede those
choices with zero-based half-open logical views.  The older report's safety
finding remains correct: a user-visible value must not hold a raw pointer into
another varlena.  The final tree and source-owner design satisfies that
constraint without forcing eager payload materialization.

\section{Access planning and materialization boundaries}
\label{sec:sequence-materialization}

\subsection{Consumers state what they require}

The abstraction cannot make every algorithm streaming.  A scalar rank scan
needs only sequential symbols.  A block-oriented kernel may need bounded
random windows.  A GPU upload or a SIMD routine which forms typed unit pointers
may require one contiguous packed region.  BioSeqDB makes this difference
explicit through \texttt{sequence\_access\_requirement} in
\texttt{sequence\_scanner.cppm}, lines 217--221, and the planner in
\texttt{lazy\_compact\_sequence.cppm}, lines 2148--2405.

\begin{lstlisting}[
  language=C++,
  basicstyle=\ttfamily\footnotesize,
  breaklines=true,
  caption={Declaration-only form of lazy access requirements and plans.},
  label={lst:sequence-access-plan}]

    sequential_symbols,

    contiguous_resident
};

    stream_symbols,
    borrow_resident,
    materialize_admitted
};

    none,
    native_typed_storage,
    reinterpreted_bytes
};

    sequence_access_requirement requirement;
    sequence_access_route route;
    optional<resident_packed_region> resident;

    sequence_size_t to;

template<sequence_alphabet Alphabet>

    basic_lazy_sequence_view<Alphabet> view,
    sequence_access_requirement requirement,
    sequence_size_t from, sequence_size_t to,
    uint8_t requested_width = 0,
    sequence_resident_borrow_policy =
        sequence_resident_borrow_policy::native_typed_storage_only);
\end{lstlisting}

For \texttt{sequential\_symbols}, the current planner immediately selects
\texttt{stream\_symbols}.  A caller uses the facade's chunk iterator or
\texttt{to\_encoded\_into} and supplies bounded scratch space.  For
\texttt{contiguous\_resident}, the planner first probes the representation at
the requested physical width.  Borrowing is accepted only when the descriptor
is internally consistent and its \texttt{leading\_symbol\_offset} is zero.  A
nonzero offset means that the requested interval begins inside a packed unit;
the ordinary \texttt{compact\_sequence\_range} interface has no field for that
offset and typed consumers would read the wrong first rank.  The current
generic planner sends \texttt{bounded\_random\_window} to admitted
materialization as well; a consumer which can formulate its computation as
forward bounded chunks should request the sequential route instead.

If no valid borrow exists, the plan reports the exact admission charge for a
packed owner over \([from,to)\).  The caller acquires a
\texttt{MemoryPermit}, and
\texttt{materialize\_packed\_region} packs only that interval at the requested
width.  The returned owner contains the stable allocation, descriptor, and
permit.  Moving ownership into an asynchronous task or Vulkan submission also
moves the permit, preventing accounting from ending before the last load or
completion fence.

\subsection{What ``zero copy'' does and does not mean}

BioSeqDB has several useful zero-copy cases, but no universal zero-copy
promise:

\begin{itemize}
    \item constructing \texttt{compact\_sequence\_range<Instance>} over an
    already resident, uncompressed flat datum is reference-only;
    \item constructing a slice, concat, or transform can be payload-free
    because it creates or shares metadata;
    \item a flat aligned interval at its native physical width can be borrowed;
    and
    \item a fragmented or source-backed interval can be \emph{streamed}
    without forming a complete packed result, although requested chunks are
    decoded into scratch.
\end{itemize}

There are corresponding boundaries where copying is required.  PostgreSQL may
first detoast a compressed or external flat value; the zero-copy C++ adapter
does not bypass PostgreSQL's varlena ownership rules.  A typed resident kernel
cannot borrow an interval with an in-unit start.  Text, binary send, and
\texttt{bioseq.letter[]} output require materialized destination forms.  A
heap tuple or index tuple requires a durable representation.  A provider view
is transaction-scoped, so it must be flattened before it crosses a durable or
cross-transaction boundary.  Finally, a logical expanded value may be larger
than the flat varlena representation can encode; metadata operations can
continue to work, but a later flat boundary raises SQLSTATE \texttt{54000}
rather than truncating it.

The important observation is that SQL evaluation and payload materialization

\subsection{Bounded source reads}

The PostgreSQL adapter state in \texttt{view\_session.cppm}, lines 430--738,
contains a read session, a logical descriptor, and either a flat pointer or a
tree edge.  Its tree-range emitter descends only through branches intersecting
the requested coordinates.  Literal ranks are extracted from the relevant
packed range; a source leaf invokes the provider's bounded
\texttt{read\_ranks} operation.  Reversal maps the logical interval to base
coordinates before traversal and only then changes destination order and
complements ranks.  A small terminal slice therefore does not require a
prefix scan of the source.

The resident probe is intentionally stricter.  It succeeds only for a flat
value at the requested native width.  Tree and source states return no
resident descriptor, even if a provider internally has a cache page, because
the generic facade does not own a stable typed allocation for that page.
This honesty prevents an optimization from extending a cache pin or
PostgreSQL memory-context pointer beyond its contract.

Three engineering lessons follow from this history.

First, the safety problem in DOC0313 was real but did not imply that all
slices must be eager.  A flat varlena has neither an arbitrary bit-start field
nor an owner pointer, so merely incrementing \texttt{data[]} is unsound.
The final solution changed the persistent representation instead of weakening
the invariant: it stores stable source coordinates or arena-owned literal
ranges and retains the source domain.

Second, the older fragmented iterator and the final facade solve different
levels of the problem.  Fragment stitching is a useful backend mechanism.  It
should not be the type named by every algorithm.  Representation erasure
allows the same logical cursor to traverse a flat value, a piece tree, a
provider, or an admitted packed owner.

Third, materialization cannot be hidden in a convenience conversion.  Once the
consumer declares its requirement, the system can estimate bytes, obtain a
permit, report the reason in \texttt{EXPLAIN}, and keep ownership through
asynchronous execution.  Without that declaration, a seemingly harmless
\texttt{to\_vector()} can expand an entire target in the scheduler's timing
window or on every row of a query.

reported the same correct mapping, but the single repeat remains too small for
a general performance claim.  Its role in this chapter is historical: it
motivated explicit conversion boundaries and comparable input ownership.

\section{Practical contract for algorithm authors}
\label{sec:sequence-author-contract}

The final representation is broad, but its safe use can be summarized in a
small set of rules:

\begin{enumerate}
    \item Write alphabet-generic code against
    \texttt{compact\_sequence\_range} traits or the behavioral lazy facade.
    Deduce masks, ranks, and alphabet cardinality from the selected type.
    Do not infer a hash-state width from the physical storage unit.
    \item Request the weakest access requirement that implements the
    algorithm.  A forward scan should remain a scan.  A resident-only routine
    must request a region and accept the admission/lifetime owner.
    \item Convert only the selected \([from,to)\) region at the point where a
    byte-oriented external API actually requires it.  Hoist invariant
    conversions out of repeated or timed calls.
    \item Treat a resident descriptor as a capability with a precise type.
    A byte-upload receipt is not permission to form a differently typed CPU
    pointer, and an unaligned first symbol is not a flat compact range.
    \item Never persist a pointer into a tuple, TOAST value, cache page, or
    provider buffer.  Persistent laziness uses retained handles, logical
    coordinates, immutable arenas, and declared flattening boundaries.
    \item Keep SQL generation and alphabet dispatch conceptually separate.
    C++ attributes generate boundary artifacts; the supported-alphabet pack
    specializes execution after a datum is read.
\end{enumerate}

These rules explain how the final solution differs from the original
resident-vector model.  The original model made the algorithm's preferred
layout the mandatory representation of every input.  The final model makes
logical ranks and ownership the mandatory contract, while packed contiguity is
a requested capability.  This inversion is what permits an alignment pipeline
to consume database-resident slices without pretending that TOAST, fragments,
source providers, GPU lifetimes, and SQL persistence are all the same kind of
memory.
