Quick start

From an empty database to a working sequence search in four steps. Lorem ipsum dolor sit amet, consectetur adipiscing elit, sed do eiusmod tempor incididunt ut labore et dolore magna aliqua.

Create a sequence table#

Declare a table with an ordinary primary key, a few metadata columns, and one Tbioseq.seq column, using the bioseq table access method.

schema.sql 
CREATE TABLE reads (
  id       bigint GENERATED ALWAYS AS IDENTITY,
  accession text,
  organism text,
  seq      bioseq.seq('dna4', 64)
) USING bioseq;
What this does

The seq column stores DNA in a 4-letter alphabet with a seed width of 64. Everything else is ordinary Postgres.

Load a FASTA file#

Stream records straight into the table with ƒbioseq.load(). Header fields map to typed columns as they arrive.

load.sql 
SELECT bioseq.load(
  'reads'::regclass,
  '/data/sample.fasta',
  'auto'
);
Output
 load
──────
 48213   (1 row)

Run your first search#

A normal SELECT becomes sequence-aware the moment ƒmmsearch() appears in the WHERE clause.

search.sql 
SELECT id, accession, organism
FROM   reads
WHERE  mmsearch(seq, 'ACGTACGTACGT'::bioseq.seq('dna4', 64));

Loading & searching sequences

The bioseq.seq column type#

The Tbioseq.seq type is parameterised by an alphabet and a seed width. Its anatomy:

bioseq.seq('dna4', 64)
alphabet

Which letters are legal and how densely they pack. 'dna4' packs 2 bits per base.

seed width (k)

The k-mer width the index seeds with. Larger k is more specific; smaller k is more sensitive.

i

Note. The alphabet and seed width are fixed at column-creation time. Sequences you insert are validated and packed against them on the way in.

Streaming FASTA & FASTQ#

ƒbioseq.load() reads records incrementally, so memory stays flat regardless of file size. Read the call left-to-right:

load_mapped.sql 
SELECT bioseq.load(
  'reads'::regclass,           -- target table
  '/data/run_042.fastq',     -- source path
  'auto',                    -- detect fasta/fastq
  ARRAY[
    ('sample_id', 'sample')::bioseq.column_mapping,
    ('run_name',  'run')::bioseq.column_mapping
  ]
);
regclass

Pass the table as a regclass so the loader resolves its columns and the sequence type.

column_mapping[]

Each tuple binds a table column to a header field, so metadata arrives typed alongside each sequence.

Mapping header fields to columns#

Sequitur header lines carry key–value fields. A mapping projects them into typed columns. Lorem ipsum dolor sit amet, consectetur adipiscing elit sed do eiusmod.

×

Type mismatches abort the load. If a mapped header value cannot cast to the column type, bioseq.load rolls back the whole transaction. Validate header formats before a bulk import.

Searching with mmsearch#

Once loaded, project the alignment accessors right beside the row. Each accessor takes the row's primary key and returns a facet of the match found by ƒmmsearch().

alignment.sql 
SELECT pk,
       bioseq.query_start(pk)  AS qs,
       bioseq.query_end(pk)    AS qe,
       bioseq.target_start(pk) AS ts,
       bioseq.target_end(pk)   AS te,
       bioseq.cigar(pk)        AS cg
FROM   reads
WHERE  mmsearch(seq0, 'ACGTACGTACGT'::bioseq.seq('dna4', 64))
ORDER BY pk;

mmsearch()#

boolean mmsearch(seq bioseq.seq, query bioseq.seq)
predicate since 0.9

Returns true for rows whose stored sequence contains a match for query. Placing it in a WHERE clause activates a custom scan that seeds, extends, and scores alignments; the alignment accessors then expose match details for each row.

Parameters
seqbioseq.seqThe stored sequence column to scan (typically the table's seq column).
querybioseq.seqThe query sequence, cast to a matching bioseq.seq alphabet and width.
Returnsboolean — whether the row matched. Alignment detail via the accessors below.

Streams records from path into rel, parsing sequences into the table's bioseq.seq column and projecting header fields into columns per mapping. Runs inside the current transaction.

Parameters

API reference/C++ core types/bit_casted_view
struct template C++26

bit_casted_view<base_t, output_t>

Lets a ◇compact_sequence_range be iterated as if its buffer were an array of a different Tstorage_unit width. Sound only when both alphabets pack with no leftover bits per unit, so the byte stream is identical and only the letters-per-stride differs.

Synopsis#

bioseq_sequences/bit_casted_view.hpp 
template <typename base_t, typename output_t>
struct bit_casted_view {
    using base_traits = base_t::traits;
    using traits      = output_t::traits;
    using iterator    = typename base_t::iterator;

    bit_casted_view(const base_t& base);

    // narrows (down) or widens (up) the storage unit
    static constexpr bool   is_down_cast;
    static constexpr size_t cast_ratio;      // unit-width ratio, >= 1
    static constexpr size_t cast_ratio_log;  // log2(cast_ratio)

    constexpr size_t bp_size()   const;  // letters, unchanged by the cast
    constexpr size_t byte_size() const;  // packed bytes, unchanged
    constexpr size_t size()      const;  // view-units for the letters
    constexpr size_t padding()   const;  // empty slots in the last unit

    constexpr const traits::storage_unit* read_cptr(const I& it) const;
    static constexpr void   advance_iter(I& it, size_t value);
    static constexpr size_t view_distance(const I& a, const I& b);
    constexpr iterator cbegin() const;
    constexpr iterator begin()  const;
};

output_tThe target type whose traits::storage_unit the buffer is reinterpreted as (e.g. uint32_t from a uint64_t base).

advance_iter.cpp 
template<typename I>
requires(base_t::template is_valid_derived_iter<I>::value)
[[always_inline]] constexpr static void advance_iter(I& it, const size_t value) {
    if constexpr (is_down_cast) {
        // one real unit spans cast_ratio view units → shift-as-divide
        DEBUG_ASSERT(value % cast_ratio == 0);
        it += (value >> cast_ratio_log);
    } else {
        // each view unit spans cast_ratio real units → shift-as-multiply
        it += (value << cast_ratio_log);
    }
}

Notes#

Both bit_casted_view and a plain ◇compact_sequence_range satisfy the supports_compact_sequence_bitcast_view concept, so the SIMD loop consumes either uniformly.

i

Why a view and not a copy. The wrapping types are the same size (both wrap a std::vector + size_t); only the storage_unit interpretation differs, so no bytes move.

!

Downcast precondition. On a downcast, advance_iter's value must be divisible by cast_ratio for the shift-as-divide to be exact. The SIMD loop advances by Lanes(d) — a power of two — so this holds by construction.

×

Not for ragged alphabets. Reinterpretation is undefined when an alphabet leaves leftover bits per unit — the byte streams no longer coincide. Only bitcast between alphabets that pack whole letters per unit.
