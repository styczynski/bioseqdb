Introducing BioseqDB

Store biological sequences beside their metadata and search them with SQL. A first look at BioseqDB, its history, two queries, and the benchmark results.

1 October 2026·4 min read·Piotr Styczyński
Markdown

BioseqDB is a PostgreSQL extension for storing, indexing and searching biological sequences with SQL. Combine genomic matches with relational data using compact sequence types and columnar storage!

I wanted to keep sequences and their metadata together. If a sample has an organism, collection date or patient identifier, those values should be ordinary columns beside its DNA. Searching for a similar sequence should fit into the same query as filtering those columns.

How it started#

This project required several years of exploration and experiments. I began without a formal background in computational biology, thus learning the field was part of the research.

  • 2021–2022: Working with large GISAID datasets made FASTA files hard to manage. I proposed the database idea in May 2021 and directed a team prototype that connected BWA-MEM to PostgreSQL in May 2022.
  • 2023–2024: I wrote a Python aligner and then improved it, learning how the algorithms work along the way.
  • December 2025–2026: The current BioseqDB began with minimap2 and columnar storage. Custom seeding and chaining, indexes, sequence slices and end-to-end benchmarks followed.

The current BioseqDB is a separate project, designed and written by me. It contains no code or intellectual property from the early BWA-MEM integration experiments. The introduction and full timeline have more of the story.

Two queries to get a feel for it#

These examples use the three synthetic samples from the SQL walkthrough. The samples table has ordinary metadata columns and a bioseq.seq column. USING bioseq selects the sequence-aware storage.

First, read metadata and a small piece of DNA. bioseq.len gives the sequence length; [:16] takes its first sixteen bases.

Executed against Bioseq extension 1.0 on PostgreSQL 17.10

Now search those samples for Ben's sequence, stored in row 2. mmsearch performs the alignment; bioseq.score and bioseq.cigar describe each match.

Executed against Bioseq extension 1.0 on PostgreSQL 17.10

Anna has two occurrences and Ben has one. These are exact matches, so each CIGAR is 512M. Alignment can also handle differences between sequences: substitutions, insertions and deletions. The alignment chapter explains how seeding, chaining and base alignment fit together.

Where it fits beside existing tools#

BioseqDB builds on ideas from existing aligners, especially minimap2. The difference I wanted was the workflow: keep the data in PostgreSQL and combine sequence search with SQL filters and joins.

ToolMain focus
minimap2Mapping reads and aligning nucleotide sequences against a reference.
BLASTFinding local sequence similarity in sequence databases.
WinnowmapLong-read mapping, including repetitive regions.
LexicMapNucleotide alignment against large collections of prokaryotic genomes.
BioseqDBStoring sequences beside relational metadata and running alignment inside SQL.

In my benchmarks, the preferred CPU configuration was typically 3–8× faster than minimap2 when a prepared reference index was available. Without that index, BioseqDB was usually slower than minimap2. These tests used 1,024 synthetic queries against one 2 or 4 Gbp reference, not a collection of real genomes. Several external tools also needed the reference split into smaller records, so the measurement details matter when comparing them.

There is still work to do. The current GPU paths were slower than the CPU paths in these measurements, and indexing has known limitations. This first release is experimental software.
