Getting to know BioseqDB

Is BioseqDB a PostgreSQL extension or a separate database?#

It is a PostgreSQL extension. You connect to PostgreSQL with the same clients you already use, then add BioseqDB sequence columns and tables where you need them. The extension supplies sequence types, alignment functions, indexes, and its own table storage. The SQL walkthrough starts with a small table you can try yourself.

What can I actually do with it?#

Store DNA sequences beside sample metadata, read slices of those sequences, perform sequence operations, and find alignments using SQL. You can combine an alignment with a metadata filter or a join in the same query. The main focus is sequence storage and alignment; it is not a complete replacement for every tool in a genomics pipeline.

How would BioseqDB fit into a workflow I already have?#

A useful starting point is the part where you repeatedly load the same reference sequences, run searches, then join the matches back to a spreadsheet or another database. Put the reference and its metadata in a BioseqDB table and issue those searches from your existing SQL or Python code. You can keep the earlier and later steps of the pipeline as they are. The butterfly tutorial shows this with SQLAlchemy and Plotly.

Why put sequences in a database instead of keeping FASTA files?#

FASTA files are still useful for exchanging sequences. The database becomes useful when the same sequences have metadata, are queried repeatedly, or need to be combined with other tables. You can filter samples by ordinary columns and ask for their sequence matches without preparing another set of input files for each query.

Is BioseqDB open source, and can I use it for free?#

Yes. BioseqDB is published under the Apache 2.0 license, and the source and release packages are available without a subscription. See the repository and license for the actual terms and the notices for included components. Running a database still uses your own machine or hosting resources.

Who is building BioseqDB?#

I am Piotr Styczyński, and BioseqDB is my independent project. It grew out of several years of experiments with sequence data, aligners, and PostgreSQL. The introduction has the timeline and explains how the current implementation developed.

Installing and trying it

What is the quickest way to try BioseqDB?#

Start with the Docker quick start. It gives you the image name, a local PostgreSQL container, and a small alignment query. Run the sample data first so you can check the installation before importing your own dataset.

Do I have to use Docker?#

No. There are native alpha packages as well as Docker images, and you can build from source. Pick a package that matches your operating system, CPU architecture, and PostgreSQL major version. The package table links to the available builds and their setup notes.

Will a package for one PostgreSQL version work with another?#

Use the build for your PostgreSQL major version. An extension binary built for one major version is not something you should copy into another server version. The release table also distinguishes stable PostgreSQL releases from prerelease and development builds, so check the full package label.

Can I install it on any managed PostgreSQL service?#

Only if the service lets you install this native extension. Many hosted PostgreSQL services accept a fixed list of extensions and do not let customers upload their own binaries. Check that before choosing a host; a self-managed PostgreSQL instance or the supplied Docker image gives you control over the installation.

Do I need a GPU?#

No. BioseqDB has CPU implementations, and the walkthrough can run without a GPU. There is also experimental Vulkan work, but a GPU is not a requirement or a promise of better performance. The benchmark chapter discusses where the tested GPU approach helped and where it did not.

Is the current release ready for production?#

It is an experimental alpha and still has bugs and limitations. I would start with a copy of a dataset and a reproducible experiment. Read the alpha limitations before depending on it, especially the notes about memory admission and automatic index maintenance.

Sequences and storage

Why use bioseq.seq instead of a text column?#

bioseq.seq gives the database a sequence type with a defined alphabet and compact representation. BioseqDB can then perform sequence operations and alignment without treating the value as an arbitrary string. With USING bioseq, sequence data also uses the extension's storage and index machinery. The sequence chapter explains the representation.

What do dna4 and 64 mean in bioseq.seq('dna4', 64)?#

dna4 selects the four-letter DNA alphabet: A, C, G, and T. The 64 selects a 64-bit storage unit for the packed representation; it does not limit the sequence to 64 bases. The sequence length is separate and can be read with bioseq.len.

What should I do with unknown bases such as N?#

Use the dna5 alphabet when N needs to be preserved. DNA4 represents only A, C, G, and T, so it is not the right representation for retaining unknown bases. Check the alphabet before importing a dataset, and keep track of unresolved bases when interpreting composition or alignment results.

Can I use it for protein or RNA alignments?#

The current documented implementation supports DNA4 and DNA5. Its sequence abstractions were designed with other alphabets in mind, but that is not the same as having a supported protein or RNA alignment workflow today. The examples on this site use DNA.

Can I keep sample names and other metadata in the same table?#

Yes. A sequence table can have ordinary columns such as an identifier, organism, collection date, or sample name beside its bioseq.seq column. Those columns can be selected, filtered, aggregated, and joined using SQL. The walkthrough uses patient metadata to illustrate this.

How do I import FASTA or FASTQ data?#

BioseqDB provides bioseq.load for loading sequence files into a table. The column layout and header format matter, so start with the FASTA import example and adapt its target table. A filename passed to the server refers to a file the PostgreSQL server can access, not automatically a file on the computer running your SQL client.

Alignments and results

What does an alignment tell me?#

An alignment describes how parts of two sequences correspond, allowing for substitutions and gaps. It can help locate similar regions, but similarity alone does not establish a gene's function or a biological cause. The alignment foundations introduce the scoring and the seed-and-extend approach used to make large searches practical.

How do I run a sequence search in SQL?#

Use mmsearch in a query over a BioseqDB table, supplying the target sequence column and a query sequence. Select the metadata and alignment fields you want from the matching rows. The first alignment query includes the table and data needed to run it, rather than just an isolated function call.

What are bioseq.score and bioseq.cigar showing me?#

bioseq.score reports the base-alignment score for a match. bioseq.cigar describes the alignment as operations such as aligned columns, insertions, and deletions. Selecting the CIGAR requests base alignment; selecting the score alone does not, so that score can be zero. A CIGAR M operation can include both matching and mismatching bases, so do not read it as a count of identical bases. The butterfly tutorial walks through these fields with real sequences.

Why did my alignment query return no rows?#

First check that the table contains the sequences you intended to import and that their lengths and alphabets make sense. Then try the small working example from the docs. The query can legitimately find no retained matches when the sequences are too short, too different, or excluded by the chosen thresholds. Inspect the settings and search diagnostics before assuming the data is missing.

Why are alignment fields NULL in a plain SELECT?#

Alignment fields describe a match produced by a search. Reading a row on its own does not create an alignment context, so a field such as bioseq.score has no match to describe. Select it in the alignment query shown in the walkthrough. Some details also depend on which alignment work the query requests and which settings are enabled.

Can I align just a region, and how do the coordinates work?#

Yes. Sequence slices let you search a region rather than the whole stored sequence. BioseqDB's sequence examples use zero-based, half-open intervals: the start is included and the end is excluded. This differs from the one-based inclusive coordinates used in some biological records. The slice examples and butterfly tutorial show the conversion explicitly.

Performance and configuration

Does the 120× speedup apply to every query?#

No. “Up to 120×” refers to particular measured comparisons, not every workload. Reusing a prepared index, available memory, sequence sizes, and the comparison tool's work all affect the result. Building the index also costs time. Use the benchmark explorer to inspect the configurations and methodology; an unindexed one-off query can be slower than minimap2.

Does BioseqDB run the minimap2 command behind the scenes?#

No separate minimap2 executable is needed for the SQL examples. BioseqDB integrates alignment work into PostgreSQL and offers configurable seeding, chaining, and final-alignment implementations. Minimap2 is an important reference and part of the project's history, but the database also adds persistent indexes, sequence storage, and SQL query integration.

When is it worth building a sequence index?#

An index is especially useful when you expect to search the same reference data repeatedly. You pay the preparation cost once and can reuse the stored lookup structures in later searches. For a one-off small comparison, that preparation may cost more than it saves. The index chapter explains what is stored and how it is read.

Will inserting new rows update the index automatically?#

Be careful with the current alpha. The default grouped-MPF index does not support automatic insert maintenance, so the walkthrough sets bioseq.index.insert_maintenance.enabled to off and shows an explicit rebuild. Other index configurations have different behavior. Follow the index maintenance notes for the configuration you use.

Where can I find the available settings and their defaults?#

The configuration reference lists settings, accepted values, defaults, and descriptions. Search for a setting by its full path in the header search box, or use PostgreSQL's SHOW and pg_settings to inspect your session. Individual reference pages also include examples and range information where it applies.

How can I understand why a query is slow?#

Start with EXPLAIN (ANALYZE, BUFFERS) on a query you are prepared to execute. BioseqDB adds search diagnostics, and its cache statistics can help explain repeated reads. Check whether the query reused an index and whether memory or a fallback changed the execution path. The walkthrough includes complete plans and explanations of their fields.

Python, external data, and next steps

Can I use BioseqDB from Python or a notebook?#

Yes. It is still PostgreSQL, so a PostgreSQL driver and SQLAlchemy can send the SQL queries and return ordinary result rows. You do not need a separate Python aligner. The butterfly tutorial includes a Poetry environment, SQLAlchemy queries, Plotly figures, and a notebook in the examples repository.

Can I search NCBI and import its sequences through SQL?#

Yes, when BioseqDB is built with the external API clients enabled. The butterfly tutorial searches NCBI by organism, chooses explicit records and sequence windows, then imports them into local tables. Keep the accessions and assembly versions with your results so you know which data you compared.

Why are the NCBI tables missing from my Docker image or native package?#

The published 0.1.0-alpha.1 Docker images and native packages do not include the external-database integration. It cannot be switched on with a runtime setting in those binaries. For the current tutorial, build from source with BIOSEQ_BUILD_EXTERNAL_API_CLIENTS=ON; the setup instructions explain the additional steps.

Does an ordinary alignment send my sequences to another service?#

An alignment over locally stored sequences runs inside your PostgreSQL server. Explicit queries to an external provider such as NCBI do make requests to that provider. Keep those two cases separate when deciding what data to import and what network access to allow for your database.

Do I need to know biology before following the tutorials?#

A little context helps, but you do not need to begin with an entire genomics course. Start with the biology introduction for DNA and the alignment chapter for sequence comparison. The SQL walkthrough uses small synthetic examples, while the butterfly post builds up a real comparison one step at a time.

Where should I report a bug or ask for a feature?#

Open a GitHub issue with the BioseqDB build, PostgreSQL version, query, and a small example that reproduces the problem. Avoid posting private data or credentials. For a conversation that does not belong in a public issue, use the contact page. I maintain the project independently, so please allow some time for a reply.
