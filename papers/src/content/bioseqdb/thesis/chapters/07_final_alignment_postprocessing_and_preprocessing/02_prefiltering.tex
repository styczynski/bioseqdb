\section{SneakySnake prefiltering}
\label{sec:prefilter-role}
\label{sec:prefilter-sneakysnake}

We discussed the postprocessing step, but there's also corresponding preprocessing step in the pipeline. I didn't separate it into its own chapter, because
the feature is exerimental and uses external dependency.

A prefilter is specialized algorithm to reject sequence quickly before doing any alignment work.
In BioseqDB I decided to use SneakySnake algorithm directly. Good prefilter should offer the following properties:
\begin{itemize}
  \item It should quickly evaluate query and sequence parts and compute estimate of edit distance.
  \item The estimated edit distance should be lower than actual edit distance to prevent situation in which prefilter rejects valid candidates.
\end{itemize}

In BioseqDB I used SneakySnake~\cite{sneakysnake_paper,sneakysnake_readme}, where the core idea is to translate approximate string matching problem into a chip maze problem
(formally SNR - Single Net Routing). I won't describe the algorithm in detail here, as I only use SneakySnake as a dependency and it wasn't evalauted in the final benchmarks.

The prefilter can be evaluated if users provides special predicate~\ref{lst:prefilter-condition}. In that case BioseqDB for case where the sequence is filtered-out
won't fetch the minimizers or recompute them meaning the rest of the pipeline will be entirely skipped (to be precise the order of the filter evaluation is as follows:
non-sequence user filters, then prefilter):
\begin{minipage}{\linewidth}
\begin{lstlisting}[style=bioseq-walk-sql]
SELECT pk, bioseq.edit(seq0) AS edits
FROM tutorial_mmsearch
WHERE public.mmsearch(seq0, $1::bioseq.seq('dna4', 64))
  AND bioseq.edit(seq0) < 5
ORDER BY pk;
\end{lstlisting}
\end{minipage}

The SNR problem is constructed as follows: For input query/target \(Q,R\in\Sigma^m\) and given maximum edit distance $E$, SneakySnake constructs a
 matrix $Z \in \{0,1\}^{(2E+1)\times m}$
The idea is that the matrix covers one sequence (columns), while the rows cover only $2E+1$ relative positions in the second sequence.
We then compare each position in the query and in target and if they match we put 0, otherwise we put 1 in the $Z$ matrix.
Now $Z$ matrix represents "obstacles" for 1s and empty spaces for 0s. The SNR problem needs to find a path from left to right (possibly going up and down and to the left, but never to the right),
where path is better if it contains less obstacles.

The benefit here is that traverse of the matrix is $O((2E+1)*m)$, which for low $E$ can be very fast. You must note however that I directly plugged SneakySnake into 
BioseqDB lazy-sequence adapters without proper benchmarking, which means that I don't know how matching quality/performance is affected by calling this prefilter.

Let's define $Z$ matrix formally. First index $i$ is up to $2E+1$ and second index $j$ is position in $R$: \(1\leq j\leq m\):
\[
 \delta_i=\begin{cases}
  -i,&1\leq i\leq E,\\
  0,&i=E+1,\\
  i-E-1,&E+1<i\leq2E+1.
 \end{cases}
 \qquad
 Z_{i,j}=\begin{cases}
  0,&1\leq j+\delta_i\leq m\ \land\ Q_{j+\delta_i}=R_j,\\
  1,&\text{otherwise}.
 \end{cases}
\]
Here, $\delta_i$ just formally defines relative lookups i.e if we look to the left of position in $R$ up to $E$ positions or to the right up to $E$ positions.
In paper authors want to look at the left side first, for example $(-1, -2, -3, 0, +1, +2, +3)$, so $\delta_i$ looks more complicated than just $i-E$.
